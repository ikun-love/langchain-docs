---
title: 分割 HTML
---

将 HTML 文档分割成可管理的块对于各种文本处理任务至关重要，例如自然语言处理、搜索索引等。在本指南中，我们将探讨 LangChain 提供的三种不同的文本分割器，您可以使用它们来有效地分割 HTML 内容：

- [**HTMLHeaderTextSplitter**](#using-htmlheadertextsplitter)
- [**HTMLSectionSplitter**](#using-htmlsectionsplitter)
- [**HTMLSemanticPreservingSplitter**](#using-htmlsemanticpreservingsplitter)

这三种分割器都有独特的功能和用例。本指南将帮助您理解它们之间的区别，说明为什么选择其中一个而不是另一个，以及如何有效地使用它们。

```
pip install -qU langchain-text-splitters
```

## 分割器概述

### [HTMLHeaderTextSplitter](#using-htmlheadertextsplitter)

<Info>
**当您想根据文档的标题结构来保留其层次结构时非常有用。**
</Info>

**描述**: 根据标题标签（例如 `<h1>`、`<h2>`、`<h3>` 等）分割 HTML 文本，并为给定块的每个相关标题添加元数据。

**能力**:
- 在 HTML 元素级别上分割文本。
- 保留编码在文档结构中的富含上下文的信息。
- 可以逐元素返回块，或将具有相同元数据的元素组合起来。

___


### [HTMLSectionSplitter](#using-htmlsectionsplitter)

<Info>
当您想将 HTML 文档分割成更大的部分，例如 `<section>`、`<div>` 或自定义定义的区块时非常有用。
</Info>

**描述**: 与 `HTMLHeaderTextSplitter` 类似，但专注于根据指定的标签将 HTML 分割成不同部分。

**能力**:
- 使用 XSLT 转换来检测和分割部分。
- 内部使用 `RecursiveCharacterTextSplitter` 来处理大块内容。
- 考虑字体大小来确定章节。
___

### [HTMLSemanticPreservingSplitter](#using-htmlsemanticpreservingsplitter)

<Info>
**当您需要确保结构化元素不会在块之间被分割，从而保持上下文相关性时，它是理想选择。**
</Info>

**描述**: 将 HTML 内容分割成可管理的块，同时保留表格、列表和其他 HTML 组件等重要元素的语义结构。

**能力**:
- 保留表格、列表和其他指定的 HTML 元素。
- 允许为特定的 HTML 标签定义自定义处理程序。
- 确保文档的语义含义得以保持。
- 内置标准化和停用词移除。
___

### 选择正确的分割器

- **当您需要**根据 HTML 文档的标题层级进行分割，并维护关于标题的元数据时，请使用 `HTMLHeaderTextSplitter`。
- **当您需要**将文档分割成更大、更通用的部分时（可能基于自定义标签或字体大小时），请使用 `HTMLSectionSplitter`。
- **当您需要**在分割 HTML 内容的同时保留表格和列表等语义元素，并确保它们不被分割、上下文得以保持时，请使用 `HTMLSemanticPreservingSplitter`。

| 特性 | HTMLHeaderTextSplitter | HTMLSectionSplitter | HTMLSemanticPreservingSplitter |
|--------------------------------------------|------------------------|---------------------|-------------------------------|
| 基于标题进行分割 | 是 | 是 | 是 |
| 保留语义元素（表格、列表） | 否 | 否 | 是 |
| 添加标题元数据 | 是 | 是 | 是 |
| 自定义 HTML 标签处理程序 | 否 | 否 | 是 |
| 保留媒体（图像、视频） | 否 | 否 | 是 |
| 考虑字体大小 | 否 | 是 | 否 |
| 使用 XSLT 转换 | 否 | 是 | 否 |

## 使用 HTMLHeaderTextSplitter

[HTMLHeaderTextSplitter](https://python.langchain.com/api_reference/text_splitters/html/langchain_text_splitters.html.HTMLHeaderTextSplitter.html) 是一个“感知结构”的[文本分割器](/oss/python/integrations/splitters)，它在 HTML 元素级别上分割文本，并为给定块的每个“相关”标题添加元数据。它可以逐元素返回块，也可以将具有相同元数据的元素组合起来，目标是 (a) （大致上）在语义上将相关文本分组，以及 (b) 保留编码在文档结构中的富含上下文的信息。它可以与其他文本分割器一起作为分块管道的一部分使用。

它类似于 Markdown 文件的 [MarkdownHeaderTextSplitter](/oss/python/integrations/splitters/markdown_header_metadata_splitter)。

要指定分割的标题，请在实例化 `HTMLHeaderTextSplitter` 时指定 `headers_to_split_on`，如下所示。


```python
from langchain_text_splitters import HTMLHeaderTextSplitter

headers_to_split_on = [
    ("h1", "Header 1"),
    ("h2", "Header 2"),
    ("h3", "Header 3"),
]

html_splitter = HTMLHeaderTextSplitter(headers_to_split_on)
html_header_splits = html_splitter.split_text(html_string)
html_header_splits
```



```output

 Document(metadata={'Header 1': 'Main Title', 'Header 2': 'Section 3: Code Example'}, page_content='This section contains a code block:'),
 Document(metadata={'Header 1': 'Main Title', 'Header 2': 'Conclusion'}, page_content='This is the conclusion of the document.')]
```


要在返回每个元素时同时返回其关联的标题，请在实例化 `HTMLHeaderTextSplitter` 时指定 `return_each_element=True`：


```python
html_splitter = HTMLHeaderTextSplitter(
    headers_to_split_on,
    return_each_element=True,
)
html_header_splits_elements = html_splitter.split_text(html_string)
```

### 如何从 URL 或 HTML 文件中分割：

要直接从 URL 读取，请将 URL 字符串传递给 `split_text_from_url` 方法。

类似地，可以向 `split_text_from_file` 方法传递一个本地 HTML 文件。


```python
url = "https://plato.stanford.edu/entries/goedel/"

headers_to_split_on = [
    ("h1", "Header 1"),
    ("h2", "Header 2"),
    ("h3", "Header 3"),
    ("h4", "Header 4"),
]

html_splitter = HTMLHeaderTextSplitter(headers_to_split_on)

# 对于本地文件，使用 html_splitter.split_text_from_file(<path_to_file>)
html_header_splits = html_splitter.split_text_from_url(url)
```

### 如何限制块大小：

## 使用 HTMLSectionSplitter

与 [HTMLHeaderTextSplitter](#using-htmlheadertextsplitter) 概念相似，`HTMLSectionSplitter` 是一个“感知结构”的[文本分割器](/oss/python/integrations/splitters)，它在元素级别上分割文本并为每个相关标题添加元数据。它允许您按部分分割 HTML。

它可以逐元素返回块，也可以将具有相同元数据的元素组合起来，目标是 (a) （大致上）在语义上将相关文本分组，以及 (b) 保留编码在文档结构中的富含上下文的信息。

使用 `xslt_path` 可以提供一个绝对路径来转换 HTML，以便它能够根据提供的标签检测不同部分。默认情况下，它使用 `data_connection/document_transformers` 目录中 `converting_to_header.xslt` 文件。这是为了将 HTML 转换为更容易检测部分的格式/布局。例如，基于字体大小的 `span` 可以转换为标题标签，被检测为一个部分。

## 使用 HTMLSemanticPreservingSplitter

`HTMLSemanticPreservingSplitter` 的设计目的是将 HTML 内容分割成可管理的块，同时保留表格、列表和其他 HTML 组件等重要元素的语义结构。这确保了此类元素不会在块之间被分割，从而避免上下文相关性（如表格标题、列表标题等）的丢失。

该分割器从根本上旨在创建上下文相关的块。与 `HTMLHeaderTextSplitter` 结合使用的一般递归分割可能会导致表格、列表和其他结构化元素在中间被分割，从而丢失重要的上下文并产生不良的块。

当 HTML 内容包含表格和列表等结构化元素，并且**关键**是要保持这些元素完整时，`HTMLSemanticPreservingSplitter` 就变得至关重要。此外，它能够为特定 HTML 标签定义自定义处理程序的能力，使其成为处理复杂 HTML 文档的多功能工具。

**重要提示**: `max_chunk_size` 不是块的明确最大尺寸，最大尺寸的计算发生在被保留的内容不属于该块时，以确保它不会被分割。当我们把保留的数据加回到块中时，块大小**有可能**会超过 `max_chunk_size`。这对于确保我们保持原始文档的结构至关重要。

<Info>

备注:

1. 我们定义了一个自定义处理程序来重新格式化代码块的内容
2. 我们定义了一个拒绝列表（deny list）用于特定的 HTML 元素，以便在预处理阶段将它们及其内容分解
3. 我们特意设置了一个较小的块大小来演示元素不被分割的情况

</Info>


```python
# BeautifulSoup 是使用自定义处理程序所必需的
from bs4 import Tag
from langchain_text_splitters import HTMLSemanticPreservingSplitter

headers_to_split_on = [
    ("h1", "Header 1"),
    ("h2", "Header 2"),
]


def code_handler(element: Tag) -> str:
    data_lang = element.get("data-lang")
    code_format = f"<code:{data_lang}>{element.get_text()}</code>"

    return code_format


splitter = HTMLSemanticPreservingSplitter(
    headers_to_split_on=headers_to_split_on,
    separators=["\n\n", "\n", ". ", "! ", "? "],
    max_chunk_size=50,
    preserve_images=True,
    preserve_videos=True,
    elements_to_preserve=["table", "ul", "ol", "code"],
    denylist_tags=["script", "style", "head"],
    custom_handlers={"code": code_handler},
)

documents = splitter.split_text(html_string)
documents
```

```output
 Document(metadata={'Header 2': 'Conclusion'}, page_content='This is the conclusion of the document.')]
```


### 保留表格和列表
在此示例中，我们将演示 `HTMLSemanticPreservingSplitter` 如何在 HTML 文档中保留表格和大型列表。我们将块大小设置为 50 个字符，以说明分割器如何确保这些元素不会被分割，即使它们超过了定义的最大块大小。


```python
from langchain_text_splitters import HTMLSemanticPreservingSplitter

html_string = """
<!DOCTYPE html>
<html>
    <body>
        <div>
            <h1>Section 1</h1>
            <p>This section contains an important table and list that should not be split across chunks.</p>
            <table>
                <tr>
                    <th>Item</th>
                    <th>Quantity</th>
                    <th>Price</th>
                </tr>
                <tr>
                    <td>Apples</td>
                    <td>10</td>
                    <td>$1.00</td>
                </tr>
                <tr>
                    <td>Oranges</td>
                    <td>5</td>
                    <td>$0.50</td>
                </tr>
                <tr>
                    <td>Bananas</td>
                    <td>50</td>
                    <td>$1.50</td>
                </tr>
            </table>
            <h2>Subsection 1.1</h2>
            <p>Additional text in subsection 1.1 that is separated from the table and list.</p>
            <p>Here is a detailed list:</p>
            <ul>
                <li>Item 1: Description of item 1, which is quite detailed and important.</li>
                <li>Item 2: Description of item 2, which also contains significant information.</li>

headers_to_split_on = [("h1", "Header 1"), ("h2", "Header 2")]

documents = splitter.split_text(html_string)
```

这在处理数据表或列表等内容时尤为重要，分割内容可能导致上下文丢失或混淆。生成的 [`Document`](https://reference.langchain.com/python/langchain_core/documents/#langchain_core.documents.base.Document) 对象保留了这些元素的完整结构，确保了信息的上下文相关性得以保持。

### 使用自定义处理程序
`HTMLSemanticPreservingSplitter` 允许您为特定 HTML 元素定义自定义处理程序。某些平台具有自定义 HTML 标签，这些标签不能被 `BeautifulSoup` 本地解析，当发生这种情况时，您可以使用自定义处理程序轻松添加格式化逻辑。

这对于需要特殊处理的元素（如 `<iframe>` 标签或特定的 'data-' 元素）特别有用。在此示例中，我们将为 `iframe` 标签创建一个自定义处理程序，它将它们转换为类似 Markdown 的链接。


```python
def custom_iframe_extractor(iframe_tag):
    iframe_src = iframe_tag.get("src", "")
    return f"[iframe:{iframe_src}]({iframe_src})"


splitter = HTMLSemanticPreservingSplitter(
    headers_to_split_on=headers_to_split_on,
    max_chunk_size=50,
    separators=["\n\n", "\n", ". "],
    elements_to_preserve=["table", "ul", "ol"],
    custom_handlers={"iframe": custom_iframe_extractor},
)

html_string = """
<!DOCTYPE html>
<html>
    <body>
        <div>
            <h1>Section with Iframe</h1>
            <iframe src="https://example.com/embed"></iframe>
            <p>Some text after the iframe.</p>
            <ul>
                <li>Item 1: Description of item 1, which is quite detailed and important.</li>
                <li>Item 2: Description of item 2, which also contains significant information.</li>
                <li>Item 3: Description of item 3, another item that we don't want to split across chunks.</li>
            </ul>
        </div>
    </body>
</html>
"""

documents = splitter.split_text(html_string)
print(documents)
```
```output
[Document(metadata={'Header 1': 'Section with Iframe'}, page_content='[iframe:https://example.com/embed](https://example.com/embed) Some text after the iframe'), Document(metadata={'Header 1': 'Section with Iframe'}, page_content=". Item 1: Description of item 1, which is quite detailed and important. Item 2: Description of item 2, which also contains significant information. Item 3: Description of item 3, another item that we don't want to split across chunks.")]
```
#### 解释
在此示例中，我们为 `iframe` 标签定义了一个自定义处理程序，它将它们转换为类似 Markdown 的链接。当分割器处理 HTML 内容时，它使用此自定义处理程序根据您提供的自定义逻辑来转换 `iframe` 标签，同时保留表格和列表等其他元素。生成的 [`Document`](https://reference.langchain.com/python/langchain_core/documents/#langchain_core.documents.base.Document) 对象显示了 iframe 如何根据您提供的自定义逻辑进行处理。

**重要提示**: 在保留链接等项目时，应注意不要在分隔符中包含 `.` 或将分隔符留空。`RecursiveCharacterTextSplitter` 会在句号处分割，这可能会将链接一分为二。请确保提供的分隔符列表中包含 `. ` 而不是 `.`。

### 使用自定义处理程序分析图像（通过 LLM）

使用自定义处理程序，我们还可以覆盖任何元素的默认处理。一个很好的例子是在分块流程中直接插入图像的语义分析。

由于在发现标签时会调用我们的函数，我们可以覆盖 `<img>` 标签并将 `preserve_images` 标志关闭，以插入我们希望嵌入到块中的任何内容。

```python
"""此示例假定您有帮助方法 `load_image_from_url` 和可以处理图像数据的 LLM 代理 `llm`。"""

from langchain.agents import AgentExecutor

# 此示例需要用您自己的代理替换
llm = AgentExecutor(...)


# 这是一个占位符方法，用于从 URL 加载图像数据，此处未实现
def load_image_from_url(image_url: str) -> bytes:
    # 假设此方法从 URL 获取图像数据
    return b"image_data"


html_string = """
<!DOCTYPE html>
<html>
    <body>
        <div>
            <h1>Section with Image and Link</h1>
            <p>
                <img src="https://example.com/image.jpg" alt="An example image" />
                Some text after the image.
            </p>
            <ul>
                <li>Item 1: Description of item 1, which is quite detailed and important.</li>
                <li>Item 2: Description of item 2, which also contains significant information.</li>
                <li>Item 3: Description of item 3, another item that we don't want to split across chunks.</li>
            </ul>
        </div>
    </body>
</html>
"""


def custom_image_handler(img_tag) -> str:
    img_src = img_tag.get("src", "")
    img_alt = img_tag.get("alt", "No alt text provided")

    image_data = load_image_from_url(img_src)
    semantic_meaning = llm.invoke(image_data)

    markdown_text = f"[Image Alt Text: {img_alt} | Image Source: {img_src} | Image Semantic Meaning: {semantic_meaning}]"

    return markdown_text


splitter = HTMLSemanticPreservingSplitter(
    headers_to_split_on=headers_to_split_on,
    max_chunk_size=50,
    separators=["\n\n", "\n", ". "],
    elements_to_preserve=["ul"],
    preserve_images=False,
    custom_handlers={"img": custom_image_handler},
)

documents = splitter.split_text(html_string)

print(documents)
```

使用自定义处理程序来提取 HTML `<img>` 元素中的特定字段，我们可以利用代理来处理图像数据，并将结果直接插入到我们的块中。重要的是要确保 `preserve_images` 设置为 `False`，否则将执行 `<img>` 字段的默认处理。
