[Yellowbrick](https://yellowbrick.com/yellowbrick-data-warehouse/) 是一款弹性、大规模并行处理（MPP）的 SQL 数据库，它利用 Kubernetes 在云端和本地运行，以实现可扩展性、弹性以及云环境的可移植性。Yellowbrick 的设计目标是解决最大、最复杂的、与业务关键相关的数据仓库使用案例。Yellowbrick 提供的扩展性效率也使其能够作为高性能、可扩展的向量数据库，用于存储和检索带有 SQL 的向量数据。

## 将 Yellowbrick 用作 ChatGPT 的向量存储

本教程演示了如何创建一个由 ChatGPT 支持的简单聊天机器人，该机器人使用 Yellowbrick 作为向量存储来支持检索增强生成（RAG）。您需要的准备工作：

1. 一个 [Yellowbrick 实验沙箱](https://cloudlabs.yellowbrick.com/) 账户
2. 一个来自 [OpenAI](https://platform.openai.com/) 的 API 密钥

本教程分为五个部分。首先，我们将使用 `langchain` 创建一个基线聊天机器人，用于在**没有**向量存储的情况下与 ChatGPT 交互。其次，我们将在 Yellowbrick 中创建一个代表向量存储的嵌入（embeddings）表。第三，我们将加载一系列文档（Yellowbrick 手册的“管理”章节）。第四，我们将创建这些文档的向量表示形式并将其存储在 Yellowbrick 表中。最后，我们将向改进后的聊天机器人发送相同的查询，以查看结果。

## 第 1 部分：创建不依赖向量存储的、由 ChatGPT 支持的基线聊天机器人

我们将使用 `langchain` 来查询 ChatGPT。由于没有向量存储，ChatGPT 将没有任何上下文来回答问题。

```python
# 设置聊天模型和特定提示
system_template = """如果你不知道答案，请尽你所能地猜测。"""
messages = [
    SystemMessagePromptTemplate.from_template(system_template),
    HumanMessagePromptTemplate.from_template("{question}"),
]
prompt = ChatPromptTemplate.from_messages(messages)

chain_type_kwargs = {"prompt": prompt}
llm = ChatOpenAI(
    model_name="gpt-3.5-turbo",  # 如果您有 GPT-4 访问权限，请修改 model_name
    temperature=0,
    max_tokens=256,
)

chain = LLMChain(
    llm=llm,
    prompt=prompt,
    verbose=False,
)


def print_result_simple(query):
    result = chain(query)
    output_text = f"""### 问题:
  {query}
  ### 回答:
  {result["text"]}
    """
    display(Markdown(output_text))


# 使用链进行查询
print_result_simple("在一个 Yellowbrick 实例中可以有多少个数据库？")

print_result_simple("在 Yellowbrick 中批量添加用户的简便方法是什么？")
```

## 第 2 部分：连接到 Yellowbrick 并创建嵌入表

要将文件嵌入（embeddings）加载到 Yellowbrick 中，您应该创建自己的表来存储它们。请注意，该表所在的 Yellowbrick 数据库必须是 UTF-8 编码。

在 UTF-8 数据库中创建一个具有以下架构的表，并提供您选择的表名：

```python
# 建立到 Yellowbrick 数据库的连接
try:
    conn = psycopg2.connect(yellowbrick_connection_string)
except psycopg2.Error as e:
    print(f"连接数据库时出错: {e}")
    exit(1)

# 使用连接创建一个游标对象
cursor = conn.cursor()

# 定义创建表的 SQL 语句
create_table_query = f"""
CREATE TABLE IF NOT EXISTS {embedding_table} (
    doc_id uuid NOT NULL,
    embedding_id smallint NOT NULL,
    embedding double precision NOT NULL
)
DISTRIBUTE ON (doc_id);
truncate table {embedding_table};
"""

# 执行 SQL 查询以创建表
try:
    cursor.execute(create_table_query)
    print(f"表 '{embedding_table}' 创建成功！")
except psycopg2.Error as e:
    print(f"创建表时出错: {e}")
    conn.rollback()

# 提交更改并关闭游标和连接
conn.commit()
cursor.close()
conn.close()
```

## 第 3 部分：从 Yellowbrick 中的现有表中提取要索引的文档

从现有的 Yellowbrick 表中提取文档路径和内容。我们将在下一步使用这些文档来创建嵌入。

```python
yellowbrick_doc_connection_string = (
    f"postgres://{urlparse.quote(YBUSER)}:{YBPASSWORD}@{YBHOST}:5432/{YB_DOC_DATABASE}"
)

print(yellowbrick_doc_connection_string)

# 建立到 Yellowbrick 数据库的连接
conn = psycopg2.connect(yellowbrick_doc_connection_string)

# 创建一个游标对象
cursor = conn.cursor()

# 查询以从表中选择所有文档
query = f"SELECT path, document FROM {YB_DOC_TABLE}"

# 执行查询
cursor.execute(query)

# 获取所有文档
yellowbrick_documents = cursor.fetchall()

print(f"成功提取了 {len(yellowbrick_documents)} 个文档！")

# 关闭游标和连接
cursor.close()
conn.close()
```

## 第 4 部分：使用文档加载 Yellowbrick 向量存储

遍历文档，将它们分割成可消化的块，创建嵌入，并将它们插入 Yellowbrick 表中。此过程大约需要 5 分钟。

```python
# 将文档分割成块，以便转换为嵌入
DOCUMENT_BASE_URL = "https://docs.yellowbrick.com/6.7.1/"  # 实际 URL


separator = "\n## "  # 此分隔符假设来自仓库的 Markdown 文档通常使用 ### 作为逻辑主标题
chunk_size_limit = 2000
max_chunk_overlap = 200

documents = [
    Document(
        page_content=document[1],
        metadata={"source": DOCUMENT_BASE_URL + document[0].replace(".md", ".html")},
    )
    for document in yellowbrick_documents
]

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=chunk_size_limit,
    chunk_overlap=max_chunk_overlap,
    separators=[separator, "\nn", "\n", ",", " ", ""],
)
split_docs = text_splitter.split_documents(documents)

docs_text = [doc.page_content for doc in split_docs]

embeddings = OpenAIEmbeddings()
vector_store = Yellowbrick.from_documents(
    documents=split_docs,
    embedding=embeddings,
    connection_string=yellowbrick_connection_string,
    table=embedding_table,
)

print(f"使用 {len(documents)} 个文档创建了向量存储")
```

## 第 5 部分：创建将 Yellowbrick 用作向量存储的聊天机器人

接下来，我们将 Yellowbrick 添加为向量存储。向量存储已填充了代表 Yellowbrick 产品文档管理章节的嵌入。

我们将向其发送与上面相同的查询，以查看改进后的响应。

```python
system_template = """使用以下上下文片段来回答用户的问题。
注意来源信息，并在答案中以格式: "SOURCES: source1 source2" 的形式包含它们，无论来源数量是多少，都使用大写的 "SOURCES"。
如果你不知道答案，只需回答 "我不知道"，不要试图编造答案。
----------------
{summaries}"""
messages = [
    SystemMessagePromptTemplate.from_template(system_template),
    HumanMessagePromptTemplate.from_template("{question}"),
]
prompt = ChatPromptTemplate.from_messages(messages)

vector_store = Yellowbrick(
    OpenAIEmbeddings(),
    yellowbrick_connection_string,
    embedding_table,  # 更改表名以反映您的嵌入
)

chain_type_kwargs = {"prompt": prompt}
llm = ChatOpenAI(
    model_name="gpt-3.5-turbo",  # 如果您有 GPT-4 访问权限，请修改 model_name
    temperature=0,
    max_tokens=256,
)
chain = RetrievalQAWithSourcesChain.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=vector_store.as_retriever(search_kwargs={"k": 5}),
    return_source_documents=True,
    chain_type_kwargs=chain_type_kwargs,
)


def print_result_sources(query):
    result = chain(query)
    output_text = f"""### 问题:
  {query}
  ### 回答:
  {result["answer"]}
  ### 来源:
  {result["sources"]}
  ### 所有相关来源:
  {", ".join(list(set([doc.metadata["source"] for doc in result["source_documents"]])))}
    """
    display(Markdown(output_text))


# 使用链进行查询

print_result_sources("在一个 Yellowbrick 实例中可以有多少个数据库？")

print_result_sources("在 Yellowbrick 中批量添加用户的简便方法是什么？")
```

## 第 6 部分：引入索引以提高性能

Yellowbrick 也支持使用局部敏感哈希（Locality-Sensitive Hashing, LSH）方法的索引。这是一种近似最近邻搜索技术，允许用户在准确性方面权衡相似性搜索时间。索引引入了两个新的可调参数：

- 超平面的数量，该参数作为 `create_lsh_index(num_hyperplanes)` 的参数提供。文档越多，需要的超平面也越多。LSH 是一种降维形式。原始嵌入被转换为低维向量，其中分量的数量与超平面的数量相同。
- 汉明距离（Hamming distance），一个表示搜索范围的整数。较小的汉明距离会带来更快的检索速度但准确性较低。

以下是您如何在已加载到 Yellowbrick 的嵌入上创建索引的方法。我们还将重新运行之前的聊天会话，但这次检索将使用索引。请注意，对于如此少量的文档，您不会在性能方面看到索引的好处。

```python
system_template = """使用以下上下文片段来回答用户的问题。
注意来源信息，并在答案中以格式: "SOURCES: source1 source2" 的形式包含它们，无论来源数量是多少，都使用大写的 "SOURCES"。
如果你不知道答案，只需回答 "我不知道"，不要试图编造答案。
----------------
{summaries}"""
messages = [
    SystemMessagePromptTemplate.from_template(system_template),
    HumanMessagePromptTemplate.from_template("{question}"),
]
prompt = ChatPromptTemplate.from_messages(messages)

vector_store = Yellowbrick(
    OpenAIEmbeddings(),
    yellowbrick_connection_string,
    embedding_table,  # 更改表名以反映您的嵌入
)

lsh_params = Yellowbrick.IndexParams(
    Yellowbrick.IndexType.LSH, {"num_hyperplanes": 8, "hamming_distance": 2}
)
vector_store.create_index(lsh_params)

chain_type_kwargs = {"prompt": prompt}
llm = ChatOpenAI(
    model_name="gpt-3.5-turbo",  # 如果您有 GPT-4 访问权限，请修改 model_name
    temperature=0,
    max_tokens=256,
)
chain = RetrievalQAWithSourcesChain.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=vector_store.as_retriever(
        k=5, search_kwargs={"index_params": lsh_params}
    ),
    return_source_documents=True,
    chain_type_kwargs=chain_type_kwargs,
)


def print_result_sources(query):
    result = chain(query)
    output_text = f"""### 问题:
  {query}
  ### 回答:
  {result["answer"]}
  ### 来源:
  {result["sources"]}
  ### 所有相关来源:
  {", ".join(list(set([doc.metadata["source"] for doc in result["source_documents"]])))}
    """
    display(Markdown(output_text))


# 使用链进行查询

print_result_sources("在一个 Yellowbrick 实例中可以有多少个数据库？")

print_result_sources("在 Yellowbrick 中批量添加用户的简便方法是什么？")
```
