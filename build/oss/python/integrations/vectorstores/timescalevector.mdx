## Timescale Vector 是什么？

`Timescale Vector` 使您能够在 `PostgreSQL` 中高效地存储和查询数百万个向量嵌入（vector embeddings）。

- 通过受 `DiskANN` 启发而来的索引算法，增强了 `pgvector`，在超过 1 亿个向量上实现更快、更准确的相似性搜索。
- 通过自动化的时序分区（time-based partitioning）和索引，实现快速的基于时间（time-based）的向量搜索。
- 提供熟悉的 SQL 接口，用于查询向量嵌入和关系型数据。

`Timescale Vector` 是面向 AI 的云端 `PostgreSQL` 解决方案，可以随着您的项目从概念验证（POC）扩展到生产环境：

- 通过允许您将关系型元数据、向量嵌入和时间序列数据存储在**单个数据库**中，简化了操作。
- 受益于坚如磐石的 PostgreSQL 基础，并具备企业级的特性，如流式备份和复制、高可用性以及行级安全性。
- 提供企业级的安全性和合规性，带来无忧的使用体验。

## 2. 使用基于时间的过滤进行相似性搜索

Timescale Vector 的一个关键用例是高效的基于时间的向量搜索。Timescale Vector 通过按时间自动分区向量（及关联的元数据）来实现这一点。这使得您能够高效地根据向量相似性和时间来查询向量。

基于时间的向量搜索功能在以下应用中很有用：

- 存储和检索 LLM 响应历史记录（例如聊天机器人）
- 查找与查询向量相似的最新嵌入（例如最新新闻）。
- 将相似性搜索限制在相关时间范围内（例如，就知识库中基于时间的问题提问）

为了说明如何使用 TimescaleVector 的基于时间向量搜索功能，我们将询问有关 TimescaleDB 日志记录历史的问题。我们将说明如何向名为 `timescale_commits` 的新集合中添加带有基于时间 UUID 的文档，以及如何运行带有时间范围过滤器的相似性搜索。

### 从 git log JSON 中提取内容和元数据

我们将定义一个辅助函数，根据其时间戳为文档和关联的向量嵌入创建 UUID。我们将使用此函数为每个 git log 条目创建一个 UUID。

重要提示：如果您的文档需要与当前日期和时间相关联以进行基于时间的搜索，则可以跳过此步骤。摄取文档时，默认会自动生成一个 UUID。

```python
from timescale_vector import client


# 函数，用于输入过去的日期字符串并返回一个 uuid v1
def create_uuid(date_string: str):
    if date_string is None:
        return None
    time_format = "%a %b %d %H:%M:%S %Y %z"
    datetime_obj = datetime.strptime(date_string, time_format)
    uuid = client.uuid_from_time(datetime_obj)
    return str(uuid)
```

接下来，我们将定义一个元数据函数，用于从 JSON 记录中提取相关元数据。我们将把这个函数传递给 `JSONLoader`。有关更多详细信息，请参阅 [JSON 文档加载器文档](/oss/python/integrations/document_loaders/json)。

```python
# 辅助函数，用于分割名称和电子邮件，给定一个由“姓名 姓氏 <email>”组成的作者字符串
def split_name(input_string: str) -> Tuple[str, str]:
    if input_string is None:
        return None, None
    start = input_string.find("<")
    end = input_string.find(">")
    name = input_string[:start].strip()
    email = input_string[start + 1 : end].strip()
    return name, email


# 辅助函数，用于将日期字符串转换为 timestamp_tz 字符串
def create_date(input_string: str) -> datetime:
    if input_string is None:
        return None
    # 定义一个字典，将月份缩写映射到其数字等效项
    month_dict = {
        "Jan": "01",
        "Feb": "02",
        "Mar": "03",
        "Apr": "04",
        "May": "05",
        "Jun": "06",
        "Jul": "07",
        "Aug": "08",
        "Sep": "09",
        "Oct": "10",
        "Nov": "11",
        "Dec": "12",
    }

    # 将输入字符串分割成其组成部分
    components = input_string.split()
    # 提取相关信息
    day = components[2]
    month = month_dict[components[1]]
    year = components[4]
    time = components[3]
    timezone_offset_minutes = int(components[5])  # 将偏移量转换为分钟
    timezone_hours = timezone_offset_minutes // 60  # 计算小时数
    timezone_minutes = timezone_offset_minutes % 60  # 计算剩余分钟数
    # 创建一个格式化的字符串用于 PostgreSQL 格式的 timestamptz
    timestamp_tz_str = (
        f"{year}-{month}-{day} {time}+{timezone_hours:02}{timezone_minutes:02}"
    )
    return timestamp_tz_str


# 元数据提取函数，用于从 JSON 记录中提取元数据
def extract_metadata(record: dict, metadata: dict) -> dict:
    record_name, record_email = split_name(record["author"])
    metadata["id"] = create_uuid(record["date"])
    metadata["date"] = create_date(record["date"])
    metadata["author_name"] = record_name
    metadata["author_email"] = record_email
    metadata["commit_hash"] = record["commit"]
    return metadata
```

### 将文档和元数据加载到 TimescaleVector 向量存储中

现在我们已经准备好了文档，让我们处理它们并将它们及其向量嵌入表示加载到我们的 TimescaleVector 向量存储中。

由于这是一个演示，我们将只加载前 500 条记录。在实践中，您可以加载任意数量的记录。

```python
NUM_RECORDS = 500
documents = documents[:NUM_RECORDS]
```

然后我们使用 `CharacterTextSplitter` 将文档分割成更小的块，以便于嵌入。请注意，这个分割过程会保留每个文档的元数据。

```python
# 将文档分割成块以便嵌入
text_splitter = CharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
)
docs = text_splitter.split_documents(documents)
```

接下来，我们将从我们预处理完成的文档集合中创建一个 Timescale Vector 实例。

首先，我们将定义一个集合名称，它将是我们 PostgreSQL 数据库中表的名称。

我们还将定义一个时间间隔（time delta），将其传递给 `time_partition_interval` 参数，它将用作按时间分区数据的间隔。每个分区将包含指定时间长度的数据。为了简单起见，我们使用 7 天，但您可以根据您的用例选择任何合适的值——例如，如果您经常查询最近的向量，您可能希望使用较短的时间间隔，如 1 天；如果您查询的是跨越十年的向量，那么您可能希望使用较长的时间间隔，如 6 个月或 1 年。

最后，我们创建 TimescaleVector 实例。我们指定 `ids` 参数为我们在上述预处理步骤中创建的元数据中的 `uuid` 字段。我们这样做是因为我们希望我们 UUID 的时间部分反映过去（即提交发生的时间）的日期。但是，如果我们希望我们的文档与当前日期和时间相关联，我们可以删除 `id` 参数，UUID 将自动以当前日期和时间创建。

```python
# 定义集合名称
COLLECTION_NAME = "timescale_commits"
embeddings = OpenAIEmbeddings()

# 从文档集合创建 Timescale Vector 实例
db = TimescaleVector.from_documents(
    embedding=embeddings,
    ids=[doc.metadata["id"] for doc in docs],
    documents=docs,
    collection_name=COLLECTION_NAME,
    service_url=SERVICE_URL,
    time_partition_interval=timedelta(days=7),
)
```

## 3. 使用 ANN 索引加速查询

您可以通过在嵌入列上创建索引来加速相似性查询。您应该只在摄取了大部分数据后才执行此操作。

Timescale Vector 支持以下索引：

- timescale\_vector 索引 (tsv)：用于快速相似性搜索的类 DiskANN 图形索引（默认）。
- pgvector 的 HNSW 索引：用于快速相似性搜索的分层可导航小世界（Hierarchical Navigable Small World）图索引。
- pgvector 的 IVFFLAT 索引：用于快速相似性搜索的倒排文件（Inverted File）索引。

重要提示：在 PostgreSQL 中，每个表对特定列只能有一个索引。因此，如果您想测试不同索引类型的性能，可以通过以下方式进行操作：(1) 创建具有不同索引的多个表，(2) 在同一表中创建多个向量列并在每个列上创建不同的索引，或者 (3) 通过在同一列上删除并重新创建索引来比较结果。

```python
# 初始化现有的 TimescaleVector 存储
COLLECTION_NAME = "timescale_commits"
embeddings = OpenAIEmbeddings()
db = TimescaleVector(
    collection_name=COLLECTION_NAME,
    service_url=SERVICE_URL,
    embedding_function=embeddings,
)
```

使用 `create_index()` 函数且不带附加参数，将默认创建 timescale\_vector\_index。

```python
# 创建一个索引
# 默认情况下，这将创建一个 Timescale Vector (DiskANN) 索引
db.create_index()
```

您也可以为索引指定参数。有关不同参数及其对性能影响的全面讨论，请参阅 Timescale Vector 文档。

注意：您无需指定参数，因为我们设置了智能默认值。但如果您想针对特定数据集榨取更多性能，您可以随时指定自己的参数。

```python
# 删除旧索引
db.drop_index()

# 创建一个索引
# 注意：您无需指定 m 和 ef_construction 参数，因为我们设置了智能默认值。
db.create_index(index_type="tsv", max_alpha=1.0, num_neighbors=50)
```

Timescale Vector 也支持 HNSW ANN 索引算法以及 ivfflat ANN 索引算法。只需在 `index_type` 参数中指定您想要创建的索引，并可选地指定该索引的参数即可。

```python
# 删除旧索引
db.drop_index()

# 创建一个 HNSW 索引
# 注意：您无需指定 m 和 ef_construction 参数，因为我们设置了智能默认值。
db.create_index(index_type="hnsw", m=16, ef_construction=64)
```

```python
# 删除旧索引
db.drop_index()

# 创建一个 IVFFLAT 索引
# 注意：您无需指定 num_lists 和 num_records 参数，因为我们设置了智能默认值。
db.create_index(index_type="ivfflat", num_lists=20, num_records=1000)
```

一般来说，我们建议使用默认的 timescale\_vector 索引或 HNSW 索引。

```python
# 删除旧索引
db.drop_index()
# 创建一个新的 timescale vector 索引
db.create_index()
```

## 4. 使用 Timescale Vector 进行自查询检索器（Self Querying Retriever）

Timescale Vector 也支持自查询检索器功能，这使其具备自我查询的能力。给定一个带有查询语句和过滤条件（单个或复合）的自然语言查询，检索器会使用查询构建 LLM 链来编写一个 SQL 查询，然后将其应用于 Timescale Vector 向量存储中的底层 PostgreSQL 数据库中。

为了说明 Timescale Vector 的自查询，我们将使用第 3 部分中的相同 gitlog 数据集。

```python
COLLECTION_NAME = "timescale_commits"
vectorstore = TimescaleVector(
    embedding_function=OpenAIEmbeddings(),
    collection_name=COLLECTION_NAME,
    service_url=SERVICE_URL,
)
```

接下来，我们将创建我们的自查询检索器。为此，我们需要预先提供有关文档支持的元数据字段以及文档内容的简短描述。

```python
from langchain.chains.query_constructor.base import AttributeInfo
from langchain_classic.retrievers.self_query.base import SelfQueryRetriever
from langchain_openai import OpenAI

# 向 LLM 提供有关元数据字段的信息
metadata_field_info = [
    AttributeInfo(
        name="id",
        description="A UUID v1 generated from the date of the commit",
        type="uuid",
    ),
    AttributeInfo(
        name="date",
        description="The date of the commit in timestamptz format",
        type="timestamptz",
    ),
    AttributeInfo(
        name="author_name",
        description="The name of the author of the commit",
        type="string",
    ),
    AttributeInfo(
        name="author_email",
        description="The email address of the author of the commit",
        type="string",
    ),
]
document_content_description = "The git log commit summary containing the commit hash, author, date of commit, change summary and change details"

# 从 LLM 实例化自查询检索器
llm = OpenAI(temperature=0)
retriever = SelfQueryRetriever.from_llm(
    llm,
    vectorstore,
    document_content_description,
    metadata_field_info,
    enable_limit=True,
    verbose=True,
)
```

现在让我们在 gitlog 数据集上测试自查询检索器。

运行下面的查询，注意您可以如何用自然语言指定查询、带过滤器的查询和带复合过滤器的查询（使用 AND、OR 的过滤器），自查询检索器会将其转换为 SQL 并对 Timescale Vector PostgreSQL 向量存储执行搜索。

这说明了自查询检索器的强大功能。您可以使用它对向量存储执行复杂搜索，而无需您或您的用户直接编写任何 SQL！

## 5. 使用现有的 TimescaleVector 向量存储

在上面的示例中，我们从文档集合创建了一个向量存储。然而，我们通常希望向现有的 TimescaleVector 存储中插入数据和查询数据。让我们看看如何初始化、向现有 TimescaleVector 存储中的现有文档集合添加文档并查询它们。

要处理现有的 Timescale Vector 存储，我们需要知道要查询的表的名称 (`COLLECTION_NAME`) 和云端 PostgreSQL 数据库的 URL (`SERVICE_URL`)。

```python
# 初始化现有的存储
COLLECTION_NAME = "timescale_commits"
embeddings = OpenAIEmbeddings()
vectorstore = TimescaleVector(
        collection_name=COLLECTION_NAME,
        service_url=SERVICE_URL,
        embedding_function=embeddings,
)
```

要将新数据加载到表中，我们使用 `add_document()` 函数。此函数接受一个文档列表和一个元数据列表。元数据必须包含每个文档的唯一 ID。

如果您希望您的文档与当前的日期和时间相关联，则无需创建 ID 列表。系统将为每个文档自动生成一个 UUID。

如果您希望您的文档与过去的日期和时间相关联，您可以使用 `timecale-vector` Python 库中的 `uuid_from_time` 函数创建 ID 列表，如上文第 2 节所示。此函数接受一个 `datetime` 对象并返回一个 UUID，其中编码了日期和时间。

```python
# 将文档添加到 TimescaleVector 中的集合
ids = vectorstore.add_documents([Document(page_content="foo")])
```

```python
db = TimescaleVector.from_documents(
        documents=docs,
        embedding=embeddings,
        collection_name=COLLECTION_NAME,
        service_url=SERVICE_URL,
        pre_delete_collection=True,
)
```
