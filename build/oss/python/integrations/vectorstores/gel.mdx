> 一个使用 `gel` 作为后端的 LangChain 向量存储抽象的实现。

[Gel](https://www.geldata.com/) 是一个开源的 PostgreSQL 数据层，它针对快速从开发到生产的周期进行了优化。它提供了一个高层次的、严格类型化的类图数据模型、可组合的分层查询语言、完整的 SQL 支持、迁移（migrations）、认证（Auth）和 AI 模块。

相关代码位于一个名为 [langchain-gel](https://github.com/geldata/langchain-gel) 的集成包中。

## 设置 (Setup)

首先安装相关的包：

```python
! pip install -qU gel langchain-gel
```

## 初始化 (Initialization)

为了将 Gel 作为 `VectorStore` 的后端，你需要一个可用的 Gel 实例。
幸运的是，除非你特别需要，否则这不需要涉及 Docker 容器或任何复杂的操作！

要设置一个本地实例，运行：

```python
! gel project init --non-interactive
```

如果你使用的是 [Gel Cloud](https://cloud.geldata.com/)（强烈推荐！），请在该命令中添加一个额外的参数：

```bash
gel project init --server-instance <org-name>/<instance-name>
```

要查看运行 Gel 的各种方法的完整列表，请参阅参考文档的 [Running Gel](https://docs.geldata.com/reference/running) 部分。

### 设置 Schema

[Gel schema](https://docs.geldata.com/reference/datamodel) 是对你的应用程序数据模型的显式高层描述。
除了能够精确定义数据的布局方式之外，它还驱动了 Gel 的许多强大功能，例如链接（links）、访问策略（access policies）、函数（functions）、触发器（triggers）、约束（constraints）、索引（indexes）等等。

LangChain 的 [`VectorStore`](https://reference.langchain.com/python/langchain_core/vectorstores/?h=#langchain_core.vectorstores.base.VectorStore) 期望 Schema 具有以下布局：

```python
schema_content = """
using extension pgvector;

module default {
    scalar type EmbeddingVector extending ext::pgvector::vector<1536>;

    type Record {
        required collection: str;
        text: str;
        embedding: EmbeddingVector;
        external_id: str {
            constraint exclusive;
        };
        metadata: json;

        index ext::pgvector::hnsw_cosine(m := 16, ef_construction := 128)
            on (.embedding)
    }
}
""".strip()

with open("dbschema/default.gel", "w") as f:
    f.write(schema_content)
```

为了将 Schema 更改应用到数据库，请使用 Gel 的 [迁移机制 (migration mechanism)](https://docs.geldata.com/reference/datamodel/migrations) 运行迁移：

```python
! gel migration create --non-interactive
! gel migrate
```

从现在开始，`GelVectorStore` 可以作为 LangChain 中任何其他向量存储的即插即用替代品。

        page_content="the new art exhibit is fascinating",
        metadata={"id": "5", "location": "museum", "topic": "art"},

        page_content="a sculpture exhibit is also at the museum",

## 查询向量存储 (Query vector store)

一旦创建了向量存储并将相关文档添加进去，在运行链（chain）或代理（agent）时，你很可能会希望查询它。

### 过滤支持 (Filtering Support)

向量存储支持一组可以应用于文档元数据字段的过滤器。

| 运算符 (Operator) | 含义/类别 (Meaning/Category) |
|----------|-------------------------|
| \$eq      | 等于 (==)           |
| \$ne      | 不等于 (!=)           |
| \$lt      | 小于 (&lt;)           |
| \$lte     | 小于或等于 (&lt;=)           |
| \$gt      | 大于 (>)        |
| \$gte     | 大于或等于 (>=)           |
| \$in      | 特殊情况 (in)      |
| \$nin     | 特殊情况 (not in)      |
| \$between | 特殊情况 (between) |
| \$like    | 文本 (like)             |
| \$ilike   | 文本 (不区分大小写的 like) |
| \$and     | 逻辑 (and)           |
| \$or      | 逻辑 (or)            |

### 直接查询 (Query directly)

执行简单的相似性搜索可以按如下方式进行：

```python
results = vector_store.similarity_search(
    "kitty", k=10, filter={"id": {"$in": ["1", "5", "2", "9"]}}
)
for doc in results:
    print(f"* {doc.page_content} [{doc.metadata}]")
```

如果你提供一个包含多个字段但没有运算符的字典，顶层将被解释为逻辑 **AND** 过滤器。

```python
vector_store.similarity_search(
    "ducks",
    k=10,
    filter={
        "id": {"$in": ["1", "5", "2", "9"]},
        "location": {"$in": ["pond", "market"]},
    },
)
```

```python
vector_store.similarity_search(
    "ducks",
    k=10,
    filter={
        "$and": [
            {"id": {"$in": ["1", "5", "2", "9"]}},
            {"location": {"$in": ["pond", "market"]}},
        ]
    },
)
```

如果你希望执行相似性搜索并接收相应的分数，可以运行：

```python
results = vector_store.similarity_search_with_score(query="cats", k=1)
for doc, score in results:
    print(f"* [SIM={score:3f}] {doc.page_content} [{doc.metadata}]")
```

### 通过转换为检索器查询 (Query by turning into retriever)

你也可以将向量存储转换为检索器（retriever），以便在链中使用更加方便。

```python
retriever = vector_store.as_retriever(search_kwargs={"k": 1})
retriever.invoke("kitty")
```
