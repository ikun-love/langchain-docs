>`LangChain decorators` 是建立在 LangChain 之上的一个层次，它提供了语法糖 🍭，用于编写自定义的 LangChain 提示和链（Chains）。
>
>如需反馈、报告问题、贡献代码，请在此处创建 Issue：
>[ju-bezdek/langchain-decorators](https://github.com/ju-bezdek/langchain-decorators)


主要原则和优势：

- 更具 `pythonic` 风格的代码编写方式
- 编写多行提示时，不会因缩进破坏代码流程
- 利用 IDE 内置对 **提示、类型检查**、以及 **带有文档的弹出窗口** 的支持，可以快速查看函数内部的提示内容、它所消耗的参数等信息。
- 充分利用 🦜🔗 LangChain 生态系统的所有强大功能
- 增加了对 **可选参数** 的支持
- 可以通过将参数绑定到一个类，轻松地在提示之间共享参数


这是使用 **LangChain Decorators ✨** 编写代码的简单示例

``` python
@llm_prompt
def write_me_short_post(topic:str, platform:str="twitter", audience:str = "developers")->str:
    """
    为我的关于 {topic} 的帖子，针对 {platform} 平台写一个简短的标题。
    [这]应该面向 {audience} 受众。
    (最多 15 个词)
    """
    return

# 自然地运行它
write_me_short_post(topic="starwars")
# 或者
write_me_short_post(topic="starwars", platform="redit")
```

# 定义其他参数
这里我们只是使用 `llm_prompt` 装饰器将函数标记为提示，有效地将其转换为一个 LLMChain。本应在初始化时传入的参数，现在被装饰器隐藏了实现细节。标准 LLMChain 需要比 `inputs_variables` 和 `prompt` 更多的初始化参数... 装饰器帮我们隐藏了这些实现细节。以下是它的工作方式：

1. 使用 **全局设置 (Global settings)**：

``` python
# 定义所有提示的全局设置（如果未设置 - 当前默认值为 chatGPT）
from langchain_decorators import GlobalSettings

GlobalSettings.define_settings(
    default_llm=ChatOpenAI(temperature=0.0), # 这是默认设置... 可以在此处全局更改
    default_streaming_llm=ChatOpenAI(temperature=0.0,streaming=True), # 这是默认设置... 可以在此处为所有流式任务更改... 将用于流式传输
)
```
2. 使用预定义的 **提示类型 (prompt types)**

```python
# 你可以更改默认的提示类型
from langchain_decorators import PromptTypes, PromptTypeSettings

PromptTypes.AGENT_REASONING.llm = ChatOpenAI()

# 或者你可以定义自己的类型：
class MyCustomPromptTypes(PromptTypes):
    GPT4=PromptTypeSettings(llm=ChatOpenAI(model="gpt-4"))

@llm_prompt(prompt_type=MyCustomPromptTypes.GPT4)
def write_a_complicated_code(app_idea:str)->str:
    ...
```
3. 将设置 **直接定义在装饰器中**

``` python
from langchain_openai import OpenAI

@llm_prompt(
    llm=OpenAI(temperature=0.7),
    stop_tokens=["\nObservation"],
    ...
    )
def creative_writer(book_title:str)->str:
    ...
```

# 简化的流式传输

如果我们想利用流式传输：
 - 我们需要将提示定义为异步函数 (`async function`)
 - 在装饰器上打开流式传输 (streaming)，或者我们可以定义一个带有流式传输的 `PromptType`
 - 使用 `StreamingContext` 捕获流

通过这种方式，我们只需标记哪个提示应该被流式传输，而无需干预我们应该使用哪个 LLM，在链的特定部分传递和分发流处理程序... 只需在提示/提示类型上打开或关闭流式传输即可。

只有当我们从流式上下文中调用它时，流式传输才会发生... 在那里我们可以定义一个简单的函数来处理流。

```python
# 此代码示例是完整的，可以按原样运行

from langchain_decorators import StreamingContext, llm_prompt

# 这将标记提示以进行流式传输（如果你只想流式传输应用中的某些提示，但不想分发回调处理程序，这很有用）
# 注意：只有异步函数才能被流式传输（如果不是，将会收到错误）
@llm_prompt(capture_stream=True)
async def write_me_short_post(topic:str, platform:str="twitter", audience:str = "developers"):
    """
    为我的关于 {topic} 的帖子，针对 {platform} 平台写一个简短的标题。
    [这]应该面向 {audience} 受众。
    (最多 15 个词)
    """
    pass



# 一个任意函数，用于演示流式传输... 在现实世界中将是 WebSocket 代码
tokens=[]
def capture_stream_func(new_token:str):
    tokens.append(new_token)

# 如果我们想捕获流，我们需要将执行包装在 StreamingContext 中...
# 这将允许我们捕获流，即使提示调用隐藏在更高层级的方法中
# 在这里只捕获那些用 capture_stream 标记的提示
with StreamingContext(stream_to_stdout=True, callback=capture_stream_func):
    result = await run_prompt()
    print("流式传输完成... 我们可以通过交替的颜色区分 token")


print("\n我们捕获了",len(tokens),"个 token🎉\n")
print("这是结果：")
print(result)
```
# 提示声明 (Prompt declarations)
默认情况下，提示是整个函数的文档字符串，除非你标记了你的提示。

## 文档化你的提示

我们可以通过指定一个带有 `<prompt>` 语言标签的代码块来指定文档的哪一部分是提示定义。

```python
@llm_prompt
def write_me_short_post(topic:str, platform:str="twitter", audience:str = "developers"):
    """
    这里有一种在函数文档字符串中编写提示的好方法，同时为开发者提供额外的文档说明。

    它需要是一个代码块，并标记为 `<prompt>` 语言
    ```<prompt>
    为我的关于 {topic} 的帖子，针对 {platform} 平台写一个简短的标题。
    [这]应该面向 {audience} 受众。
    (最多 15 个词)
    ```
    现在只有上面的代码块将被用作提示，而文档字符串的其余部分将用作开发人员的描述。
    （它还有一个额外的好处，即 IDE（如 VS Code）可以正确显示提示（不会尝试将其解析为 markdown，因此不会正确显示换行符））
    """
    return
```

## 聊天消息提示 (Chat messages prompt)

对于聊天模型来说，将提示定义为消息模板集非常有用... 做法如下：

```python
@llm_prompt
def simulate_conversation(human_input:str, agent_role:str="a pirate"):
    """
    ## 系统消息
     - 注意 <prompt:_role_> 标签内带有 `:system` 后缀的


    ```<prompt:system>
    你是一个 {agent_role} 黑客。你必须像他一样行动。
    你总是用代码回复，使用 python 或 javascript 代码块...
    例如：

    ... 不要用任何其他内容回复... 只用代码 - 遵守你的角色。
    ```
    # 人类消息
    (我们使用的是 LLM 强制执行的真实角色 - GPT 支持 system, user, assistant)
    ``` <prompt:user>
    你好，你是谁
    ```
    回复：


    ``` <prompt:assistant>
    \``` python <<- 用 \ 来转义内部代码块，该代码块应作为提示的一部分存在
    def hello():
        print("Argh... hello you pesky pirate")
    \```
    ```

    我们还可以使用占位符添加一些历史记录
    ```<prompt:placeholder>
    {history}
    ```
    ```<prompt:user>
    {human_input}
    ```

    现在只有上面的代码块将被用作提示，而文档字符串的其余部分将用作开发人员的描述。
    （它还有一个额外的好处，即 IDE（如 VS Code）可以正确显示提示（不会尝试将其解析为 markdown，因此不会正确显示换行符））
    """
    pass
```

这里的角色是模型的原生角色（对于 ChatGPT 是 assistant, user, system）

# 可选部分 (Optional sections)
- 你可以定义整个提示部分应该是可选的
- 如果该部分中的任何输入缺失，则整个部分将不会被渲染

其语法如下：

```python
@llm_prompt
def prompt_with_optional_partials():
    """
    这段文本将始终被渲染，但是

    {? 位于此块内的任何内容都只在 {value} 参数全部不为空 (None | "") 时才会被渲染 ?}

    你也可以把它放在单词之间
    这段内容也会被渲染{? ，但是
        只有当 {this_value} 和 {this_value} 都不为空时，此块才会被渲染?} !
    """
```
# 输出解析器 (Output parsers)

- `llm_prompt` 装饰器会根据输出类型自动尝试检测最佳输出解析器。（如果未设置，则返回原始字符串）
- 原生地也支持 `list`、`dict` 和 `pydantic` 输出（自动完成）

```python
# 此代码示例是完整的，可以按原样运行

from langchain_decorators import llm_prompt

@llm_prompt
def write_name_suggestions(company_business:str, count:int)->list:
    """ 为一个 {company_business} 公司写 {count} 个好的名字建议
    """
    pass

write_name_suggestions(company_business="sells cookies", count=5)
```
## 更复杂的结构

对于 `dict` / `pydantic`，你需要指定格式化说明...
这可能很繁琐，因此你可以让输出解析器根据模型（pydantic）为你生成说明

```python
from langchain_decorators import llm_prompt
from pydantic import BaseModel, Field


class TheOutputStructureWeExpect(BaseModel):
    name:str = Field (description="公司的名称")
    headline:str = Field( description="公司的标语（用于登陆页面）")
    employees:list[str] = Field(description="5-8 个虚构员工的姓名及其职位")

@llm_prompt()
def fake_company_generator(company_business:str)->TheOutputStructureWeExpect:
    """ 为一个 {company_business} 生成一个虚构公司
    {FORMAT_INSTRUCTIONS}
    """
    return

company = fake_company_generator(company_business="sells cookies")

# 漂亮地打印结果
print("公司名称: ",company.name)
print("公司标语: ",company.headline)
print("公司员工: ",company.employees)

```
# 将提示绑定到对象上

```python
from pydantic import BaseModel
from langchain_decorators import llm_prompt

class AssistantPersonality(BaseModel):
    assistant_name:str
    assistant_role:str
    field:str

    @property
    def a_property(self):
        return "whatever"

    def hello_world(self, function_kwarg:str=None):
        """
        我们可以在提示中引用任何 {field} 或 {a_property} ... 并与方法中的 {function_kwarg} 结合起来
        """


    @llm_prompt
    def introduce_your_self(self)->str:
        """
        ``` <prompt:system>
        你是一个名叫 {assistant_name} 的助手。
        你的角色是充当 {assistant_role}
        ```
        ```<prompt:user>
        介绍你自己 (少于 20 个词)
        ```
        """



personality = AssistantPersonality(assistant_name="John", assistant_role="a pirate")

print(personality.introduce_your_self(personality))
```
