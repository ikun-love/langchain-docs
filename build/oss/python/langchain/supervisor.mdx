## 概述

**主管模式**（Supervisor Pattern）是一种多代理（[multi-agent](/oss/python/langchain/multi-agent)）架构，其中一个中心化的主管代理协调专门的工人代理。当任务需要不同类型的专业知识时，这种方法表现出色。与其构建一个必须在所有领域管理工具选择的单一代理，不如创建聚焦的专家，由一个理解整体工作流程的主管来协调。

在本教程中，您将构建一个个人助理系统，通过一个实际的工作流程来演示这种模式的优势。该系统将协调两个职责本质上不同的专家：

- **日历代理**：处理日程安排、可用性检查和事件管理。
- **邮件代理**：管理通信、起草消息和发送通知。

我们还将整合[人工干预审核](/oss/python/langchain/human-in-the-loop)机制，允许用户根据需要批准、编辑和拒绝操作（例如传出的电子邮件）。

### 为什么要使用主管？

多代理架构允许您将[工具](/oss/python/langchain/tools)划分给不同的工作代理，每个代理都有自己独立的提示词或指令。想象一个可以直接访问所有日历和电子邮件 API 的代理：它必须从许多相似的工具中进行选择，理解每个 API 的确切格式，并同时处理多个领域。如果性能下降，将相关工具和关联的提示词分离到逻辑组中可能是有益的（部分是为了管理迭代改进）。

## 1. 定义工具

首先定义那些需要结构化输入（Structured Inputs）的工具。在实际应用中，这些将调用实际的 API（如 Google Calendar、SendGrid 等）。在本教程中，我们将使用存根（stubs）来演示这种模式。

```python
from langchain.tools import tool

@tool
def create_calendar_event(
    title: str,
    start_time: str,       # ISO 格式: "2024-01-15T14:00:00"
    end_time: str,         # ISO 格式: "2024-01-15T15:00:00"
    attendees: list[str],  # 电子邮件地址
    location: str = ""
) -> str:
    """创建日历事件。需要精确的 ISO 日期时间格式。"""
    # 存根：在实践中，这将调用 Google Calendar API, Outlook API 等。
    return f"事件已创建: {title} 从 {start_time} 到 {end_time} 共有 {len(attendees)} 位参与者"


@tool
def send_email(
    to: list[str],  # 电子邮件地址
    subject: str,
    body: str,
    cc: list[str] = []
) -> str:
    """通过电子邮件 API 发送电子邮件。需要格式正确的地址。"""
    # 存根：在实践中，这将调用 SendGrid, Gmail API 等。
    return f"电子邮件已发送至 {', '.join(to)} - 主题: {subject}"


@tool
def get_available_time_slots(
    attendees: list[str],
    date: str,  # ISO 格式: "2024-01-15"
    duration_minutes: int
) -> list[str]:
    """检查给定参与者在特定日期的日历可用时间段。"""
    return ["09:00", "14:00", "16:00"]
```




## 2. 创建专用的子代理

接下来，我们将创建处理每个领域的专用子代理。

### 创建一个日历代理

日历代理理解自然语言的日程安排请求，并将其转换为精确的 API 调用。它负责日期解析、可用性检查和事件创建。

```python
from langchain.agents import create_agent


CALENDAR_AGENT_PROMPT = (
    "你是一个日历调度助手。 "
    "将自然语言调度请求（例如，“下周二下午 2 点”）解析为正确的 ISO 日期时间格式。 "
    "在需要时使用 get_available_time_slots 检查可用性。 "
    "使用 create_calendar_event 来安排事件。 "
    "在你的最终回复中始终确认已调度的内容。"
)

calendar_agent = create_agent(
    model,
    tools=[create_calendar_event, get_available_time_slots],
    system_prompt=CALENDAR_AGENT_PROMPT,
)
```

## 3. 将子代理包装为工具

现在将每个子代理包装成一个主管可以调用的工具。这是创建分层系统的关键架构步骤。主管将看到“`schedule_event`”这样的高级工具，而不是“`create_calendar_event`”这样的低级工具。

```python
@tool
def schedule_event(request: str) -> str:
    """使用自然语言安排日历事件。

    当用户想要创建、修改或检查日历约会*时*使用此工具。
    处理日期/时间解析、可用性检查和事件创建。

    输入：自然语言调度请求（例如，“与设计团队开会，下周二下午 2 点”）
    """
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })
    return result["messages"][-1].text


@tool
def manage_email(request: str) -> str:
    """使用自然语言发送电子邮件。

    当用户想要发送通知、提醒或任何电子邮件通信*时*使用此工具。
    处理收件人提取、主题生成和电子邮件撰写。

    输入：自然语言电子邮件请求（例如，“给他们发送一个关于会议的提醒”）
    """
    result = email_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })
    return result["messages"][-1].text
```




工具描述帮助主管决定何时使用每个工具，因此请确保它们清晰明确。我们只返回子代理的最终响应，因为主管不需要看到中间的推理过程或工具调用。

## 4. 创建主管代理

现在创建主管，它协调子代理。主管只能看到高级工具，并在领域级别而不是单个 API 级别上做出路由决策。

```python
SUPERVISOR_PROMPT = (
    "你是一位乐于助人的个人助理。 "
    "你可以安排日历事件和发送电子邮件。 "
    "将用户请求分解为适当的工具调用并协调结果。 "
    "当请求涉及多个操作时，按顺序使用多个工具。"
)

supervisor_agent = create_agent(
    model,
    tools=[schedule_event, manage_email],
    system_prompt=SUPERVISOR_PROMPT,
)
```

## 7. 高级功能：控制信息流

### 将附加的对话上下文传递给子代理

```python
from langchain.tools import tool, ToolRuntime

@tool
def schedule_event(
    request: str,
    runtime: ToolRuntime
) -> str:
    """使用自然语言安排日历事件。"""
    # 自定义子代理收到的上下文
    original_user_message = next(
        message for message in runtime.state["messages"]
        if message.type == "human"
    )
    prompt = (
        "你正在协助以下用户查询：\n\n"
        f"{original_user_message.text}\n\n"
        "你的任务是以下子请求：\n\n"
        f"{request}"
    )
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": prompt}],
    })
    return result["messages"][-1].text
```




这允许子代理查看完整的对话历史记录，这在解决像“明天同一时间安排”这样的模糊引用时非常有用（引用之前的对话）。

```python
    """使用自然语言安排日历事件。"""
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })

    # 选项 1：仅返回确认消息
    return result["messages"][-1].text

    # 选项 2：返回结构化数据
    # return json.dumps({
    #     "status": "success",
    #     "event_id": "evt_123",
    #     "summary": result["messages"][-1].text
    # })
```




**重要提示：** 确保子代理的提示词强调他们的最终消息应包含所有相关信息。常见的失败模式是子代理执行了工具调用但没有在最终响应中包含结果。



## 8. 关键要点

主管模式创建了抽象层，每一层都有明确的职责。在设计主管系统时，应从清晰的领域边界开始，并为每个子代理提供聚焦的工具和提示词。为主管编写清晰的工具描述，在集成之前独立测试每一层，并根据您的具体需求控制信息流。

<Tip>
**何时使用主管模式**

当您有多个不同的领域（日历、电子邮件、CRM、数据库）时，每个领域都有多个工具或复杂的逻辑，您希望集中控制工作流程，并且子代理不需要直接与用户对话时，请使用主管模式。

对于只有少量工具的简单情况，请使用单个代理。当代理需要与用户进行对话时，请使用[交接（handoffs）](/oss/python/langchain/multi-agent#handoffs)代替。对于代理之间的点对点协作，请考虑其他多代理模式。
</Tip>
