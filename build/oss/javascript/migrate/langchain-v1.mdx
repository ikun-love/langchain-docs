## `createAgent`

在 v1 中，React Agent 的预构建组件现已位于 `langchain` 包中。下表概述了功能的变化情况：

| 部分 | 变更内容 |
|---------|--------------|
| [导入路径](#import-path) | 包从 `@langchain/langgraph/prebuilts` 迁移到 `langchain` |
| [提示词](#prompts) | 参数重命名为 `systemPrompt`，动态提示词使用中间件 |
| [预模型钩子](#pre-model-hook) | 被具有 `beforeModel` 方法的中间件取代 |
| [后模型钩子](#post-model-hook) | 被具有 `afterModel` 方法的中间件取代 |
| [自定义状态](#custom-state) | 在中间件中定义，仅限于 Zod 对象 |
| [模型](#model) | 通过中间件动态选择，不再支持预绑定的模型 |
| [工具](#tools) | 工具错误处理移至中间件中的 `wrapToolCall` |
| [结构化输出](#structured-output) | 移除了基于提示词的输出，请使用 `toolStrategy`/`providerStrategy` |
| [流式传输节点名称](#streaming-node-name-rename) | 节点名称从 `"agent"` 更改为 `"model"` |
| [运行时上下文](#runtime-context) | 使用 `context` 属性代替 `config.configurable` |
| [命名空间](#simplified-package) | 简化以专注于 Agent 构建块，遗留代码已移至 `@langchain/classic` |

### 导入路径

React Agent 预构建组件的导入路径已从 `@langchain/langgraph/prebuilts` 更改为 `langchain`。函数的名称已从 `createReactAgent` 更改为 `createAgent`：

```typescript
import { createReactAgent } from "@langchain/langgraph/prebuilts"; // [!code --]
import { createAgent } from "langchain"; // [!code ++]
```

### 提示词（Prompts）

#### 静态提示词重命名

`prompt` 参数已重命名为 `systemPrompt`：

<CodeGroup>
```typescript v1 (新)
import { createAgent } from "langchain";

agent = createAgent({
  model,
  tools,
  systemPrompt: "You are a helpful assistant.", // [!code highlight]
});
```
```typescript v0 (旧)
import { createReactAgent } from "@langchain/langgraph/prebuilts";

const agent = createReactAgent({
  model,
  tools,
  prompt: "You are a helpful assistant.", // [!code highlight]
});
```
</CodeGroup>

#### `SystemMessage`

如果在使用 `SystemMessage` 对象作为系统提示词时，其字符串内容现在会直接被使用：

<CodeGroup>
```typescript v1 (新)
import { SystemMessage, createAgent } from "langchain";

const agent = createAgent({
  model,
  tools,
  systemPrompt: "You are a helpful assistant.", // [!code highlight]
});
```
```typescript v0 (旧)
import { createReactAgent } from "@langchain/langgraph/prebuilts";

const agent = createReactAgent({
  model,
  tools,
  prompt: new SystemMessage(content: "You are a helpful assistant."), // [!code highlight]
});
```
</CodeGroup>

#### 动态提示词

动态提示词是一种核心的上下文工程模式——它会根据当前的对话状态来调整你告诉模型的指示。要实现此功能，请使用 `dynamicSystemPromptMiddleware`：

<CodeGroup>
```typescript v1 (新)
import { createAgent, dynamicSystemPromptMiddleware } from "langchain";
import * as z from "zod";

const contextSchema = z.object({
  userRole: z.enum(["expert", "beginner"]).default("beginner"),
});

const userRolePrompt = dynamicSystemPromptMiddleware<z.infer<typeof contextSchema>>( // [!code highlight]
    (_state, runtime) => {
        const userRole = runtime.context.userRole;
        const basePrompt = "You are a helpful assistant.";

        if (userRole === "expert") {
            return `${basePrompt} Provide detailed technical responses.`;
        } else if (userRole === "beginner") {
            return `${basePrompt} Explain concepts simply and avoid jargon.`;
        }
        return basePrompt; // [!code highlight]
    }
);

const agent = createAgent({
  model,
  tools,
  middleware: [userRolePrompt],
  contextSchema,
});

await agent.invoke(
    {
        messages: [new HumanMessage("Explain async programming")]
    },
    {
        configurable: {
            userRole: "expert",
        }
    }
);
```

```typescript v0 (旧)
import { createReactAgent } from "@langchain/langgraph/prebuilts";

const contextSchema = z.object({
  userRole: z.enum(["expert", "beginner"]).default("user"),
});

const agent = createReactAgent({
  model,
  tools,
  prompt: (state) => {
    const userRole = state.context.userRole;
    const basePrompt = "You are a helpful assistant.";

    if (userRole === "expert") {
      return `${basePrompt} Provide detailed technical responses.`;
    } else if (userRole === "beginner") {
      return `${basePrompt} Explain concepts simply and avoid jargon.`;
    }
    return basePrompt;
  },
  contextSchema,
});

// Use with context
await agent.invoke({
  messages: [new HumanMessage("Explain async programming")],
  context: { userRole: "expert" },
});
```
</CodeGroup>


### 预模型钩子（Pre-model hook）

预模型钩子现在通过实现 `beforeModel` 方法的中间件来完成。这种模式更具可扩展性——你可以在调用模型之前定义多个中间件来运行，并在 Agent 之间重用它们。

常见用例包括：
- 总结对话历史
- 裁剪消息
- 输入护栏，例如 PII（个人身份信息）的屏蔽

v1 包含了内置的总结中间件：

<CodeGroup>
```typescript v1 (新)
import { createAgent, summarizationMiddleware } from "langchain";

const agent = createAgent({
  model: "claude-sonnet-4-5-20250929",
  tools,
  middleware: [
    summarizationMiddleware({
      model: "claude-sonnet-4-5-20250929",
      trigger: { tokens: 1000 },
    }),
  ],
});
```
```typescript v0 (旧)
import { createReactAgent } from "@langchain/langgraph/prebuilts";

function customSummarization(state) {
  // Custom logic for message summarization
}

const agent = createReactAgent({
  model: "claude-sonnet-4-5-20250929",
  tools,
  preModelHook: customSummarization,
});
```
</CodeGroup>

### 后模型钩子（Post-model hook）

后模型钩子现在通过实现 `afterModel` 方法的中间件来完成。这允许你在模型响应后组合多个处理器。

常见用例包括：
- 人工干预审批（Human-in-the-loop approval）
- 输出护栏

v1 包含了内置的人工干预中间件：

<CodeGroup>
```typescript v1 (新)
import { createAgent, humanInTheLoopMiddleware } from "langchain";

const agent = createAgent({
  model: "claude-sonnet-4-5-20250929",
  tools: [readEmail, sendEmail],
  middleware: [
    humanInTheLoopMiddleware({
      interruptOn: {
        sendEmail: { allowedDecisions: ["approve", "edit", "reject"] },
      },
    }),
  ],
});
```
```typescript v0 (旧)
import { createReactAgent } from "@langchain/langgraph/prebuilts";

function customHumanInTheLoopHook(state) {
  // Custom approval logic
}

const agent = createReactAgent({
  model: "claude-sonnet-4-5-20250929",
  tools: [readEmail, sendEmail],
  postModelHook: customHumanInTheLoopHook,
});
```
</CodeGroup>

### 自定义状态（Custom state）

自定义状态现在通过中间件中使用 `stateSchema` 属性来定义。使用 Zod 来声明在 Agent 运行过程中携带的额外状态字段。

<CodeGroup>
```typescript v1 (新)
import * as z from "zod";
import { createAgent, createMiddleware, tool } from "langchain";

const UserState = z.object({
  userName: z.string(),
});

const userState = createMiddleware({
  name: "UserState",
  stateSchema: UserState,
  beforeModel: (state) => {
    // Access custom state properties
    const name = state.userName;
    // Optionally modify messages/system prompt based on state
    return;
  },
});

const greet = tool(
  async () => {
    return "Hello!";
  },
  {
    name: "greet",
    description: "Greet the user",
    schema: z.object({}),
  }
);

const agent = createAgent({
  model: "claude-sonnet-4-5-20250929",
  tools: [greet],
  middleware: [userState],
});

await agent.invoke({
  messages: [{ role: "user", content: "Hi" }],
  userName: "Ada",
});
```
```typescript v0 (旧)
import { getCurrentTaskInput } from "@langchain/langgraph";
import { createReactAgent } from "@langchain/langgraph/prebuilts";
import * as z from "zod";

const UserState = z.object({
  userName: z.string(),
});

const greet = tool(
  async () => {
    const state = await getCurrentTaskInput();
    const userName = state.userName;
    return `Hello ${userName}!`;
  },
);

// Custom state was provided via agent-level state schema or accessed ad hoc in hooks
const agent = createReactAgent({
  model: "claude-sonnet-4-5-20250929",
  tools: [greet],
  stateSchema: UserState,
});
```
</CodeGroup>

### 模型（Model）

动态模型选择现在通过中间件发生。使用 `wrapModelCall` 来根据状态或运行时上下文来交换模型（和工具）。在 `createReactAgent` 中，这曾是通过传递给 `model` 参数的函数来完成的。

此功能已移植到 v1 中的中间件接口。

#### 动态模型选择

<CodeGroup>
```typescript v1 (新)
import { createAgent, createMiddleware } from "langchain";

const dynamicModel = createMiddleware({
  name: "DynamicModel",
  wrapModelCall: (request, handler) => {
    const messageCount = request.state.messages.length;
    const model = messageCount > 10 ? "openai:gpt-5" : "openai:gpt-5-nano";
    return handler({ ...request, model });
  },
});

const agent = createAgent({
  model: "gpt-5-nano",
  tools,
  middleware: [dynamicModel],
});
```
```typescript v0 (旧)
import { createReactAgent } from "@langchain/langgraph/prebuilts";

function selectModel(state) {
  return state.messages.length > 10 ? "openai:gpt-5" : "openai:gpt-5-nano";
}

const agent = createReactAgent({
  model: selectModel,
  tools,
});
```
</CodeGroup>

#### 预绑定模型（Pre-bound models）

为了更好地支持结构化输出，`createAgent` 应该接收一个普通的模型（字符串或实例）和一个单独的 `tools` 列表。在使用结构化输出时，应避免传递预先绑定了工具的模型。

```typescript
// 不再支持
// const modelWithTools = new ChatOpenAI({ model: "gpt-4o-mini" }).bindTools([someTool]);
// const agent = createAgent({ model: modelWithTools, tools: [] });

// 请改为使用以下方式
const agent = createAgent({ model: "gpt-4o-mini", tools: [someTool] });
```

### 工具（Tools）

`createAgent` 的 `tools` 参数接受：

- 使用 `tool` 创建的函数
- LangChain 工具实例
- 代表内置提供商工具的对象

#### 处理工具错误

现在可以通过实现 `wrapToolCall` 方法的中间件来配置工具错误的捕获处理。

<CodeGroup>
```typescript v1 (新)
import { createAgent, createMiddleware, ToolMessage } from "langchain";

const handleToolErrors = createMiddleware({
  name: "HandleToolErrors",
  wrapToolCall: async (request, handler) => {
    try {
      return await handler(request);
    } catch (error) {
      // 只处理因输入无效（通过了 Schema 验证但在运行时失败，例如无效的 SQL 语法）而导致的工具执行错误。
      // 不要处理：
      // - 网络故障（请改用工具重试中间件）
      // - 不正确的工具实现错误（应冒泡）
      // - Schema 不匹配错误（框架已自动处理）
      //
      // 向模型返回自定义错误消息
      return new ToolMessage({
        content: `工具错误：请检查您的输入并重试。(${error})`,
        tool_call_id: request.toolCall.id!,
      });
    }
  },
});

const agent = createAgent({
  model: "claude-sonnet-4-5-20250929",
  tools: [checkWeather, searchWeb],
  middleware: [handleToolErrors],
});
```
```typescript v0 (旧)
import { createReactAgent, ToolNode } from "@langchain/langgraph/prebuilts";

const agent = createReactAgent({
  model: "claude-sonnet-4-5-20250929",
  tools: new ToolNode(
    [checkWeather, searchWeb],
    { handleToolErrors: true } // [!code highlight]
  ),
});
```
</CodeGroup>

### 结构化输出（Structured output）

#### 节点变更

结构化输出过去在主 Agent 之外的单独节点中生成。现在不再是这种情况。结构化输出在主循环中生成（没有额外的 LLM 调用），从而降低了成本和延迟。

#### 工具和提供商策略

在 v1 中，有两种策略：

- `toolStrategy` 使用人工工具调用来生成结构化输出
- `providerStrategy` 使用提供商原生的结构化输出生成

<CodeGroup>
```typescript v1 (新)
import { createAgent, toolStrategy } from "langchain";
import * as z from "zod";

const OutputSchema = z.object({
  summary: z.string(),
  sentiment: z.string(),
});

const agent = createAgent({
  model: "gpt-4o-mini",
  tools,
  // 明确使用工具策略
  responseFormat: toolStrategy(OutputSchema), // [!code highlight]
});
```
```typescript v0 (旧)
import { createReactAgent } from "@langchain/langgraph/prebuilts";
import * as z from "zod";

const OutputSchema = z.object({
  summary: z.string(),
  sentiment: z.string(),
});

const agent = createReactAgent({
  model: "gpt-4o-mini",
  tools,
  // 结构化输出主要通过工具调用驱动，选项较少
  responseFormat: OutputSchema,
});
```
</CodeGroup>

#### 移除了基于提示词的输出

为了支持上述策略，移除了 `responseFormat` 中通过自定义指令实现的基于提示词的输出。

### 流式传输节点名称重命名

当从 Agent 流式传输事件时，节点名称已从 `"agent"` 更改为 `"model"`，以更好地反映该节点的用途。

### 运行时上下文（Runtime context）

调用 Agent 时，通过 `context` 配置参数传递静态、只读的配置信息。这取代了使用 `config.configurable` 的旧模式。

<CodeGroup>
```typescript v1 (新)
import { createAgent, HumanMessage } from "langchain";
import * as z from "zod";

const agent = createAgent({
  model: "gpt-4o",
  tools,
  contextSchema: z.object({ userId: z.string(), sessionId: z.string() }),
});

const result = await agent.invoke(
  { messages: [new HumanMessage("Hello")] },
  { context: { userId: "123", sessionId: "abc" } }, // [!code highlight]
);
```
```typescript v0 (旧)
import { createReactAgent, HumanMessage } from "@langchain/langgraph/prebuilts";

const agent = createReactAgent({ model, tools });

// 通过 config.configurable 传递上下文
const result = await agent.invoke(
  { messages: [new HumanMessage("Hello")] },
  {
    config: { // [!code highlight]
      configurable: { userId: "123", sessionId: "abc" }, // [!code highlight]
    }, // [!code highlight]
  }
);
```
</CodeGroup>

<Note>
    旧的 `config.configurable` 模式对于向后兼容仍然有效，但对于新应用或迁移到 v1 的应用，建议使用新的 `context` 参数。
</Note>

## 标准内容（Standard content）

在 v1 中，消息获得了提供商无关的标准内容块。通过 `message.contentBlocks` 访问它们，可以跨提供商获得一致的、类型化的视图。现有的 `message.content` 字段对于字符串或提供商原生的结构保持不变。

### 变更之处

- 消息上新增 `contentBlocks` 属性，用于规范化内容。
- 引入新的 TypeScript 类型在 `ContentBlock` 下，以实现强类型检查。
- 通过 `LC_OUTPUT_VERSION=v1` 或 `outputVersion: "v1"` 可选地将标准块序列化到 `content` 字段中。

### 读取标准化内容

<CodeGroup>
```typescript v1 (新)
import { initChatModel } from "langchain";

const model = await initChatModel("gpt-5-nano");
const response = await model.invoke("Explain AI");

for (const block of response.contentBlocks) {
  if (block.type === "reasoning") {
    console.log(block.reasoning);
  } else if (block.type === "text") {
    console.log(block.text);
  }
}
```
```typescript v0 (旧)
// Provider-native formats vary; you needed per-provider handling.
const response = await model.invoke("Explain AI");
for (const item of response.content as any[]) {
  if (item.type === "reasoning") {
    // OpenAI-style reasoning
  } else if (item.type === "thinking") {
    // Anthropic-style thinking
  } else if (item.type === "text") {
    // Text
  }
}
```
</CodeGroup>

### 创建多模态消息

<CodeGroup>
```typescript v1 (新)
import { HumanMessage } from "langchain";

const message = new HumanMessage({
  contentBlocks: [
    { type: "text", text: "Describe this image." },
    { type: "image", url: "https://example.com/image.jpg" },
  ],
});
const res = await model.invoke([message]);
```
```typescript v0 (旧)
import { HumanMessage } from "langchain";

const message = new HumanMessage({
  // Provider-native structure
  content: [
    { type: "text", text: "Describe this image." },
    { type: "image_url", image_url: { url: "https://example.com/image.jpg" } },
  ],
});
const res = await model.invoke([message]);
```
</CodeGroup>

### 序列化标准内容

默认情况下，标准内容块**不会**序列化到 `content` 属性中。如果你需要在 `content` 属性中访问标准内容块（例如，将消息发送给客户端时），可以选择选择将其序列化到 `content` 中。

<CodeGroup>
```bash
export LC_OUTPUT_VERSION=v1
```
```typescript
import { initChatModel } from "langchain";

const model = await initChatModel("gpt-5-nano", {
  outputVersion: "v1",
});
```
</CodeGroup>

    了解更多：[消息](/oss/javascript/langchain/messages#message-content) 和 [标准内容块](/oss/javascript/langchain/messages#standard-content-blocks)。有关输入的示例，请参阅[多模态](/oss/javascript/langchain/messages#multimodal)。
</Note>

## 简化包（Simplified package）

`langchain` 包的命名空间已简化，重点关注 Agent 的构建块。遗留功能已移至 `@langchain/classic`。新包仅暴露最有用的相关功能。

### 导出项

v1 包包含：

| 模块 | 可用内容 | 备注 |
|--------|------------------|-------|
| Agents | `createAgent`, `AgentState` | 核心 Agent 创建功能 |
| Messages | 消息类型，内容块，`trimMessages` | 从 `@langchain/core` 中重新导出 |
| Tools | `tool`，工具类 | 从 `@langchain/core` 中重新导出 |
| 聊天模型 | `initChatModel`, `BaseChatModel` | 统一的模型初始化 |

### `@langchain/classic`

如果你使用遗留的链（chains）、索引 API，或之前从 `@langchain/community` 重新导出的功能，请安装 `@langchain/classic` 并更新导入路径：

<CodeGroup>
```bash npm
npm install @langchain/classic
```
```bash pnpm
pnpm install @langchain/classic
```
```bash yarn
yarn add @langchain/classic
```

</CodeGroup>

## 破坏性变更（Breaking changes）

### 删除了对 Node 18 的支持

所有 LangChain 包现在要求 **Node.js 20 或更高版本**。Node.js 18 已于 2025 年 3 月达到[生命周期结束](https://nodejs.org/en/about/releases/)。

### 新的构建输出

所有 langchain 包的构建现在使用基于打包器（bundler）的方法，而不是使用原始的 TypeScript 输出。如果你之前是从 `dist/` 目录导入文件（不推荐的做法），则需要更新导入以使用新的模块系统。

### 遗留代码已移至 `@langchain/classic`

位于标准接口和 Agent 关注点之外的遗留功能已移至 [`@langchain/classic`](https://www.npmjs.com/package/@langchain/classic) 包。请参阅[简化包](#simplified-package)部分，了解核心 `langchain` 包中提供了哪些功能以及哪些内容已移至 `@langchain/classic`。

### 移除了已弃用的 API

已被标记为弃用并计划在 1.0 中删除的方法、函数和其他对象已被删除。

<Accordion title="查看已移除的弃用 API">

v1 中移除了以下弃用 API：

#### 核心功能
- `TraceGroup` - 请改用 LangSmith 跟踪
- `BaseDocumentLoader.loadAndSplit` - 请先调用 `.load()`，然后使用文本分割器
- `RemoteRunnable` - 不再支持

#### 提示词
