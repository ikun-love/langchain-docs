[Apache Cassandra®](https://cassandra.apache.org/_/index.html) 是一个面向行、高度可扩展且高可用的 NoSQL 数据库。

Apache Cassandra 的[最新版本](<https://cwiki.apache.org/confluence/display/CASSANDRA/CEP-30%3A+Approximate+Nearest+Neighbor(ANN)+Vector+Search+via+Storage-Attached+Indexes>) 原生支持向量相似性搜索（Vector Similarity Search）。

## 设置

首先，安装 Cassandra Node.js 驱动程序：

<Tip>
有关安装 LangChain 包的常规说明，请参阅[本节](/oss/javascript/langchain/install)。
</Tip>

```bash npm
npm install cassandra-driver @langchain/community @langchain/openai @langchain/core
```
具体如何连接到数据库将取决于您使用的数据库提供商。我们将创建一个名为 `configConnection` 的文档，它将用作向量存储配置的一部分。

### Apache Cassandra®

Vector search（向量搜索）在 [Apache Cassandra® 5.0](https://cassandra.apache.org/_/Apache-Cassandra-5.0-Moving-Toward-an-AI-Driven-Future.html) 及更高版本中受支持。您可以使用标准的连接文档，例如：

```typescript
const configConnection = {
  contactPoints: ['h1', 'h2'],
  localDataCenter: 'datacenter1',
  credentials: {
    username: <...> as string,
    password: <...> as string,
  },
};
```
### Astra DB

Astra DB 是一个云原生的 Cassandra-as-a-Service 平台。

1. 创建一个 [Astra DB 账户](https://astra.datastax.com/register)。
2. 创建一个[支持向量的数据库](https://astra.datastax.com/createDatabase)。
3. 为您的数据库创建一个[令牌](https://docs.datastax.com/en/astra/docs/manage-application-tokens.html)。

```typescript
const configConnection = {
  serviceProviderArgs: {
    astra: {
      token: <...> as string,
      endpoint: <...> as string,
    },
  },
};
```
您可以使用 `datacenterID:` 属性和可选的 `regionName:` 属性来替代 `endpoint:` 属性。

## 索引文档

```typescript
import { CassandraStore } from "@langchain/classic/vectorstores/cassandra";
import { OpenAIEmbeddings } from "@langchain/openai";

// configConnection 文档在上面定义
const config = {
  ...configConnection,
  keyspace: "test",
  dimensions: 1536,
  table: "test",
  indices: [{ name: "name", value: "(name)" }],
  primaryKey: {
    name: "id",
    type: "int",
  },
  metadataColumns: [
    {
      name: "name",
      type: "text",
    },
  ],
};

const vectorStore = await CassandraStore.fromTexts(
  ["I am blue", "Green yellow purple", "Hello there hello"],
  [
    { id: 2, name: "2" },
    { id: 1, name: "1" },
    { id: 3, name: "3" },
  ],
  new OpenAIEmbeddings(),
  cassandraConfig
);
```
## 查询文档

```typescript
const results = await vectorStore.similaritySearch("Green yellow purple", 1);
```
或者进行过滤查询：

```typescript
const results = await vectorStore.similaritySearch("B", 1, { name: "Bubba" });
```
## 向量类型

Cassandra 支持 `cosine`（默认值）、`dot_product` 和 `euclidean` 相似性搜索；这在向量存储首次创建时定义，并在构造函数参数 `vectorType` 中指定，例如：

```typescript
  ...,
  vectorType: "dot_product",
  ...
```
## 索引（Indices）

随着 5.0 版本的发布，Cassandra 引入了存储附加索引（Storage Attached Indexes, SAI）。这些索引允许在不指定分区键（partition key）的情况下进行 `WHERE` 过滤，并支持额外的操作符（如不等式）。您可以使用 `indices` 参数定义这些索引，该参数接受零个或多个字典，每个字典包含 `name` 和 `value` 条目。

索引是可选的，但如果对非分区列使用过滤查询则是必需的。

- `name` 条目是对象名称的一部分；对于名为 `test_table` 的表，名为 `some_column` 的索引将是 `idx_test_table_some_column`。
- `value` 条目是创建索引的列，用 `(` 和 `)` 包围。对于上述列 `some_column`，它将指定为 `value: "(some_column)"`。
- 可选的 `options` 条目是一个传递给 `CREATE CUSTOM INDEX` 语句的 `WITH OPTIONS =` 子句的映射。具体的条目取决于索引类型。

```typescript
  indices: [{ name: "some_column", value: "(some_column)" }],
```
## 高级过滤

默认情况下，过滤器使用等号 `=` 进行应用。对于具有 `indices` 条目的字段，您可以提供一个 `operator` 字符串（使用索引支持的值）；在这种情况下，您需要指定一个或多个过滤器，可以是单个值或列表（它们将被 `AND` 组合起来）。例如：

```typescript
   { name: "create_datetime", operator: ">", value: some_datetime_variable }
```
或者

```typescript
[
  { userid: userid_variable },
  { name: "create_datetime", operator: ">", value: some_date_variable },
];
```
`value` 可以是单个值或一个数组。如果它不是数组，或者 `value` 中只有一个元素，则生成的查询类似于 `${name} ${operator} ?`，其中 `value` 绑定到 `?`。

如果 `value` 数组中有多个元素，将计算 `name` 中无引号的 `?` 数量，并从 `value` 的长度中减去该数量，最后将计算出的 `?` 数量放在运算符的右侧；如果有多个 `?`，它们将被封装在 `(` 和 `)` 中，例如 `(?, ?, ?)`。

这有助于在运算符左侧绑定值，这对于某些函数很有用；例如，一个地理距离过滤器：

```typescript
{
  name: "GEO_DISTANCE(coord, ?)",
  operator: "<",
  value: [new Float32Array([53.3730617,-6.3000515]), 10000],
},
```
## 数据分区和复合键

在某些系统中，您可能希望出于各种原因对数据进行分区，或许是按用户或按会话。Cassandra 中的数据总是会被分区；默认情况下，此库将按第一个主键字段进行分区。您可以指定构成记录主（唯一）键的多个列，并可选地指示应成为分区键的字段。例如，向量存储可以同时按 `userid` 和 `collectionid` 分区，额外的字段 `docid` 和 `docpart` 使单个条目唯一：

```typescript
  ...,
  primaryKey: [
    {name: "userid", type: "text", partition: true},
    {name: "collectionid", type: "text", partition: true},
    {name: "docid", type: "text"},
    {name: "docpart", type: "int"},
  ],
  ...
```
在搜索时，您可以在不为这些列定义 `indices` 的情况下将分区键包含在过滤器中；您不需要指定所有分区键，但必须首先指定键中包含的分区键。在上面的示例中，您可以指定一个过滤器 `{userid: userid_variable}` 和 `{userid: userid_variable, collectionid: collectionid_variable}`，但是如果您只想指定一个过滤器 `{collectionid: collectionid_variable}`，那么您必须将 `collectionid` 包含在 `indices` 列表中。

## 附加配置选项

在配置文档中，提供了进一步的可选参数；它们的默认值如下：

```typescript
  ...,
  maxConcurrency: 25,
  batchSize: 1,
  withClause: "",
  ...
```

| 参数 | 用途 |
| :--- | :--- |
| `maxConcurrency` | 在给定时间内发送到 Cassandra 的并发请求数量。 |
| `batchSize` | 单个请求发送到 Cassandra 的文档数量。当使用大于 1 的值时，您应确保批次大小不会超过 Cassandra 参数 `batch_size_fail_threshold_in_kb`。批次是未记录的（unlogged）。 |
| `withClause` | Cassandra 表可以用可选的 `WITH` 子句创建；这通常不是必需的，但为完整性而提供。 |
