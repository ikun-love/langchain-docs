```md
**集成是 LangChain 的核心组件。**

LangChain 为构建 LLM 应用所需的几种不同组件（如语言模型、向量存储等）提供了标准接口。贡献一个集成有助于扩展 LangChain 的生态系统，并让您的服务被数百万开发者发现。

## 为什么向 LangChain 贡献集成？

<Card title="可发现性" icon="magnifying-glass">
    LangChain 是构建 LLM 应用最常使用的框架，每月下载量超过 2000 万次。
</Card>

<Card title="互操作性" icon="arrows-rotate">
    LangChain 组件会暴露一个标准的接口，使开发者可以轻松地将它们互相替换。如果您实现了一个 LangChain 集成，任何使用其他组件的开发者都可以轻松地将您的替换进来。
</Card>

<Card title="最佳实践" icon="star">
    通过其标准接口，LangChain 组件能够鼓励并促进最佳实践（如流式传输、异步操作等），从而提升开发者的体验和应用的性能。
</Card>

## 需要集成的组件类型

虽然任何组件都可以集成到 LangChain 中，但我们更鼓励以下特定类型的集成：

**请集成这些 ✅**:
- [**聊天模型 (Chat Models)**](/oss/javascript/integrations/chat): 使用最频繁的组件类型
- [**工具/工具包 (Tools/Toolkits)**](/oss/javascript/integrations/tools): 启用 Agent 能力
- [**检索器 (Retrievers)**](/oss/javascript/integrations/retrievers): RAG 应用的核心
- [**文本嵌入模型 (Embedding Models)**](/oss/javascript/integrations/text_embedding): 向量操作的基础
- [**向量存储 (Vector Stores)**](/oss/javascript/integrations/vectorstores): 语义搜索的关键

**请勿集成这些 ❌**:
- **LLM（文本补全模型）**: 已弃用，推荐使用 [聊天模型 (Chat Models)](/oss/javascript/integrations/chat) 替代
- [**文档加载器 (Document Loaders)**](/oss/javascript/integrations/document_loaders): 维护负担重
- [**键值存储 (Key-Value Stores)**](/oss/javascript/integrations/stores): 用途有限
- **文档转换器 (Document Transformers)**: 用例较少
- **模型缓存 (Model Caches)**: 属于基础设施范畴
- **图 (Graphs)**: 复杂的抽象层
- **消息历史 (Message Histories)**: 存储抽象
- **回调 (Callbacks)**: 系统级组件
- **聊天加载器 (Chat Loaders)**: 需求有限
- **适配器 (Adapters)**: 边缘情况工具

## 如何贡献一个集成

<Steps>
    <Step title="确认资格">
        验证您的集成是否在我们当前接受的 [鼓励组件列表](#components-to-integrate) 中。
    </Step>

    <Step title="实现您的包">
        <Card title="如何实现一个 LangChain 集成" icon="link" href="/oss/javascript/contributing/implement-langchain" arrow />
    </Step>

    <Step title="通过标准测试">
        如果适用，请实现对 LangChain [标准测试套件 (standard test suite)](/oss/javascript/contributing/standard-tests-langchain) 的支持，并成功运行它们。
    </Step>

    <Step title="发布集成">
        <Card title="如何发布集成" icon="upload" href="/oss/javascript/contributing/publish-langchain" arrow />
    </Step>

    <Step title="添加文档">
        打开一个 PR (Pull Request)，将您集成的文档添加到官方 LangChain 文档中。

        <Accordion title="集成文档指南" icon="book">
            一个集成的重要性与其文档的完善程度是成正比的。为确保用户体验的一致性，所有新的集成都需要文档。我们为每种集成类型提供了一个标准的起始点模板供您复制和修改。

            在 LangChain [文档仓库 (docs repo)](https://github.com/langchain-ai/docs) 中一个新的 PR 中，使用适当的模板文件，在 `src/oss/python/integrations/<component_type>/` 目录下创建一个新文件，命名为 `integration_name.mdx`：

            - [聊天模型](https://github.com/langchain-ai/docs/blob/main/src/oss/python/integrations/chat/TEMPLATE.mdx)
            - [工具和工具包](https://github.com/langchain-ai/docs/blob/main/src/oss/python/integrations/tools/TEMPLATE.mdx)
            - [检索器](https://github.com/langchain-ai/docs/blob/main/src/oss/python/integrations/retrievers/TEMPLATE.mdx)
            - 文档分割器 - 即将推出
            - 嵌入模型 - 即将推出
            - [向量存储](https://github.com/langchain-ai/docs/blob/main/src/oss/python/integrations/vectorstores/TEMPLATE.mdx)
            - 文档加载器 - 即将推出
            - 键值存储 - 即将推出

            对于参考文档（Reference Docs），请在对应仓库中打开一个 Issue，以便维护者可以添加。
        </Accordion>
    </Step>

    <Step title="联合营销" icon="megaphone">
        （可选）与 LangChain 团队合作进行联合 [联合营销 (co-marketing)](/oss/javascript/contributing/comarketing)。
    </Step>
</Steps>
```
