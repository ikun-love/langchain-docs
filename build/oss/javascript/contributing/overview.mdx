**欢迎！感谢您对贡献的兴趣。**

LangChain 已经帮助形成了生成式 AI 领域最大的开发者社区，我们一直欢迎新的贡献者。无论您是修复 Bug、添加新特性、改进文档，还是分享反馈，您的参与都将帮助 LangChain 和 LangGraph 为每个人变得更好 🦜❤️

## 贡献方式

<AccordionGroup>
    <Accordion title="报告 Bug" icon="bug">
        发现 Bug 了吗？请通过遵循以下步骤帮助我们修复它：

        <Steps>
            <Step title="搜索">
                请检查对应仓库的 GitHub Issues 中是否已存在该问题：


                <Columns cols={2}>
                    <Card title="LangChain" icon="link" href="https://github.com/langchain-ai/langchainjs/issues">Issues</Card>
                    <Card title="LangGraph" icon="circle-nodes" href="https://github.com/langchain-ai/langgraphjs/issues">Issues</Card>
                </Columns>

            </Step>
            <Step title="创建 Issue">
                如果尚未存在该 Issue，请创建一个新的 Issue。在撰写时，请务必遵循提供的模板，并附上一个[最小、可重现的示例](https://stackoverflow.com/help/minimal-reproducible-example)。 Issue 创建完成后，请附加任何相关的标签。如果项目维护者无法重现您的问题，则该问题可能无法及时得到解决。
            </Step>
            <Step title="等待">
                项目维护者将对 Issue 进行分类，并可能要求提供更多信息。请耐心等待，因为我们需要处理大量的 Issue。除非您有新的信息可以提供，否则请勿“顶帖”（bump）该 Issue。
            </Step>
        </Steps>

        如果您要添加一个 Issue，请尽量保持其只关注一个主题。如果两个 Issue 相关或互相阻塞，请[将它们链接起来](https://docs.github.com/en/issues/tracking-your-work-with-issues/linking-a-pull-request-to-an-issue#linking-a-pull-request-to-an-issue-using-a-keyword)，而不是将它们合并。例如：

        ```text
        This issue is blocked by #123 and related to #456.
        ```
    </Accordion>

            <Step title="搜索">

                <Columns cols={2}>

            </Step>
            <Step title="描述">
                请务必描述用例以及它对其他人的价值。如果可能，请在适用情况下提供示例或原型图。并概述应该通过的测试用例。
            </Step>
        </Steps>

## LLM 的可接受用途

生成式 AI 可以作为贡献者的有用工具，但像任何工具一样，它应该被有批判性思维和良好判断力地使用。

当我们遇到贡献者（代码更改、文档更新、Pull Request 描述）的**全部工作**都是由 LLM 生成时，我们会感到头疼。这些“临时性”的贡献往往是出于好意，但在上下文相关性、准确性和质量方面常常不符合要求。

我们将关闭那些没有建设性的 Pull Request 和 Issue，以便我们将维护者的精力集中在其他地方。
