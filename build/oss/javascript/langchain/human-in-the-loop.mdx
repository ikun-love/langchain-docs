---
title: 人在回路 (Human-in-the-Loop, HITL)
---

`Human-in-the-Loop (HITL)` [中间件](/oss/javascript/langchain/middleware/built-in#human-in-the-loop) 允许您为代理的工具调用添加人工审查环节。
当模型提议执行一个可能需要审查的操作时——例如写入文件或执行 SQL——该中间件可以暂停执行，等待用户的决策。

它是通过将每个工具调用与一个可配置的策略进行检查来实现的。如果需要干预，中间件会触发一个 [interrupt](https://reference.langchain.com/javascript/functions/_langchain_langgraph.index.interrupt.html)（中断）来停止执行。图的状态会使用 LangGraph 的 [持久化层](/oss/javascript/langgraph/persistence) 进行保存，因此执行可以安全地暂停，并在稍后恢复。

接下来发生的事情取决于人工的决策：操作可以按原样批准（`approve`）、在运行前修改（`edit`）或附带反馈被拒绝（`reject`）。

## 中断决策类型

[中间件](/oss/javascript/langchain/middleware/built-in#human-in-the-loop) 定义了三种内置的人工响应中断的方式：

| 决策类型 | 描述 | 示例用法 |
|---|---|---|
| ✅ `approve` | 操作按原样批准并执行，不作任何更改。 | 原样发送撰写好的电子邮件草稿 |
| ✏️ `edit` | 工具调用在修改后执行。 | 发送电子邮件前更改收件人 |
| ❌ `reject` | 工具调用被拒绝，并在对话中添加解释。 | 拒绝电子邮件草稿并解释应如何重写 |

每种工具可用的决策类型取决于您在 `interrupt_on` 中配置的策略。
当多个工具调用同时暂停时，每个操作都需要单独的决策。
决策的提供顺序必须与中断请求中操作的出现顺序一致。

<Tip>
在**编辑**工具参数时，请谨慎操作。对原始参数进行重大修改可能会导致模型重新评估其方法，并可能导致工具被执行多次或采取意外操作。
</Tip>


## 配置中断

要使用 HITL，在创建代理时将 [中间件](/oss/javascript/langchain/middleware/built-in#human-in-the-loop) 添加到代理的 `middleware` 列表中。

您需要通过一个映射来配置它，该映射将工具操作与允许的决策类型相关联。当工具调用与映射中的操作匹配时，中间件将中断执行。



```ts
import { createAgent, humanInTheLoopMiddleware } from "langchain"; // [!code highlight]
import { MemorySaver } from "@langchain/langgraph"; // [!code highlight]

const agent = createAgent({
    model: "gpt-4o",
    tools: [writeFileTool, executeSQLTool, readDataTool],
    middleware: [
        humanInTheLoopMiddleware({
            interruptOn: {
                write_file: true, // 允许所有决策（批准、编辑、拒绝）
                execute_sql: {
                    allowedDecisions: ["approve", "reject"],
                    // 不允许编辑
                    description: "🚨 SQL execution requires DBA approval",
                },
                // 安全操作，无需批准
                read_data: false,
            },
            // 中断消息的前缀 —— 与工具名称和参数组合形成完整消息
            // 例如："Tool execution pending approval: execute_sql with query='DELETE FROM...'"
            // 单个工具可以通过在其中断配置中指定 "description" 来覆盖此项
            descriptionPrefix: "Tool execution pending approval",
        }),
    ],
    // 人在回路需要检查点机制来处理中断。
    // 在生产环境中，请使用持久化的检查点，例如 AsyncPostgresSaver。
    checkpointer: new MemorySaver(), // [!code highlight]
});
```



<Info>
    您必须配置一个检查点 (checkpointer) 来跨中断持久化图状态。
    在生产环境中，请使用持久化的检查点，例如 [`AsyncPostgresSaver`](https://reference.langchain.com/javascript/classes/_langchain_langgraph-checkpoint-postgres.AsyncPostgresSaver.html)。对于测试或原型设计，请使用 [`InMemorySaver`](https://reference.langchain.com/javascript/classes/_langchain_langgraph-checkpoint.MemorySaver.html)。

    调用代理时，请传递包含 **线程 ID** 的 `config`，以便将执行与会话线程关联起来。
    有关详细信息，请参阅 [LangGraph 中断文档](/oss/javascript/langgraph/interrupts)。
</Info>

<Accordion title="配置选项">



<ParamField body="interruptOn" type="object" required>
    工具名称到批准配置的映射
</ParamField>

**工具批准配置选项:**

<ParamField body="allowAccept" type="boolean" default="false">
    是否允许批准
</ParamField>

<ParamField body="allowEdit" type="boolean" default="false">
    是否允许编辑
</ParamField>

<ParamField body="allowRespond" type="boolean" default="false">
    是否允许响应/拒绝
</ParamField>


</Accordion>

## 响应中断

当您调用代理时，它会运行直到完成或触发中断。当中断触发时，工具调用匹配了您在 `interrupt_on` 中配置的策略。在这种情况下，调用结果将包含一个带有所需审查操作的 `__interrupt__` 字段。然后，您可以向审查员展示这些操作，并在提供决策后恢复执行。




```typescript
import { HumanMessage } from "@langchain/core/messages";
import { Command } from "@langchain/langgraph";

// 您必须提供一个 thread ID 以将执行与会话线程关联起来，
// 这样会话才能暂停和恢复（如人工审查所需）。
const config = { configurable: { thread_id: "some_id" } }; // [!code highlight]

// 运行图直到命中中断。
const result = await agent.invoke(
    {
        messages: [new HumanMessage("Delete old records from the database")],
    },
    config // [!code highlight]
);


// 中断包含完整的 HITL 请求，其中有 action_requests (操作请求) 和 review_configs (审查配置)
console.log(result.__interrupt__);
// > [
// >    Interrupt(
// >       value: {
// >          action_requests: [
// >             {
// >                name: 'execute_sql',
// >                arguments: { query: 'DELETE FROM records WHERE created_at < NOW() - INTERVAL \'30 days\';' },
// >                description: 'Tool execution pending approval\n\nTool: execute_sql\nArgs: {...}'
// >             }
// >          ],
// >          review_configs: [
// >             {
// >                action_name: 'execute_sql',
// >                allowed_decisions: ['approve', 'reject']
// >             }
// >          ]
// >       }
// >    )
// > ]

// 使用批准决策恢复
await agent.invoke(
    new Command({ // [!code highlight]
        resume: { decisions: [{ type: "approve" }] }, // 或 "reject" [!code highlight]
    }), // [!code highlight]
    config // 使用相同的 thread ID 恢复暂停的会话
);
```


### 决策类型

<Tabs>
<Tab title="✅ approve">
使用 `approve` 按原样批准工具调用并执行，不做任何更改。



```typescript
await agent.invoke(
    new Command({
        // 决策以列表形式提供，每个待审查的操作一个决策。
        // 决策的顺序必须与 `__interrupt__` 请求中列出的操作顺序相匹配。
        resume: {
            decisions: [
                {
                    type: "approve",
                }
            ]
        }
    }),
    config  // 使用相同的 thread ID 恢复暂停的会话
);
```

</Tab>
<Tab title="✏️ edit">
    使用 `edit` 在执行前修改工具调用。
    提供带有新工具名称和参数的编辑后的操作。



    ```typescript
    await agent.invoke(
        new Command({
            // 决策以列表形式提供，每个待审查的操作一个决策。
            // 决策的顺序必须与 `__interrupt__` 请求中列出的操作顺序相匹配。
            resume: {
                decisions: [
                    {
                        type: "edit",
                        // 编辑后的操作，包含工具名称和参数
                        editedAction: {
                            // 要调用的工具名称。
                            // 通常会与原始操作相同。
                            name: "new_tool_name",
                            // 传递给工具的参数。
                            args: { key1: "new_value", key2: "original_value" },
                        }
                    }
                ]
            }
        }),
        config  // 使用相同的 thread ID 恢复暂停的会话
    );
    ```


    <Tip>
        在**编辑**工具参数时，请谨慎操作。对原始参数进行重大修改可能会导致模型重新评估其方法，并可能导致工具被执行多次或采取意外操作。
    </Tip>

</Tab>

<Tab title="❌ reject">
    使用 `reject` 拒绝工具调用，并提供反馈而不是执行。



    ```typescript
    await agent.invoke(
        new Command({
            // 决策以列表形式提供，每个待审查的操作一个决策。
            // 决策的顺序必须与 `__interrupt__` 请求中列出的操作顺序相匹配。
            resume: {
                decisions: [
                    {
                        type: "reject",
                        // 关于操作为何被拒绝的解释
                        message: "No, this is wrong because ..., instead do this ...",
                    }
                ]
            }
        }),
        config  // 使用相同的 thread ID 恢复暂停的会话
    );
    ```


`message` 会作为反馈添加到对话中，以帮助代理理解操作被拒绝的原因以及它应该采取什么替代措施。

---

### 多个决策

当有多个操作需要审查时，请按照它们在中断中出现的顺序为每个操作提供一个决策：



```typescript
{
    decisions: [
        { type: "approve" },
        {
            type: "edit",
            editedAction: {
                name: "tool_name",
                args: { param: "new_value" }
            }
        },
        {
            type: "reject",
            message: "This action is not allowed"
        }
    ]
}
```


</Tab>
</Tabs>


## 执行生命周期

中间件定义了一个 `after_model` 钩子，在模型生成响应后但在执行任何工具调用之前运行：

1. 代理调用模型以生成响应。
2. 中间件检查响应中是否存在工具调用。
3. 如果任何调用需要人工输入，中间件会构建一个包含 `action_requests` 和 `review_configs` 的 `HITLRequest` 并调用 [interrupt](https://reference.langchain.com/javascript/functions/_langchain_langgraph.index.interrupt.html)。
4. 代理等待人工决策。
5. 根据 `HITLResponse` 中的决策，中间件执行已批准或已编辑的调用，为被拒绝的调用合成 [ToolMessage](https://reference.langchain.com/javascript/classes/_langchain_core.messages.ToolMessage.html)，然后恢复执行。



## 自定义 HITL 逻辑

对于更专业的（specialized）工作流程，您可以通过直接使用 [interrupt](https://reference.langchain.com/javascript/functions/_langchain_langgraph.index.interrupt.html) 原语和 [中间件](/oss/javascript/langchain/middleware) 抽象来构建自定义的 HITL 逻辑。

请参阅上方的 [执行生命周期](#execution-lifecycle)，以了解如何将中断集成到代理的操作中。
