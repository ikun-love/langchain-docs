以大规模构建 Agent 会带来难以追踪的、基于使用量的非必要成本。LangSmith 会自动记录主要提供商的 LLM Token 使用情况和成本，同时也允许您为任何附加组件提交自定义成本数据。

这为您提供了跨整个应用程序的统一成本视图，便于监控、理解和调试支出情况。

## 在 LangSmith UI 中查看成本
在 [LangSmith UI](https://smith.langchain.com) 中，您可以通过三种主要方式来探索使用情况和支出：首先是了解 Token 和成本是如何分解的，然后在单个追踪（trace）中查看这些详细信息，最后是通过检查项目统计数据和仪表板中的聚合指标。

### Token 和成本分解
Token 使用量和成本被细分为三个类别：
- **Input (输入)**：发送给模型的 Prompt 中的 Token。子类型包括：缓存读取（cache reads）、文本 Token、图像 Token 等。
- **Output (输出)**：模型响应中生成的 Token。子类型包括：推理 Token（reasoning tokens）、文本 Token、图像 Token 等。
- **Other (其他)**：来自工具调用、检索步骤或任何自定义运行（run）的成本。

您可以通过将鼠标悬停在 UI 中的成本部分来查看详细的分解情况。在可用时，每个部分会进一步按子类型分类。

## 成本跟踪

您可以通过两种方式跟踪成本：

1. LLM 调用的成本可以**根据 Token 计数和模型价格自动推导**
2. LLM 调用或任何其他运行类型的成本可以**作为运行数据的一部分手动指定**

您使用的方法取决于您正在跟踪的内容以及模型的定价结构：


| 方法 | 运行类型: LLM | 运行类型: 其他 |
|--------|---------------|-----------------|
| **自动** | <ul><li>使用 [LangChain](/oss/python/langchain/overview) 调用 LLM</li><li>追踪到 OpenAI、Anthropic 或遵循 OpenAI 兼容格式的模型调用，并使用 `@traceable`</li><li>使用 LangSmith 包装器来处理 [OpenAI](/langsmith/trace-openai) 或 [Anthropic](/langsmith/trace-anthropic)</li><li>对于其他模型提供商，请阅读[Token 和成本信息指南](/langsmith/log-llm-trace#provide-token-and-cost-information)</li></ul> | 不适用。 |
| **手动** | 如果 LLM 调用的成本是非线性的（例如，遵循自定义成本函数） | 为任何运行类型发送成本，例如工具调用、检索步骤 |


### LLM 调用：根据 Token 计数自动跟踪成本

要根据 Token 使用量自动计算成本，您需要提供**Token 计数**、**模型和提供商**以及**模型价格**。

<Note>

如果您使用的模型提供商的响应与 OpenAI 或 Anthropic 的响应模式不同，请遵循以下说明。

**只有**当您**不满足**以下条件时，才需要执行这些步骤：
- 使用 [LangChain](/oss/python/langchain/overview) 调用 LLM
- 使用 `@traceable` 来追踪到 OpenAI、Anthropic 或遵循 OpenAI 兼容格式的模型调用
- 使用 LangSmith 包装器来处理 [OpenAI](/langsmith/trace-openai) 或 [Anthropic](/langsmith/trace-anthropic)。
</Note>

**1. 发送 Token 计数**

许多模型都在响应中包含了 Token 计数。您必须提取此信息，并通过以下方法之一将其包含在您的运行中：

<Accordion title="A. 在运行的元数据中设置 `usage_metadata` 字段">

在运行的元数据中设置 `usage_metadata` 字段。这种方法的优点是您无需更改被追踪函数的运行时输出。

<CodeGroup>

```python Python
from langsmith import traceable, get_current_run_tree

inputs = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "I'd like to book a table for two."},
]

@traceable(
    run_type="llm",
    metadata={"ls_provider": "my_provider", "ls_model_name": "my_model"}
)
def chat_model(messages: list):
    # 想象这是您的应用程序期望的真实模型输出格式
    assistant_message = {
        "role": "assistant",
        "content": "Sure, what time would you like to book the table for?"
    }

    # 您计算或从提供商处收到的 Token 使用量
    token_usage = {
        "input_tokens": 27,
        "output_tokens": 13,
        "total_tokens": 40,
        "input_token_details": {"cache_read": 10}
    }

    # 将 Token 使用量附加到 LangSmith 运行中
    run = get_current_run_tree()
    run.set(usage_metadata=token_usage)

    return assistant_message

chat_model(inputs)
```

```typescript TypeScript

const inputs = [
  { role: "system", content: "You are a helpful assistant." },
  { role: "user", content: "I'd like to book a table for two." },
];

const chatModel = traceable(
  async ({ messages }) => {
    // 您的应用程序期望的输出
    const assistantMessage = {
      role: "assistant",
      content: "Sure, what time would you like to book the table for?",
    };

    // 您计算或从提供商处收到的 Token 使用量
    const tokenUsage = {
      input_tokens: 27,
      output_tokens: 13,
      total_tokens: 40,

    const runTree = getCurrentRunTree();
    runTree.metadata.usage_metadata = tokenUsage;

    return assistantMessage;
  },
  {
    run_type: "llm",
    name: "chat_model",
    metadata: {
      ls_provider: "my_provider",
      ls_model_name: "my_model",
    },
  }
);

await chatModel({ messages: inputs });
```

在任一情况下，使用情况元数据应包含以下 LangSmith 识别字段的子集：

<Accordion title="使用情况元数据 Schema 和成本计算">

`usage_metadata` 字典中的以下字段被 LangSmith 识别。您可以直接查看完整的 [Python 类型](https://github.com/langchain-ai/langsmith-sdk/blob/e705fbd362be69dd70229f94bc09651ef8056a61/python/langsmith/schemas.py#L1196-L1227) 或 [TypeScript 接口](https://github.com/langchain-ai/langsmith-sdk/blob/e705fbd362be69dd70229f94bc09651ef8056a61/js/src/schemas.ts#L637-L689)。


<ParamField path="input_tokens" type="number">
模型输入中使用的 Token 数量。所有输入 Token 类型的总和。
</ParamField>

<ParamField path="output_tokens" type="number">
模型响应中使用的 Token 数量。所有输出 Token 类型的总和。
</ParamField>

<ParamField path="total_tokens" type="number">
输入和输出中使用的 Token 总数。可选，可以推断。 input_tokens + output_tokens 的总和。
</ParamField>

<ParamField path="input_token_details" type="object">
输入 Token 类型的分解。键是 Token 类型字符串，值是计数。例如 `{"cache_read": 5}`。

已知字段包括：`audio`（音频）、`text`（文本）、`image`（图像）、`cache_read`（缓存读取）、`cache_creation`（缓存创建）。根据模型或提供商，可能存在其他字段。
</ParamField>

<ParamField path="output_token_details" type="object">
输出 Token 类型的分解。键是 Token 类型字符串，值是计数。例如 `{"reasoning": 5}`。

已知字段包括：`audio`（音频）、`text`（文本）、`image`（图像）、`reasoning`（推理）。根据模型或提供商，可能存在其他字段。
</ParamField>

<ParamField path="input_cost" type="number">
输入 Token 的成本。
</ParamField>

<ParamField path="output_cost" type="number">
输出 Token 的成本。
</ParamField>

<ParamField path="total_cost" type="number">
Token 的总成本。可选，可以推断。 input_cost + output_cost 的总和。
</ParamField>

<ParamField path="input_cost_details" type="object">
输入成本的详细信息。键是 Token 类型字符串，值是成本金额。
</ParamField>

<ParamField path="output_cost_details" type="object">
输出成本的详细信息。键是 Token 类型字符串，值是成本金额。
</ParamField>

**成本计算**

一个运行的成本是根据 Token 类型的特异性从最具体到最不具体的顺序贪婪计算的。假设您为 1M 输入 Token 设置的价格是 $2，为 1M `cache_read` 输入 Token 设置的详细价格是 $1，为 1M 输出 Token 设置的价格是 $3。如果您上传了以下使用情况元数据：

```python
{
  "input_tokens": 20,
  "input_token_details": {"cache_read": 5},
  "output_tokens": 10,
  "total_tokens": 30,
}
```

那么 Token 成本将按如下方式计算：

```python
# 请注意，LangSmith 会计算 cache_read 的成本，然后对任何
# 剩余的 input_tokens 应用默认的输入价格。
input_cost = 5 * 1e-6 + (20 - 5) * 2e-6  # 3.5e-5
output_cost = 10 * 3e-6  # 3e-5
total_cost = input_cost + output_cost  # 6.5e-5
```

</Accordion>


**2. 指定模型名称**

在使用自定义模型时，需要在[运行的元数据](/langsmith/add-metadata-tags)中指定以下字段，以便将 Token 计数与成本相关联。提供这些元数据字段也有助于在查看追踪和筛选时识别模型。

- `ls_provider`: 模型的提供商，例如“openai”、“anthropic”。
- `ls_model_name`: 模型的名称，例如“gpt-4o-mini”、“claude-3-opus-20240229”。


**3. 设置模型价格**

模型定价映射（model pricing map）用于将模型名称映射到其逐 Token 价格，以便根据 Token 计数计算成本。LangSmith 的[模型定价表](https://smith.langchain.com/settings/workspaces/models)用于此目的。

<Note>
该表预设了大多数 OpenAI、Anthropic 和 Gemini 模型的定价信息。如果您有自定义定价，可以[为其他模型添加价格](/langsmith/cost-tracking#create-a-new-model-price-entry)，或[覆盖默认模型的定价](/langsmith/cost-tracking#update-an-existing-model-price-entry)。
</Note>

对于为不同 Token 类型（例如多模态或缓存 Token）具有不同定价的模型，您可以为每种 Token 类型指定价格明细。将鼠标悬停在输入/输出价格旁边的 `...` 上，即可查看按 Token 类型划分的价格明细。

    在这里，您可以指定以下字段：

    * **Model Name (模型名称)**：模型的可读名称。
    * **Input Price (输入价格)**：模型每 1M 输入 Token 的成本。该数字乘以 Prompt 中的 Token 数量以计算 Prompt 成本。
    * **Input Price Breakdown (输入价格明细)**（可选）：每种不同类型输入 Token 的价格细分，例如 `cache_read`、`video`（视频）、`audio`（音频）。
    * **Output Price (输出价格)**：模型每 1M 输出 Token 的成本。该数字乘以完成（completion）中的 Token 数量以计算完成成本。
    * **Output Price Breakdown (输出价格明细)**（可选）：每种不同类型输出 Token 的价格细分，例如 `reasoning`（推理）、`image`（图像）等。
    * **Model Activation Date (模型激活日期)**（可选）：定价适用的日期。只有该日期之后记录的运行才会应用此模型价格。
    * **Match Pattern (匹配模式)**：一个正则表达式，用于匹配模型名称。这用于匹配运行元数据中 `ls_model_name` 的值。
    * **Provider (提供商)**（可选）：模型的提供商。如果指定，这将与运行元数据中的 `ls_provider` 进行匹配。

    设置好模型定价映射后，LangSmith 将根据 LLM 调用中提供的 Token 计数自动计算和汇总追踪的基于 Token 的成本。
</Accordion>

### LLM 调用：直接发送成本

如果您的模型遵循非线性定价方案，我们建议在客户端计算成本，并将其作为 `usage_metadata` 发送给 LangSmith。

<Note>
Gemini 3 Pro Preview 和 Gemini 2.5 Pro 遵循具有阶梯式成本函数的定价方案。我们默认支持 Gemini 的此定价方案。对于任何具有非线性定价的其他模型，您需要遵循这些说明来计算成本。
</Note>


<CodeGroup>

```python Python
from langsmith import traceable, get_current_run_tree

inputs = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "I'd like to book a table for two."},
]

@traceable(
    run_type="llm",
    metadata={"ls_provider": "my_provider", "ls_model_name": "my_model"}
)
def chat_model(messages: list):
    llm_output = {
        "choices": [
            {
                "message": {
                    "role": "assistant",
                    "content": "Sure, what time would you like to book the table for?"
                }
            }
        ],
        "usage_metadata": {
            # 指定输入和输出的成本（以美元为单位）
            "input_cost": 1.1e-6,
            "input_cost_details": {"cache_read": 2.3e-7},
            "output_cost": 5.0e-6,
        },
    }
    run = get_current_run_tree()
    run.set(usage_metadata=llm_output["usage_metadata"])
    return llm_output["choices"][0]["message"]

chat_model(inputs)
```

### 其他运行：发送成本

您也可以为任何非 LLM 运行（如工具调用）发送成本信息。成本必须在运行 `usage_metadata` 下的 `total_cost` 字段中指定。

<Accordion title="A. 在运行的 `usage_metadata` 中设置 `total_cost` 字段">

在运行的 `usage_metadata` 中设置 `total_cost` 字段。这种方法的优点是您无需更改被追踪函数的运行时输出。

<CodeGroup>

```python Python
from langsmith import traceable, get_current_run_tree

# 示例工具：get_weather
@traceable(run_type="tool", name="get_weather")
def get_weather(city: str):
    # 您的工具逻辑在此处
    result = {
        "temperature_f": 68,
        "condition": "sunny",
        "city": city,
    }

    # 此工具调用的成本（按您喜欢的方式计算）
    tool_cost = 0.0015

    # 将使用情况元数据附加到 LangSmith 运行中
    run = get_current_run_tree()
    run.set(usage_metadata={"total_cost": tool_cost})

    # 仅返回实际的工具结果（不含使用信息）
    return result

tool_response = get_weather("San Francisco")
```

```typescript TypeScript
    };

    // 此工具调用的成本（按您喜欢的方式计算）
    const toolCost = 0.0015;

    // 将使用情况元数据附加到 LangSmith 运行中
    const runTree = getCurrentRunTree();
    runTree.metadata.usage_metadata = {
      total_cost: toolCost,
    };

    // 仅返回实际的工具结果（不含使用信息）
    return result;
  },
  {
    run_type: "tool",
    name: "get_weather",
  }
);

const toolResponse = await getWeather({ city: "San Francisco" });
```

```python Python
            "total_cost": 0.0015,   # <-- 此工具调用的成本

tool_response = get_weather("San Francisco")
```
