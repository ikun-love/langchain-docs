本指南将引导您解决在运行自托管版 LangSmith 实例时可能遇到的常见问题。

在运行 LangSmith 时，您可能会遇到意外的 500 错误、性能缓慢或其他问题。本指南将帮助您诊断和解决这些问题。

## 获取有用的信息

为了诊断和解决问题，您首先需要收集一些相关信息。以下部分将说明如何在 Kubernetes 或 Docker 环境中执行此操作，以及如何获取有用的浏览器信息。

通常，您需要分析的主要服务包括：

- `langsmith-backend`: 负责处理 CRUD API 请求、业务逻辑、来自前端和 SDK 的请求、用于摄取的跟踪准备工作以及 Hub API。
- `langsmith-platform-backend`: 负责身份验证、运行数据摄取以及其他高流量任务。
- `langsmith-queue`: 负责处理传入的跟踪和反馈、异步摄取和持久化到数据存储、数据完整性检查以及在数据库错误或连接问题期间的重试机制。

有关这些服务的更多详细信息，请参阅[架构概述](/langsmith/architectural-overview)。

#### Kubernetes

故障排除的第一步是收集有关您的 LangSmith 部署的重要调试信息。服务日志、Kubernetes 事件以及容器的资源利用率可以帮助查明问题的根本原因。

您可以运行我们的 [k8s 故障排除脚本](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/scripts/get_k8s_debugging_info.sh)，该脚本将拉取所有相关的 Kubernetes 信息并将其输出到一个文件夹中供调查。该脚本还会将此文件夹压缩成一个 zip 文件以便共享。以下是一个运行此脚本的示例，假设您的 LangSmith 部署是在一个名为 `langsmith` 的命名空间中启动的：

```bash
bash get_k8s_debugging_info.sh --namespace langsmith
```

然后，您可以检查生成的文件夹内容，查找任何相关的错误或信息。如果您希望 LangSmith 团队协助调试，请将此 zip 文件与团队共享。

#### Docker

如果在 Docker 上运行，您可以通过运行以下命令来检查部署日志：

```bash
docker compose logs >> logs.txt
```

#### 浏览器错误

如果您遇到的问题表现为浏览器错误，那么检查 HAR 文件也可能有所帮助，其中可能包含关键信息。要获取 HAR 文件，您可以遵循 [本指南](https://support.langchain.com/articles/9042697994-how-to-generate-a-har-file-for-troubleshooting)，其中解释了针对不同浏览器的简短操作流程。

然后，您可以使用 [Google 的 HAR 分析器](https://toolbox.googleapps.com/apps/har_analyzer/)进行调查。您也可以将 HAR 文件发送给 LangSmith 团队以协助调试。

## 常见问题

### *DB::Exception: Cannot reserve 1.00 MiB, not enough space: While executing WaitForAsyncInsert. (NOT\_ENOUGH\_SPACE)*

出现此错误是由于 ClickHouse 的磁盘空间已用尽。您需要增加 ClickHouse 可用的磁盘空间。

#### Kubernetes

在 Kubernetes 中，您需要增加 ClickHouse PVC 的大小。要实现此目的，您可以执行以下步骤：

1. 获取 PVC 的存储类：`kubectl get pvc data-langsmith-clickhouse-0 -n <namespace> -o jsonpath='{.spec.storageClassName}'`

2. 确保存储类配置了 `AllowVolumeExpansion: true`：`kubectl get sc <storage-class-name> -o jsonpath='{.allowVolumeExpansion}'`

   * 如果结果是 `false`，某些存储类可以更新以允许卷扩展。
   * 要更新存储类，您可以运行 `kubectl patch sc <storage-class-name> -p '{"allowVolumeExpansion": true}'`
   * 如果这失败了，您可能需要创建一个新的存储类，其中包含正确的设置。

3. 编辑您的 pvc 以设置新大小：`kubectl edit pvc data-langsmith-clickhouse-0 -n <namespace>` 或 `kubectl patch pvc data-langsmith-clickhouse-0 '{"spec":{"resources":{"requests":{"storage":"100Gi"}}}}' -n <namespace>`

4. 将 Helm Chart 中的 `langsmith_config.yaml` 更新为新大小（例如 `100 Gi`）

5. 删除 ClickHouse StatefulSet：`kubectl delete statefulset langsmith-clickhouse --cascade=orphan -n <namespace>`

6. 应用更新大小的 Helm Chart（您可以参考[此处](/langsmith/self-host-upgrades)的升级指南）

7. 此时您的 pvc 应该已经具有新大小。可以通过运行 `kubectl get pvc` 和 `kubectl exec langsmith-clickhouse-0 -- bash -c "df"` 来验证。

#### Docker

在 Docker 中，您需要增加 ClickHouse 卷的大小。要实现此目的，您可以执行以下步骤：

1. 停止 LangSmith 实例。`docker compose down`
2. 如果使用绑定挂载 (bind mount)，则需要增加挂载点的空间。
3. 如果使用 Docker `volume`，则需要为该卷/Docker 分配更多空间。

### *error: Dirty database version 'version'. Fix and force version*

出现此错误是由于 ClickHouse 数据库与我们的迁移状态不一致。您需要回滚到更早的数据库版本，然后重新运行升级/迁移过程。

#### Kubernetes

1. 将迁移强制回退到早期版本，其中 `version = dirty version - 1`。

```bash
kubectl exec -it deployments/langsmith-backend -- bash -c 'migrate -source "file://clickhouse/migrations" -database "clickhouse://$CLICKHOUSE_HOST:$CLICKHOUSE_NATIVE_PORT?username=$CLICKHOUSE_USER&password=$CLICKHOUSE_PASSWORD&database=$CLICKHOUSE_DB&x-multi-statement=true&x-migrations-table-engine=MergeTree&secure=$CLICKHOUSE_TLS" force <version>'
```

1. 重新运行您的升级/迁移。

#### Docker

1. 将迁移强制回退到早期版本，其中 `version = dirty version - 1`。

```bash
docker compose exec langchain-backend migrate -source "file://clickhouse/migrations" -database "clickhouse://$CLICKHOUSE_HOST:$CLICKHOUSE_NATIVE_PORT?username=$CLICKHOUSE_USER&password=$CLICKHOUSE_PASSWORD&database=$CLICKHOUSE_DB&x-multi-statement=true&x-migrations-table-engine=MergeTree&secure=$CLICKHOUSE_TLS" force <version>
```

1. 重新运行您的升级/迁移。

### *413 - Request Entity Too Large*

出现此错误是由于请求大小超过了允许的最大限制。您需要在 Nginx 配置中增加最大请求体大小。

#### Kubernetes

1. 编辑您的 `langsmith_config.yaml` 并增加 `frontend.maxBodySize` [值](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/values.yaml#L519)。配置可能如下所示：

```yaml
frontend:
  maxBodySize: "100M"
```

2. 将更改应用到集群。

### *Details: code: 497, message: default: Not enough privileges. To execute this query, it's necessary to have the grant CREATE ROW POLICY ON default.feedbacks\_rmt*

此错误表示您的用户没有在 ClickHouse 中创建行策略所需的必要权限。在部署 Docker 实例时，您需要将 `users.xml` 文件从 GitHub 仓库复制过来。这会在 `users.xml` 文件中添加 `<access_management>` 标签，从而允许用户创建行策略。下面是我们期望使用的默认 `users.xml` 文件。

```xml
<clickhouse>
    <users>
        <default>
            <access_management>1</access_management>
            <named_collection_control>1</named_collection_control>
            <show_named_collections>1</show_named_collections>
            <show_named_collections_secrets>1</show_named_collections_secrets>
            <profile>default</profile>
        </default>
    </users>
    <profiles>
        <default>
            <async_insert>1</async_insert>
            <async_insert_max_data_size>2000000</async_insert_max_data_size>
            <wait_for_async_insert>0</wait_for_async_insert>
            <parallel_view_processing>1</parallel_view_processing>
            <allow_simdjson>0</allow_simdjson>
            <lightweight_deletes_sync>0</lightweight_deletes_sync>
        </default>
    </profiles>
</clickhouse>
```

在某些环境中，您的挂载点可能不可被容器写入。在这种情况下，我们建议构建一个包含 `users.xml` 文件的自定义镜像。

示例 `Dockerfile`:

```dockerfile
FROM clickhouse/clickhouse-server:24.8
COPY ./users.xml /etc/clickhouse-server/users.d/users.xml
```

然后执行以下步骤：

1. 构建您的自定义镜像。

```bash
docker build -t <image-name> .
```

2. 更新您的 `docker-compose.yaml` 以使用自定义镜像。确保移除 `users.xml` 的挂载配置。

```yaml
langchain-clickhouse:
  image: <image-name>
```

3. 重新启动您的 LangSmith 实例。

```bash
docker compose down --volumes
docker compose up
```

### *在运行包含 AquaSec 的集群时 ClickHouse 无法启动*

在某些环境中，AquaSec 可能会阻止 ClickHouse 正确启动。这可能表现为 ClickHouse Pod 不发出任何日志，并且无法被标记为就绪状态。这通常是由于 AquaSec 设置了 `LD_PRELOAD` 环境变量，从而干扰了 ClickHouse 的运行。要解决此问题，您可以向 ClickHouse 部署添加以下环境变量：

#### Kubernetes

在 `langsmith_config.yaml`（或相应的配置文件）中，设置 `AQUA_SKIP_LD_PRELOAD` 环境变量：

```yaml
clickhouse:
  statefulSet:
    extraEnv:
      - name: AQUA_SKIP_LD_PRELOAD
        value: "true"
```

#### Docker

在 `docker-compose.yaml` 中，设置 `AQUA_SKIP_LD_PRELOAD` 环境变量：

```yaml
langchain-clickhouse:
  environment:
    - AQUA_SKIP_LD_PRELOAD=true
```
