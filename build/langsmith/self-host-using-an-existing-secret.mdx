title: 为您的安装使用现有 Secret（Kubernetes）

---

默认情况下，LangSmith 会配置多个 Kubernetes Secret，用于存储敏感信息，例如许可证密钥（license keys）、盐值（salts）和其他配置参数。但是，您可能希望使用已经在 Kubernetes 集群中创建（或通过某种 Secret Operator 预配）的现有 Secret。如果您希望以集中化的方式管理敏感信息，或者有特定的安全要求，这样做会很有帮助。

默认情况下，我们将为 LangSmith 的不同组件预配以下 Secret：

* `langsmith-secrets`: 此 Secret 包含许可证密钥和其他一些基本配置参数。您可以在 [此处](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/templates/secrets.yaml) 查看此 Secret 的模板。
* `langsmith-redis`: 此 Secret 包含 Redis 连接字符串（如果使用 Redis 集群，则是节点 URI）和密码。您可以在 [此处](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/templates/redis/secrets.yaml) 查看此 Secret 的模板。
* `langsmith-postgres`: 此 Secret 包含 Postgres 连接字符串和密码。您可以在 [此处](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/templates/postgres/secrets.yaml) 查看此 Secret 的模板。
* `langsmith-clickhouse`: 此 Secret 包含 ClickHouse 连接字符串和密码。您可以在 [此处](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/templates/clickhouse/secrets.yaml) 查看此 Secret 的模板。

## 要求

* 一个现有的 Kubernetes 集群
* 一种在集群中创建 Kubernetes Secret 的方法。这可以通过使用 `kubectl`、Helm Chart 或像 [Sealed Secrets](https://github.com/bitnami-labs/sealed-secrets) 这样的 Secret Operator 来完成。

## 参数

您需要创建自己的 Kubernetes Secret，使其结构符合 LangSmith Helm Chart 预配的 Secret 结构。

<Warning>
这些 Secret 的结构必须与 LangSmith Helm Chart 预配的 Secret 结构一致（请参阅上方的链接查看具体 Secret 的内容）。如果缺少任何必需的 Key，您的 LangSmith 实例可能无法正常工作。
</Warning>

一个示例 Secret 可能如下所示：

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: langsmith-existing-secrets
  namespace: langsmith
stringData:
  oauth_client_id: foo
  oauth_client_secret: foo
  oauth_issuer_url: foo
  langsmith_license_key: foo
  langgraph_cloud_license_key: foo
  api_key_salt: foo
  jwt_secret: foo
  initial_org_admin_password: foo
  blob_storage_access_key: foo
  blob_storage_access_key_secret: foo
  azure_storage_account_key: foo
  azure_storage_connection_string: foo
```

## 配置

在预配了这些 Secret 之后，您可以配置 LangSmith 实例，使其直接使用这些 Secret，从而避免通过明文形式传递 Secret 值。您可以通过修改 LangSmith Helm Chart 安装的 `langsmith_config.yaml` 文件来实现这一点。

```yaml
config:
  existingSecretName: "langsmith-secrets" # 包含许可证密钥和其他基本配置参数的 Secret 名称
redis:
  external:
    enabled: true # 如果设置为 true，则使用外部 Redis 实例。仅在使用外部 Redis 实例时才需要此 Secret
    existingSecretName: "langsmith-redis" # 包含 Redis 连接字符串和密码的 Secret 名称
postgres:
  external:
    enabled: true # 如果设置为 true，则使用外部 Postgres 实例。仅在使用外部 Postgres 实例时才需要此 Secret
    existingSecretName: "langsmith-postgres" # 包含 Postgres 连接字符串和密码的 Secret 名称
clickhouse:
  external:
    enabled: true # 如果设置为 true，则使用外部 ClickHouse 实例。仅在使用外部 ClickHouse 实例时才需要此 Secret
    existingSecretName: "langsmith-clickhouse" # 包含 ClickHouse 连接字符串和密码的 Secret 名称
```

配置完成后，您需要更新 LangSmith 的安装。您可以按照 [此处](/langsmith/self-host-upgrades) 的升级指南进行操作。如果所有配置正确，您的 LangSmith 实例现在应该可以通过 Ingress 访问了。您可以运行以下命令来检查 Secret 是否已正确使用：

```bash
kubectl describe deployment langsmith-backend | grep -i <secret-name>
```

您应该在输出中看到类似以下的内容：

```bash
POSTGRES_DATABASE_URI:                    <set to the key 'connection_url' in secret <your-secret-name>  Optional: false
CLICKHOUSE_DB:                            <set to the key 'clickhouse_db' in secret <your-secret-name>   Optional: false
```
