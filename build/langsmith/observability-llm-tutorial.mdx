在本教程中，我们将使用 OpenAI SDK 构建一个简单的 RAG（检索增强生成）应用程序。我们将从原型设计到生产的每个开发阶段为该应用添加可观测性。

<CodeGroup>

```python Python
from openai import OpenAI
openai_client = OpenAI()

# 这是我们将在 RAG 中使用的检索器 (retriever)
# 这里是模拟的，但它可以是我们想要的任何东西
def retriever(query: str):
    results = ["Harrison worked at Kensho"]
    return results

# 这是端到端的 RAG 链 (chain)。
# 它执行检索步骤，然后调用 OpenAI
def rag(question):
    docs = retriever(question)
    system_message = """Answer the users question using only the provided information below:
        {docs}""".format(docs="\n".join(docs))

    return openai_client.chat.completions.create(
        messages=[
            {"role": "system", "content": system_message},
            {"role": "user", "content": question},
        ],
        model="gpt-4o-mini",
    )
```

```typescript TypeScript
import { OpenAI } from "openai";
const openAIClient = new OpenAI();

// 这是我们将在 RAG 中使用的检索器 (retriever)
// 这里是模拟的，但它可以是我们想要的任何东西
async function retriever(query: string) {
  return ["This is a document"];
}

// 这是端到端的 RAG 链 (chain)。
// 它执行检索步骤，然后调用 OpenAI
async function rag(question: string) {
  const docs = await retriever(question);

  const systemMessage =
    "Answer the users question using only the provided information below:\n\n" +
    docs.join("\n");

  return await openAIClient.chat.completions.create({
    messages: [
      { role: "system", content: systemMessage },
      { role: "user", content: question },
    ],
    model: "gpt-4o-mini",
  });
}
```

</CodeGroup>

## 原型设计 (Prototyping)

从一开始就设置好可观测性可以帮助你比以往任何时候都**快得多**地迭代。它能在你快速迭代提示词 (prompt) 或更改使用的数据和模型时，让你对应用程序有很好的可见性。在本节中，我们将介绍如何设置可观测性，以便在原型设计过程中获得最大的可见性。

### 设置环境

首先，通过访问 [设置页面](https://smith.langchain.com/settings) 创建一个 API 密钥。

接下来，安装 LangSmith SDK：

<CodeGroup>

```bash Python SDK
pip install langsmith
```

```bash TypeScript SDK
npm install langsmith
```

</CodeGroup>

最后，设置相应的环境变量。这将把跟踪日志记录到 `default` 项目中（尽管你可以轻松更改它）。

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY=<your-api-key>
export LANGSMITH_WORKSPACE_ID=<your-workspace-id>
export LANGSMITH_PROJECT=default
```

<Note>
在其他地方，你可能会看到这些变量被引用为 `LANGCHAIN_*`。它们都是等效的，但最佳实践是使用 `LANGSMITH_TRACING`、`LANGSMITH_API_KEY`、`LANGSMITH_PROJECT`。

`LANGSMITH_PROJECT` 标志仅在 JS SDK 版本 >= 0.2.16 中受支持，如果你使用的是旧版本，请改用 `LANGCHAIN_PROJECT`。
</Note>

### 跟踪你的 LLM 调用

你最想跟踪的第一件事是所有 OpenAI 调用。毕竟，这是实际调用 LLM 的地方，因此它是最重要的部分！我们通过引入一个极其简单的 OpenAI 包装器，使 LangSmith 尽可能容易地实现这一点。你所需要做的就是修改代码，使其看起来像这样：

<CodeGroup>

```python Python

openai_client = wrap_openai(OpenAI())

# 这是我们将在 RAG 中使用的检索器
```

### 跟踪整个链

很好——我们已经跟踪了 LLM 调用。但通常能跟踪更多内容会提供很有价值的信息。LangSmith 是**为**跟踪整个 LLM 管道而构建的——所以我们来做这件事吧！我们可以通过修改代码来实现这一点，使其现在看起来像这样：

<CodeGroup>

```python Python
from openai import OpenAI
from langsmith import traceable
from langsmith.wrappers import wrap_openai
openai_client = wrap_openai(OpenAI())

def retriever(query: str):
    results = ["Harrison worked at Kensho"]
    return results

@traceable
def rag(question):
    docs = retriever(question)
    system_message = """Answer the users question using only the provided information below:
        {docs}""".format(docs="\n".join(docs))

    return openai_client.chat.completions.create(
        messages=[
            {"role": "system", "content": system_message},
            {"role": "user", "content": question},
        ],
        model="gpt-4o-mini",
    )
```

```typescript TypeScript
import { OpenAI } from "openai";
import { traceable } from "langsmith/traceable";
import { wrapOpenAI } from "langsmith/wrappers";
const openAIClient = wrapOpenAI(new OpenAI());

async function retriever(query: string) {
  return ["This is a document"];
}

const rag = traceable(async function rag(question: string) {
  const docs = await retriever(question);

  const systemMessage =
    "Answer the users question using only the provided information below:\n\n" +
    docs.join("\n");

  return await openAIClient.chat.completions.create({
    messages: [
      { role: "system", content: systemMessage },
      { role: "user", content: question },
    ],
    model: "gpt-4o-mini",
  });
});
```

</CodeGroup>

注意我们如何导入 `from langsmith import traceable` 并使用它来装饰整个函数（`@traceable`）。

如果你以以下方式调用它会发生什么？

```python
rag("where did harrison work")
```

这将生成整个 RAG 管道的跟踪记录——它看起来应该像[这样](https://smith.langchain.com/public/8cafba6a-1a6d-4a73-8565-483186f31c29/r)

![](/langsmith/images/tracing-tutorial-chain.png)

## Beta 测试 (Beta Testing)

LLM 应用程序开发的下一阶段是 Beta 测试你的应用程序。这是将应用发布给最初的几批用户时。此时设置良好的可观测性至关重要，因为用户实际使用你的应用程序的方式往往是你无法完全预知的，所以可观测性可以让你获得关于他们如何使用的见解。这也意味着你可能需要对现有的跟踪设置进行一些更改，以更好地支持这一点。这扩展了你在上一节中设置的可观测性。

### 收集反馈

在 Beta 测试期间拥有良好的可观测性的重要组成部分是收集反馈。收集什么反馈通常取决于应用程序的具体情况——但至少，简单的点赞/点踩是一个好的开始。在记录了该反馈之后，你需要能够轻松地将其与导致该反馈的运行 (run) 相关联。幸运的是，LangSmith 使之变得容易。

首先，你需要从应用中记录反馈。一种简单的方法是跟踪每次运行的运行 ID (`run ID`)，然后使用该 ID 来记录反馈。跟踪运行 ID 的操作看起来像这样：

```python
from langsmith import uuid7

run_id = str(uuid7())
rag(
    "where did harrison work",
    langsmith_extra={"run_id": run_id}
)
```

将反馈与该运行关联起来的操作看起来像这样：

```python
from langsmith import Client
ls_client = Client()
ls_client.create_feedback(
    run_id,
    key="user-score",
    score=1.0,
)
```

一旦记录了反馈，你就可以在检查运行记录时，通过点击 `Metadata`（元数据）选项卡将其与每个运行关联起来。它看起来应该像[这样](https://smith.langchain.com/public/8cafba6a-1a6d-4a73-8565-483186f31c29/r)

![](/langsmith/images/tracing-tutorial-feedback.png)

你还可以通过使用运行表中的过滤逻辑，查询所有带有正面（或负面）反馈的运行记录。你可以通过创建如下过滤器来实现这一点：

### 记录元数据 (Logging Metadata)

开始记录元数据也是个好主意。这可以让你开始跟踪应用的各种属性。这对于了解是哪个版本的应用或哪个变体 (variant) 产生了给定的结果非常重要。

对于这个例子，我们将记录所使用的 LLM。你通常会尝试不同的 LLM，因此将该信息作为元数据保留下来，对于过滤非常有用。为了做到这一点，我们可以这样添加它：

```python
from openai import OpenAI
from langsmith import traceable
from langsmith.wrappers import wrap_openai
openai_client = wrap_openai(OpenAI())

@traceable(run_type="retriever")
def retriever(query: str):
    results = ["Harrison worked at Kensho"]
    return results

@traceable(metadata={"llm": "gpt-4o-mini"})
def rag(question):
    docs = retriever(question)
    system_message = """Answer the users question using only the provided information below:
    {docs}""".format(docs='\n'.join(docs))
    return openai_client.chat.completions.create(messages = [
        {"role": "system", "content": system_message},
        {"role": "user", "content": question},
    ], model="gpt-4o-mini")
```

注意我们为 `rag` 函数添加了 `@traceable(metadata={"llm": "gpt-4o-mini"})`。

以这种方式跟踪元数据，假设这些信息是预先知道的。对于 LLM 类型来说这没问题，但对于其他类型的信息（如 `User ID`）来说就不那么理想了。为了记录这类信息，我们可以使用运行 ID 在运行时传递它。

```python
from langsmith import uuid7

run_id = str(uuid7())
rag(
    "where did harrison work",
    langsmith_extra={"run_id": run_id, "metadata": {"user_id": "harrison"}}
)
```

现在我们已经记录了这两段元数据，我们应该能在 UI [这里](https://smith.langchain.com/public/37adf7e5-97aa-42d0-9850-99c0199bddf6/r)看到它们都显示出来。

## 生产环境 (Production)

很好——你已经利用这种新获得的可观测性快速迭代，并确信你的应用性能良好。是时候将其部署到生产环境了！你需要添加哪些新的可观测性功能呢？

首先，请注意，你已经添加的相同可观测性在生产环境中仍将发挥作用。你将能够继续深入研究特定的运行记录。

在生产环境中，你的流量可能会大得多。因此，你不太想一次只关注单个数据点。幸运的是，LangSmith 拥有一套工具可以帮助实现生产环境中的可观测性。

### 监控 (Monitoring)

如果你点击项目中（项目中的）`Monitor`（监控）选项卡，你将看到一系列监控图表。我们在这里跟踪许多特定于 LLM 的统计数据——跟踪记录的数量、反馈、首次令牌时间等等。你可以查看这些数据在几个不同的时间段内的变化情况。

![](/langsmith/images/tracing-tutorial-monitor.png)

### A/B 测试

<Note>
A/B 测试的 Group-by（分组）功能要求给定的元数据键至少存在 2 个不同的值。
</Note>

你也可以使用此选项卡来进行某种形式的 A/B 测试。在前面的教程中，我们开始跟踪几个不同的元数据属性——其中之一是 `llm`。我们可以按**任何**元数据属性对监控图表进行分组，并立即获得随时间变化的汇总图表。这使我们能够试验不同的 LLM（或提示词、或其他）并跟踪它们随时间的表现。

要做到这一点，我们只需点击顶部的 `Metadata`（元数据）按钮。这将弹出一个菜单，提供可供选择的分组选项：

![](/langsmith/images/tracing-tutorial-monitor-metadata.png)

选择此选项后，我们将开始看到按此属性分组的图表：

![](/langsmith/images/tracing-tutorial-monitor-grouped.png)

### 深入分析 (Drilldown)

LangSmith 提供的强大功能之一是能够轻松地深入分析你在监控图表中识别出的有问题的数据点。要做到这一点，你只需将鼠标悬停在监控图表中的数据点上。当你这样做时，你可以点击该数据点。这将引导你返回运行表，并显示一个过滤后的视图：

![](/langsmith/images/tracing-tutorial-monitor-drilldown.png)

## 结论

在本教程中，你了解了如何为你的 LLM 应用设置一流的可观测性。无论你的应用处于哪个阶段，你都可以从可观测性中获益。

如果你对可观测性有更深入的问题，请查看[操作指南部分](/langsmith/observability-concepts)，其中包含有关测试、提示管理等主题的指南。
