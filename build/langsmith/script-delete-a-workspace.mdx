<Note>
在 LangSmith 自托管 (Self-Hosted) 版本 **v0.10 中原生支持**删除工作区。请查看 [删除工作区的说明](/langsmith/set-up-a-workspace#delete-a-workspace)。

对于早于 v0.10 的自托管版本，请遵循以下指南操作。
</Note>

LangSmith UI 目前不支持从组织中删除单个工作区。然而，可以通过以下方式实现：直接从 ClickHouse 中的所有物化视图（除了 `runs_history` 视图）以及 `runs` 和 `feedbacks` 表中移除工作区的所有痕迹，然后从 Postgres 的 `tenants` 表中删除该工作区。

此操作需要提供工作区 ID 作为参数来执行命令。

### 先决条件 (Prerequisites)

请确保您准备好以下工具/项目。

1. kubectl

   * [https://kubernetes.io/docs/tasks/tools/](https://kubernetes.io/docs/tasks/tools/)

2. PostgreSQL 客户端

   * [https://www.postgresql.org/download/](https://www.postgresql.org/download/)

3. PostgreSQL 数据库连接信息：

   * Host (主机名)
   * Port (端口)
   * Username (用户名)
     * 如果使用捆绑版本，则为 `postgres`
   * Password (密码)
     * 如果使用捆绑版本，则为 `postgres`
   * Database name (数据库名称)
     * 如果使用捆绑版本，则为 `postgres`

4. Clickhouse 数据库凭据

   * Host (主机名)
   * Port (端口)
   * Username (用户名)
     * 如果使用捆绑版本，则为 `default`
   * Password (密码)
     * 如果使用捆绑版本，则为 `password`
   * Database name (数据库名称)
     * 如果使用捆绑版本，则为 `default`

5. 从您将运行迁移脚本的机器到 PostgreSQL 数据库的网络连通性。

   * 如果您使用的是捆绑版本，您可能需要为 postgresql 服务进行端口转发 (port forward) 到本地机器。
   * 运行 `kubectl port-forward svc/langsmith-postgres 5432:5432` 命令将 postgresql 服务端口转发到您的本地机器。

6. 从您将运行迁移脚本的机器到 Clickhouse 数据库的网络连通性。

   * 如果您使用的是捆绑版本，您可能需要为 clickhouse 服务进行端口转发到本地机器。
     * 运行 `kubectl port-forward svc/langsmith-clickhouse 8123:8123` 命令将 clickhouse 服务端口转发到您的本地机器。
   * 如果您使用的是 Clickhouse Cloud，您需要指定 `--ssl` 标志并使用端口 `8443`。

7. 删除工作区的脚本

   * 您可以从 [此处](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/scripts/delete_workspace.sh) 下载该脚本。

### 运行单个工作区的删除脚本

运行以下命令来执行工作区移除脚本：

```bash
sh delete_workspace.sh <postgres_url> <clickhouse_url> --workspace_id <workspace_id>
```

例如，如果您使用的是带有端口转发的捆绑版本，命令应如下所示：

```bash
sh delete_workspace.sh "postgres://postgres:postgres@localhost:5432/postgres" "clickhouse://default:password@localhost:8123/default" --workspace_id 4ec70ec7-0808-416a-b836-7100aeec934b
```

如果您现在访问 LangSmith UI，您应该会看到该工作区已被删除。
