在本指南中，我们将为聊天机器人设置评估（Evaluations）。这些评估允许你根据一组数据来衡量应用程序的性能表现。能够快速、可靠地获得这些洞察，将使你能够充满信心地进行迭代开发。

从高层次来看，在本教程中我们将执行以下操作：

* *创建一个初始的“黄金数据集”用于度量性能*
* *定义用于衡量性能的指标*
* *对几种不同的提示（Prompts）或模型运行评估*
* *手动比较结果*
* *长期跟踪结果*
* *设置自动化测试，在 CI/CD 中运行*

有关 LangSmith 支持的评估工作流程的更多信息，请参阅[操作指南](/langsmith/evaluation)，或查看有关 `[evaluate](https://docs.smith.langchain.com/reference/python/evaluation/langsmith.evaluation._runner.evaluate)` 及其异步对应项 `[aevaluate](https://docs.smith.langchain.com/reference/python/evaluation/langsmith.evaluation._arunner.aevaluate)` 的参考文档。

内容较多，我们马上开始深入探讨！

## 创建数据集 (Create a dataset)

准备测试和评估应用程序的第一步是定义你想要评估的数据点（datapoints）。这里需要考虑几个方面：

* 每个数据点的 **Schema**（模式）应该是什么？
* 我应该收集多少个数据点？
* 我应该如何收集这些数据点？

**Schema (模式):** 每个数据点至少应包含应用程序的输入（inputs）。如果你能够定义预期的输出（expected outputs）会非常有帮助——这些代表你期望一个运行正常的应用程序会输出的内容。通常情况下，你无法定义*完美*的输出——这没关系！评估是一个迭代过程。有时你可能还想为每个示例定义更多信息——比如 RAG（检索增强生成）中预期的检索文档，或者代理（agent）应采取的预期步骤。LangSmith 数据集非常灵活，允许你定义任意的 Schema。

**How many (数量):** 对于应该收集多少个数据点，没有固定的规则。最重要的是确保你对可能需要防范的**边缘情况**（edge cases）有适当的覆盖。即使是 10-50 个示例也能提供很大的价值！一开始不必担心收集大量数据——你可以（也应该）随着时间的推移不断添加！

**How to get (获取方式):** 这可能是最棘手的部分。一旦你知道要收集数据集……你该如何着手呢？对于大多数从头开始新项目进行评估的团队，我们通常看到他们首先手工收集前 10-20 个数据点。在有了这些初始数据点之后，数据集通常会成为*动态*的构建块，并随时间增长。它们通常在观察到真实用户如何使用你的应用程序、发现现有痛点，然后将其中一些数据点移入这个集合后而增长。此外，还有诸如**合成生成数据**之类的方法可以用来增强你的数据集。起初，我们建议不要担心这些，只需**手工标注**大约 10-20 个示例即可。

收集完数据集后，有几种不同的方法可以将它们上传到 LangSmith。在本教程中，我们将使用客户端（client），但你也可以通过 UI 上传（或者甚至在 UI 中创建它们）。

在本教程中，我们将创建 5 个数据点进行评估。我们将评估一个问答应用程序。输入将是一个问题（question），输出将是一个答案（answer）。由于这是一个问答应用程序，我们可以定义预期的答案。让我们展示如何创建并将此数据集上传到 LangSmith！

```python
from langsmith import Client

client = Client()

# 定义数据集：这些是你的测试用例
dataset_name = "QA Example Dataset"
dataset = client.create_dataset(dataset_name)

client.create_examples(
    dataset_id=dataset.id,
    examples=[
        {
            "inputs": {"question": "What is LangChain?"},
            "outputs": {"answer": "A framework for building LLM applications"},
        },
        {
            "inputs": {"question": "What is LangSmith?"},
            "outputs": {"answer": "A platform for observing and evaluating LLM applications"},
        },
        {
            "inputs": {"question": "What is OpenAI?"},
            "outputs": {"answer": "A company that creates Large Language Models"},
        },
        {
            "inputs": {"question": "What is Google?"},
            "outputs": {"answer": "A technology company known for search"},
        },
        {
            "inputs": {"question": "What is Mistral?"},
            "outputs": {"answer": "A company that creates Large Language Models"},
        }
    ]
)
```

现在，如果我们转到 LangSmith UI，在“Datasets & Testing” 页面上查找 `QA Example Dataset`，点击进入后，我们应该会看到我们有了五个新的示例。

## 定义指标 (Define metrics)

创建数据集后，我们现在可以定义一些指标来评估我们的响应。由于我们有一个预期的答案，我们可以将其作为评估的一部分进行比较。但是，我们不期望应用程序输出**完全相同**的答案，而是相似的内容。这使得我们的评估稍微复杂一些。

除了评估正确性之外，我们还要确保答案简短且简洁。这会更容易一些——我们可以定义一个简单的 Python 函数来衡量响应的长度。

让我们来定义这两个指标。

对于第一个指标，我们将使用一个 LLM 来**判断**输出是否正确（相对于预期输出）。这种**LLM 即裁判（LLM-as-a-judge）**在对于简单函数难以衡量的复杂情况中相当常见。我们可以在这里定义我们自己的提示和用于评估的 LLM：

```python
import openai
from langsmith import wrappers

openai_client = wrappers.wrap_openai(openai.OpenAI())

eval_instructions = "You are an expert professor specialized in grading students' answers to questions."

def correctness(inputs: dict, outputs: dict, reference_outputs: dict) -> bool:
    user_content = f"""You are grading the following question:
{inputs['question']}
Here is the real answer:
{reference_outputs['answer']}
You are grading the following predicted answer:
{outputs['response']}
Respond with CORRECT or INCORRECT:
Grade:"""
    response = openai_client.chat.completions.create(
        model="gpt-4o-mini",
        temperature=0,
        messages=[
            {"role": "system", "content": eval_instructions},
            {"role": "user", "content": user_content},
        ],
    ).choices[0].message.content
    return response == "CORRECT"
```

对于评估响应长度，要容易得多！我们可以定义一个简单的函数，检查实际输出的长度是否不到预期结果长度的 2 倍。

```python
def concision(outputs: dict, reference_outputs: dict) -> bool:
    return int(len(outputs["response"]) < 2 * len(reference_outputs["answer"]))
```

## 运行评估 (Run Evaluations)

太棒了！那么我们如何运行评估呢？现在我们有了一个数据集和评估器，我们所需要的就是我们的应用程序！我们将构建一个简单的应用程序，其中包含一个带有响应指令的系统消息，然后将其传递给 LLM。我们将直接使用 OpenAI SDK 来构建它：

```python
default_instructions = "Respond to the users question in a short, concise manner (one short sentence)."

def my_app(question: str, model: str = "gpt-4o-mini", instructions: str = default_instructions) -> str:
    return openai_client.chat.completions.create(
        model=model,
        temperature=0,
        messages=[
            {"role": "system", "content": instructions},
            {"role": "user", "content": question},
        ],
    ).choices[0].message.content
```

在通过 LangSmith 评估运行它之前，我们需要定义一个简单的包装器（wrapper），它将数据集中的输入键映射到我们想要调用的函数，然后还将函数的输出映射到我们期望的输出键。

```python
def ls_target(inputs: str) -> dict:
    return {"response": my_app(inputs["question"])}
```

太好了！现在我们准备运行评估了。让我们开始吧！

```python
experiment_results = client.evaluate(
    ls_target, # 你的 AI 系统
    data=dataset_name, # 用于预测和评估的数据
    evaluators=[concision, correctness], # 用于评分的评估器
    experiment_prefix="openai-4o-mini", # 用于轻松识别实验名称的前缀
)
```

这将输出一个 URL。如果点击它，我们应该会看到评估结果！

![](/langsmith/images/testing-tutorial-run.png)

如果我们回到数据集页面并选择 `Experiments` 选项卡，我们现在可以看到我们运行的一次性摘要！

![](/langsmith/images/testing-tutorial-one-run.png)

让我们尝试使用另一个模型！我们来试试 `gpt-4-turbo`

```python
def ls_target_v2(inputs: str) -> dict:
    return {"response": my_app(inputs["question"], model="gpt-4-turbo")}

experiment_results = client.evaluate(
    ls_target_v2,
    data=dataset_name,
    evaluators=[concision, correctness],
    experiment_prefix="openai-4-turbo",
)
```

现在让我们使用 GPT-4，同时也更新提示，要求答案更严格地简短。

```python
instructions_v3 = "Respond to the users question in a short, concise manner (one short sentence). Do NOT use more than ten words."

def ls_target_v3(inputs: str) -> dict:
    response = my_app(
        inputs["question"],
        model="gpt-4-turbo",
        instructions=instructions_v3
    )
    return {"response": response}

experiment_results = client.evaluate(
    ls_target_v3,
    data=dataset_name,
    evaluators=[concision, correctness],
    experiment_prefix="strict-openai-4-turbo",
)
```

## 比较结果 (Comparing results)

太棒了，我们已经评估了三次运行。但是我们如何比较结果呢？我们可以做的第一种方法是查看 `Experiments` 选项卡中的运行。如果我们这样做，我们可以看到每个运行的指标的**高层视图**：

![](/langsmith/images/testing-tutorial-compare-metrics.png)

很好！我们可以看出 GPT-4 在识别公司方面比 GPT-3.5 更好，我们也可以看到严格的提示在长度上帮助很大。但是，如果我们想更详细地探索呢？

为了做到这一点，我们可以选择所有想要比较的运行（在本例中是所有三个）并在比较视图中打开它们。我们立即看到所有三个测试并排显示。有些单元格会用颜色编码——这显示了与**某个基线**相比**某个指标**的回归情况。我们会自动选择基线和指标的默认值，但你可以自己更改它们。你也可以使用 `Display` 控件选择要查看的列和指标。通过点击顶部的图标，你还可以自动过滤以仅查看有改进/回归的运行。

![](/langsmith/images/testing-tutorial-compare-runs.png)

如果我们想查看更多信息，我们还可以选择鼠标悬停在某一行时出现的 `Expand` 按钮，以打开一个侧面面板，其中包含更多详细信息：

![](/langsmith/images/testing-tutorial-side-panel.png)

## 设置自动化测试以在 CI/CD 中运行 (Set up automated testing to run in CI/CD)

现在我们已经以一次性的方式运行了它，我们可以设置它以自动化的方式运行。我们只需将其包含为一个 pytest 文件，在 CI/CD 中运行它即可。作为此过程的一部分，我们可以选择仅记录结果，或者设置一些标准来确定它是否通过。例如，如果我想确保我们至少有 80% 的生成响应通过了 `length` 检查，我们可以使用如下测试来设置它：

```python
def test_length_score() -> None:
    """测试长度得分至少达到 80%."""
    experiment_results = evaluate(
        ls_target, # 你的 AI 系统
        data=dataset_name, # 用于预测和评估的数据
        evaluators=[concision, correctness], # 用于评分的评估器
    )
    # 这将在下一个版本中清理：
    feedback = client.list_feedback(
        run_ids=[r.id for r in client.list_runs(project_name=experiment_results.experiment_name)],
        feedback_key="concision"
    )
    scores = [f.score for f in feedback]
    assert sum(scores) / len(scores) >= 0.8, "聚合得分应至少为 .8"
```

## 长期跟踪结果 (Track results over time)

现在我们已经以自动化的方式运行了这些实验，我们希望跟踪这些结果。我们可以从数据集页面的总体 `Experiments` 选项卡中做到这一点。默认情况下，我们显示随时间变化的评估指标（在红色中突出显示）。我们还会自动跟踪 git 指标，以便轻松地将其与代码分支相关联（在黄色中突出显示）。

## 结论 (Conclusion)

本教程到此结束！

我们已经介绍了如何创建初始测试集、定义一些评估指标、运行实验、手动比较它们、设置 CI/CD，以及跟踪随时间变化的结果。希望这能帮助你充满信心地进行迭代。

这仅仅是个开始。如前所述，评估是一个持续进行的过程。例如——你希望评估的数据点很可能会随着时间的推移而继续变化。你可能会希望探索许多类型的评估器。有关此信息，请参阅[操作指南](/langsmith/evaluation)。

此外，除了这种“离线”方式之外，还有其他评估数据的方式（例如，你可以评估生产数据）。有关在线评估的更多信息，请参阅[本指南](/langsmith/online-evaluations)。
