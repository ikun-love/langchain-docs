<Info>
自托管 LangSmith 是企业版（Enterprise Plan）的一项附加功能，专为我们规模最大、最注重安全性的客户设计。请查看我们的 [定价页面](https://www.langchain.com/pricing) 了解更多详情，如果您想试用 LangSmith 环境，请 [联系我们的销售团队](https://www.langchain.com/contact-sales) 获取许可证密钥。
</Info>

本指南提供了使用 Docker 在本地运行 **LangSmith 平台**的说明，主要用于开发和测试目的。

<Warning>
**仅限开发/测试用途**。请勿将 Docker Compose 用于生产环境。对于生产部署，请使用 [Kubernetes](/langsmith/kubernetes)。
</Warning>

<Note>
此页面介绍了如何安装基础 [LangSmith 平台](/langsmith/self-hosted#langsmith) 以进行本地测试。它**不包含**部署管理功能。如需更多详细信息，请参阅 [自托管选项](/langsmith/self-hosted)。
</Note>

请注意，Docker Compose 仅限于本地开发环境，不支持 AWS Elastic Container Service、Azure Container Instances 和 Google Cloud Run 等容器服务。

## 先决条件

1. 确保您的系统上已安装并运行 Docker。您可以通过运行以下命令进行验证：

   ```bash
   docker info
   ```

   如果输出中没有显示任何服务器信息，请确保 Docker 安装正确并启动了 Docker 守护进程（daemon）。

   1. 推荐配置：您的机器上至少有 4 个 vCPU 和 16GB 内存。
      * 您可能需要根据组织规模/用量调整所有不同服务的资源请求/限制。
   2. 磁盘空间：LangSmith 可能会占用大量磁盘空间。请确保您有足够的可用空间。

2. LangSmith 许可证密钥（License Key）
   1. 您可以从您的 LangChain 代表处获取此密钥。[联系我们的销售团队](https://www.langchain.com/contact-sales) 了解更多信息。

3. API 密钥盐（Api Key Salt）

   1. 这是一个可以自行生成的密钥。它应该是一串随机字符。
   2. 您可以使用以下命令生成此密钥：

   ```bash
   openssl rand -base64 32
   ```

4. 访问 `https://beacon.langchain.com` 的出口流量（如果未运行在离线模式）
   1. LangSmith 需要访问 `https://beacon.langchain.com` 进行许可证验证和使用情况报告。这是 LangSmith 正常运行所必需的。您可以在 [出口流量（Egress）](/langsmith/self-host-egress) 部分找到有关出口要求的更多信息。

5. 配置

   1. 您可以在 `.env` 文件中设置多个配置选项。有关可用配置选项的更多信息，请参阅 [配置](/langsmith/self-host-scale) 部分。

## 通过 Docker Compose 运行

以下说明了如何使用 Docker Compose 运行 LangSmith。这是在没有 Kubernetes 的情况下运行 LangSmith 的最灵活的方式。Docker Compose 的默认配置仅适用于本地测试，不适用于任何服务暴露给公共互联网的实例。**在生产环境中，我们强烈建议使用安全的 Kubernetes 环境。**

### 1. 获取 LangSmith 的 `docker-compose.yml` 文件

您可以在 LangSmith SDK 仓库中找到 `docker-compose.yml` 文件及相关文件：[*LangSmith Docker Compose 文件*](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/docker-compose/docker-compose.yaml)

将 `docker-compose.yml` 文件以及 LangSmith SDK 中该目录下的所有文件复制到您的项目目录中。

* 确保同时复制 `users.xml` 文件。

### 2. 配置环境变量

1. 将 LangSmith SDK 中的 `.env.example` 文件复制到您的项目目录，并将其重命名为 `.env`。
2. 在 `.env` 文件中配置适当的值。有关可用配置选项，请参阅 [配置](/langsmith/self-hosted) 部分。

您也可以直接在 `docker-compose.yml` 文件中设置这些环境变量，或在终端中导出它们。我们建议将它们设置在 `.env` 文件中。

### 3. 启动服务器

在终端中执行以下命令来启动 LangSmith 应用程序：

```bash
docker-compose up
```

您也可以通过运行以下命令在后台运行服务器：

```bash
docker-compose up -d
```

### 验证部署：

1. `cli-langchain-frontend-1` 容器的暴露端口进行 curl 操作：

   ```bash
   curl localhost:1980/info{"version":"0.5.7","license_expiration_time":"2033-05-20T20:08:06","batch_ingest_config":{"scale_up_qsize_trigger":1000,"scale_up_nthreads_limit":16,"scale_down_nempty_trigger":4,"size_limit":100,"size_limit_bytes":20971520}}
   ```

2. 在浏览器中访问暴露的 `cli-langchain-frontend-1` 容器端口

   LangSmith UI 应该可以在 `http://localhost:1980` 看到并运行：

   ![.langsmith\_ui.png](/langsmith/images/langsmith-ui.png)

### 查看日志

如果任何时候您想检查服务器是否正在运行并查看日志，请运行

```bash
docker-compose logs
```

### 停止服务器

```bash
docker-compose down
```

## 使用 LangSmith

既然 LangSmith 正在运行，您就可以开始使用它来追踪您的代码了。您可以在 [自托管使用指南](/langsmith/self-hosted) 中找到有关如何使用自托管 LangSmith 的更多信息。

您的 LangSmith 实例现在正在运行，但设置可能尚未完全完成。

如果您使用基础配置之一，您可能部署了一个无认证（no-auth）的配置。在这种状态下，没有身份验证或用户账户/API 密钥的概念，只要将主机名传递给 LangChain Tracer/LangSmith SDK，就可以直接提交跟踪（traces）。

接下来的步骤中，我们强烈建议您与基础设施管理员合作，完成以下操作：

* 为您的 LangSmith 实例设置 DNS，以便更容易访问
* 配置 SSL，以确保提交到 LangSmith 的跟踪数据在传输过程中得到加密
* 配置 LangSmith 以使用 [OAuth 身份验证](/langsmith/self-host-sso) 或 [基本身份验证](/langsmith/self-host-basic-auth) 来保护您的 LangSmith 实例
* 保护对您的 Docker 环境的访问权限，仅限于 LangSmith 前端和 API
* 将 LangSmith 连接到安全的 Postgres 和 Redis 实例
