为了能够部署到 LangSmith（或进行自托管），应用程序必须使用一个 [配置文件](/langsmith/cli#configuration-file) 进行配置。本操作指南将介绍使用 `package.json` 来指定项目依赖项，从而设置 JavaScript 应用程序以进行部署的基本步骤。

本演练基于 [此仓库](https://github.com/langchain-ai/langgraphjs-studio-starter)，您可以对该仓库进行试验，以进一步了解如何为部署设置您的应用程序。

最终的仓库结构将如下所示：

```bash
my-app/
├── src # 所有项目代码位于此处
│   ├── utils # 图（graph）的可选工具
│   │   ├── tools.ts # 图的工具
│   │   ├── nodes.ts # 图的节点函数
│   │   └── state.ts # 图的状态定义
│   └── agent.ts # 用于构造图的代码
├── package.json # 包依赖项
├── .env # 环境变量
└── langgraph.json # LangGraph 的配置文件
```

## 指定依赖项

依赖项可以在 `package.json` 中指定。如果未创建上述任何文件，则稍后可以在 [配置文件](#create-the-api-config) 中指定依赖项。

`package.json` 文件的示例：

```json
{
  "name": "langgraphjs-studio-starter",
  "packageManager": "yarn@1.22.22",
  "dependencies": {
    "@langchain/community": "^0.2.31",
    "@langchain/core": "^0.2.31",
    "@langchain/langgraph": "^0.2.0",
    "@langchain/openai": "^0.2.8"
  }
}
```

在部署应用程序时，依赖项将使用您选择的包管理器进行安装，前提是它们符合下面列出的兼容版本范围：

```
"@langchain/core": "^0.3.42",
"@langchain/langgraph": "^0.2.57",
"@langchain/langgraph-checkpoint": "~0.0.16",
```

文件目录示例：

```bash
my-app/
└── package.json # 包依赖项
```

## 指定环境变量

环境变量可以选择在文件中指定（例如 `.env`）。请参阅 [环境变量参考](/langsmith/env-var) 以配置部署所需的其他变量。

`.env` 文件的示例：

```
MY_ENV_VAR_1=foo
MY_ENV_VAR_2=bar
OPENAI_API_KEY=key
TAVILY_API_KEY=key_2
```

文件目录示例：

```bash
my-app/
├── package.json
└── .env # 环境变量
```

## 定义图

实现您的图（Graphs）。图可以定义在一个文件中，也可以定义在多个文件中。请记下每个已编译图的变量名称，以便包含在应用程序中。变量名称稍后在创建 [配置文件](/langsmith/cli#configuration-file) 时会用到。

这是一个 `agent.ts` 的示例：

```ts
import type { AIMessage } from "@langchain/core/messages";
import { TavilySearchResults } from "@langchain/community/tools/tavily_search";
import { ChatOpenAI } from "@langchain/openai";

import { MessagesAnnotation, StateGraph } from "@langchain/langgraph";
import { ToolNode } from "@langchain/langgraph/prebuilt";

const tools = [new TavilySearchResults({ maxResults: 3 })];

// 定义调用模型的函数
async function callModel(state: typeof MessagesAnnotation.State) {
  /**
   * 调用驱动我们 Agent 的 LLM。
   * 欢迎自定义提示词、模型和其他逻辑！
   */
  const model = new ChatOpenAI({
    model: "gpt-4o",
  }).bindTools(tools);

  const response = await model.invoke([
    {
      role: "system",
      content: `You are a helpful assistant. The current date is ${new Date().getTime()}.`,
    },
    ...state.messages,
  ]);

  // MessagesAnnotation 支持返回单个消息或消息数组
  return { messages: response };
}

// 定义确定是否继续的函数
function routeModelOutput(state: typeof MessagesAnnotation.State) {
  const messages = state.messages;
  const lastMessage: AIMessage = messages[messages.length - 1];
  // 如果 LLM 正在调用工具，则路由到工具。
  if ((lastMessage?.tool_calls?.length ?? 0) > 0) {
    return "tools";
  }
  // 否则结束图。
  return "__end__";
}

// 定义一个新的图。
// 有关定义自定义图状态的更多信息，请参阅 https://langchain-ai.github.io/langgraphjs/how-tos/define-state/#getting-started
const workflow = new StateGraph(MessagesAnnotation)
  // 定义我们将循环往复的两个节点
  .addNode("callModel", callModel)
  .addNode("tools", new ToolNode(tools))
  // 将入口点设置为 `callModel`
  // 这意味着这是第一个被调用的节点
  .addEdge("__start__", "callModel")
  .addConditionalEdges(
    // 首先，我们定义边的源节点。我们使用 `callModel`。
    // 这意味着这些是在调用 `callModel` 节点后采取的边。
    "callModel",
    // 接下来，我们传入将确定接收节点的函数，该函数将在源节点调用后被调用。
    routeModelOutput,
    // 条件边可以路由到的可能目的地的列表。
    // 这是为了确保 Studio 中图的正确渲染所必需的。
    ["tools", "__end__"]
  )
  // 这意味着调用 `tools` 之后，接下来调用 `callModel` 节点。
  .addEdge("tools", "callModel");

// 最后，我们编译它！
// 这会将其编译成一个可以调用和部署的图。
export const graph = workflow.compile();
```

文件目录示例：

```bash
my-app/
├── src # 所有项目代码位于此处
│   ├── utils # 图（graph）的可选工具
│   │   ├── tools.ts # 图的工具
│   │   ├── nodes.ts # 图的节点函数
│   │   └── state.ts # 图的状态定义
│   └── agent.ts # 用于构造图的代码
├── package.json # 包依赖项
├── .env # 环境变量
└── langgraph.json # LangGraph 的配置文件
```

## 创建 API 配置

创建一个名为 `langgraph.json` 的 [配置文件](/langsmith/cli#configuration-file)。有关配置对象中每个键的详细解释，请参阅 [配置文件参考](/langsmith/cli#configuration-file)。

`langgraph.json` 文件的示例：

```json
{
  "node_version": "20",
  "dockerfile_lines": [],
  "dependencies": ["."],
  "graphs": {
    "agent": "./src/agent.ts:graph"
  },
  "env": ".env"
}
```

请注意，`CompiledGraph` 的变量名出现在顶级 `graphs` 键下每个子键值对的末尾（即 `:<variable_name>` 之前的部分）。

<Info>
    **配置文件的位置**
    配置文件必须放置在与包含已编译图和相关依赖项的 TypeScript 文件**相同级别或更高级别的**目录中。
</Info>
