本指南假设您熟悉 [LangSmith](/langsmith/home)、[持久化](/oss/langgraph/persistence) 和 [跨线程持久化](/oss/langgraph/persistence#memory-store) 的概念。

LangSmith 会持久化[检查点](/oss/langgraph/persistence#checkpoints)（线程状态）和[跨线程内存项](/oss/langgraph/persistence#memory-store)（存储项）。在 `langgraph.json` 中配置生存时间（Time-to-Live, TTL）策略，可以自动管理这些数据，防止数据无限期累积。

## 配置检查点 TTL

检查点会捕获对话线程的状态。设置 TTL 可以确保旧的检查点和线程被自动删除。

向 `langgraph.json` 文件添加 `checkpointer.ttl` 配置：

```json
{
  "dependencies": ["."],
  "graphs": {
    "agent": "./agent.py:graph"
  },
  "checkpointer": {
    "ttl": {
      "strategy": "delete",
      "sweep_interval_minutes": 60,
      "default_ttl": 43200
    }
  }
}
```

* `strategy`: 指定过期后要执行的操作。目前只支持 `"delete"` 策略，它会在过期时删除线程中的所有检查点。
* `sweep_interval_minutes`: 定义系统检查过期检查点的频率（以分钟为单位）。
* `default_ttl`: 设置线程（及相应检查点）的默认生存期（以分钟为单位）（例如：43200 分钟 = 30 天）。此设置仅适用于配置部署后创建的检查点；现有检查点/线程不会被更改。如需清除旧数据，请显式删除它们。

## 配置存储项 TTL

存储项（Store items）支持跨线程数据持久化。为存储项配置 TTL 有助于通过移除陈旧数据来管理内存。

向 `langgraph.json` 文件添加 `store.ttl` 配置：

```json
{
  "dependencies": ["."],
  "graphs": {
    "agent": "./agent.py:graph"
  },
  "store": {
    "ttl": {
      "refresh_on_read": true,
      "sweep_interval_minutes": 120,
      "default_ttl": 10080
    }
  }
}
```

* `refresh_on_read`:（可选，默认为 `true`）如果设置为 `true`，通过 `get` 或 `search` 访问某项时，会重置其过期计时器。如果设置为 `false`，TTL 只会在 `put` 操作时刷新。
* `sweep_interval_minutes`:（可选）定义系统检查过期项的频率（以分钟为单位）。如果省略，则不会进行清除操作。
* `default_ttl`:（可选）设置存储项的默认生存期（以分钟为单位）（例如：10080 分钟 = 7 天）。此设置仅适用于配置部署后创建的项；现有项不会被更改。如果需要清除较旧的项，请手动删除它们。如果省略，则存储项默认不会过期。

## 组合 TTL 配置

您可以在同一个 `langgraph.json` 文件中配置检查点和存储项的 TTL，为每种数据类型设置不同的策略。以下是一个示例：

```json
{
  "dependencies": ["."],
  "graphs": {
    "agent": "./agent.py:graph"
  },
  "checkpointer": {
    "ttl": {
      "strategy": "delete",
      "sweep_interval_minutes": 60,
      "default_ttl": 43200
    }
  },
  "store": {
    "ttl": {
      "refresh_on_read": true,
      "sweep_interval_minutes": 120,
      "default_ttl": 10080
    }
  }
}
```

## 配置每个线程的 TTL

您可以为每个线程应用 [TTL 配置](https://reference.langchain.com/python/langsmith/deployment/sdk/#langgraph_sdk.client.ThreadsClient.create)。

```python
thread = await client.threads.create(
    ttl={
        "strategy": "delete",
        "ttl": 43200  # 30 days in minutes
    }
)
```

## 运行时覆盖

`langgraph.json` 中的默认 `store.ttl` 设置可以在运行时被覆盖，方法是在 SDK 方法调用（如 `get`, `put`, 和 `search`）中提供特定的 TTL 值。

## 部署流程

在 `langgraph.json` 中配置好 TTL 后，部署或重启您的 LangGraph 应用程序以使更改生效。对于本地开发使用 `langgraph dev`，对于 Docker 部署使用 `langgraph up`。

有关其他可配置选项，请参阅 [langgraph.json CLI 参考](https://langchain-ai.github.io/langgraph/reference/configuration/#configuration-file)。
