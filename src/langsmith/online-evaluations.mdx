在线评估器提供对生产轨迹（traces）的实时反馈。这对于持续监控应用程序的性能非常有用——例如，识别问题、衡量改进并确保长期一致的质量。

LangSmith 支持两种类型的在线评估器：

- **[LLM 即判官 (LLM-as-a-judge)](/langsmith/evaluation-concepts#llm-as-judge)**：使用大型语言模型（LLM）来评估轨迹，作为类人判断（如毒性、幻觉、正确性）的可扩展替代方案。支持两种不同的粒度级别：
    - **运行级别 (Run level)**：评估单个运行。
    - [**对话串级别 (Thread level)**](/langsmith/online-evaluations#configure-multi-turn-online-evaluators)：评估对话串中的所有轨迹。
- **自定义代码 (Custom Code)**：直接在 LangSmith 中使用 Python 编写评估器。通常用于验证数据的结构或统计属性。

<Note>当在线评估器在轨迹中的任何运行上运行时，该轨迹将自动升级到 [扩展数据保留](/langsmith/administration-overview#data-retention-auto-upgrades) 策略。此升级将影响轨迹定价，但可确保满足您评估标准的轨迹（通常是分析价值最高的轨迹）得到保留以供调查。 </Note>

## 配置在线评估器

#### 1. 导航到在线评估器

前往 **Tracing Projects** 选项卡并选择一个追踪项目。点击追踪项目页面右上角的 **+ New**，然后点击 **New Evaluator**。选择要配置的评估器类型。

#### 2. 命名您的评估器

#### 3. 创建一个过滤器

例如，您可能希望根据以下条件应用特定的评估器：

- 具有 [用户反馈](/langsmith/attach-user-feedback) 表明响应不令人满意（unsatisfactory）的运行。
- 调用了特定工具的运行。有关详细信息，请参阅 [按工具调用过滤](/langsmith/filter-traces-in-application#example-filtering-for-tool-calls)。
- 匹配特定元数据的运行（例如，如果您记录了带有 `plan_type` 的轨迹，并且只希望对来自企业客户的轨迹运行评估）。有关详细信息，请参阅 [向轨迹添加元数据](/langsmith/add-metadata-tags)。

评估器上的过滤器的工作方式与项目中的轨迹过滤方式相同。有关过滤器的更多信息，您可以参考 [此指南](./filter-traces-in-application)。

<Tip>
在创建评估器过滤器时，检查运行（runs）通常很有帮助。在打开评估器配置面板时，您可以检查运行并对其应用过滤器。应用于运行表的任何过滤器都将自动反映在评估器的过滤器中。
</Tip>

#### 4.（可选）配置采样率

配置采样率以控制触发自动化操作的经过过滤的运行的百分比。例如，为了控制成本，您可能希望设置一个过滤器，仅将评估器应用于 10% 的轨迹。要做到这一点，您需要将采样率设置为 `0.1`。

#### 5.（可选）将规则应用于过去的运行

通过切换 **Apply to past runs**（应用于过去运行）并输入“Backfill from”（从…回填）日期，将规则应用于过去的运行。这仅在创建规则时才可能。注意：回填是作为后台作业处理的，因此您不会立即看到结果。

要跟踪回填的进度，您可以前往追踪项目中的 **Evaluators** 选项卡，并点击您创建的评估器的 **Logs** 按钮。在线评估器日志与 [自动化规则日志](./rules#view-logs-for-your-automations) 类似。

- 添加评估器名称
- (可选) 过滤您希望应用评估器的运行，或配置采样率。
- 选择 **Apply Evaluator**

#### 6. 选择评估器类型

- 配置 [LLM 即判官评估器](/langsmith/online-evaluations#configure-a-llm-as-a-judge-online-evaluator)
- 配置 [自定义代码评估器](/langsmith/online-evaluations#configure-a-custom-code-evaluator)

### 配置自定义代码评估器

选择 **custom code**（自定义代码）评估器。

#### 编写您的评估函数

<Note>
**自定义代码评估器的限制。**

**允许的库**：您可以导入所有标准库函数，以及以下公共包：

```
numpy (v2.2.2): "numpy"
pandas (v1.5.2): "pandas"
jsonschema (v4.21.1): "jsonschema"
scipy (v1.14.1): "scipy"
sklearn (v1.26.4): "scikit-learn"
```

**网络访问**：您不能从自定义代码评估器访问互联网。
</Note>

自定义代码评估器必须内联（inline）编写。我们建议在 LangSmith 中设置自定义代码评估器之前在本地进行测试。

在用户界面（UI）中，您会看到一个面板，允许您内联编写代码，其中包含一些起始代码：

![](/langsmith/images/online-eval-custom-code.png)

自定义代码评估器接受一个参数：

- 一个 `Run`（[参考](/langsmith/run-data-format)）。这代表要评估的被采样运行。

它们返回一个单一的值：

- 反馈字典 (Feedback(s) Dictionary)：一个字典，其键是您希望返回的反馈类型，值是您将为该反馈键赋予的分数。例如，`{"correctness": 1, "silliness": 0}` 将在运行上创建两种类型的反馈，一种表示它是正确的，另一种表示它不愚蠢。

在下面的截图中，您可以看到一个简单函数的示例，该函数验证实验中的每个运行是否具有已知的 json 字段：

<CodeGroup>

```python Python
import json

def perform_eval(run):
  output_to_validate = run['outputs']
  is_valid_json = 0

  # assert you can serialize/deserialize as json
  try:
    json.loads(json.dumps(output_to_validate))
  except Exception as e:
    return { "formatted": False }

  # assert output facts exist
  if "facts" not in output_to_validate:
    return { "formatted": False }

  # assert required fields exist
  if "years_mentioned" not in output_to_validate["facts"]:
    return { "formatted": False }

  return {"formatted": True}
```

```javascript JavaScript
function perform_eval(run) {
    const outputToValidate = run.outputs;

    // Assert you can serialize/deserialize as json
    try {
        JSON.stringify(outputToValidate);
        JSON.parse(JSON.stringify(outputToValidate));
    } catch (e) {
        return { "formatted": false };
    }

    // Assert output facts exist
    if (!("facts" in outputToValidate)) {
        return { "formatted": false };
    }

    // Assert required fields exist
    if (!outputToValidate["facts"].hasOwnProperty("years_mentioned")) {
        return { "formatted": false };
    }

    return { "formatted": true };
}
```

</CodeGroup>

#### 测试并保存您的评估函数

在保存之前，您可以通过点击 **Test Code**（测试代码）在最近的运行上测试评估函数，以确保代码正常执行。

一旦您点击 **Save**（保存），您的在线评估器将对新采样的运行（如果选择了回填选项，也会对回填的运行）进行评估。

## 配置多轮次在线评估器

多轮次在线评估器允许您评估人与代理之间的整个对话——而不仅仅是单个的交互。它们衡量整个对话串中端到端（end-to-end）的交互质量。

您可以使用多轮次评估来衡量：
1. 语义意图 (Semantic Intent)：用户试图做什么。
2. 语义结果 (Semantic Outcome)：实际发生了什么，任务是否成功。
3. 轨迹 (Trajectory)：对话如何展开，包括工具调用的轨迹。

<Note> 运行多轮次在线评估将自动将对话串内的每个轨迹升级到 [扩展数据保留](/langsmith/administration-overview#data-retention-auto-upgrades) 策略。此升级将影响轨迹定价，但可确保满足您评估标准的轨迹（通常是分析价值最高的轨迹）得到保留以供调查。 </Note>

### 先决条件

- 您的追踪项目必须使用 [对话串 (threads)](/langsmith/threads)。
- 对话串中每个轨迹的顶层输入（inputs）和输出（outputs）必须包含一个名为 `messages` 的键，其中包含消息列表。我们支持 [LangChain](/langsmith/log-llm-trace#messages-format)、[OpenAI Chat Completions](https://platform.openai.com/docs/api-reference/chat/create) 和 [Anthropic Messages](https://platform.claude.com/docs/en/api/messages) 格式的消息。
    - 如果每个轨迹的顶层输入和输出只包含对话的最新消息，LangSmith 将自动将消息跨轮次合并到对话串中。
    - 如果每个轨迹的顶层输入和输出包含完整的对话历史记录，LangSmith 将直接使用该历史记录。

<Note>
如果您的轨迹不遵循上述格式，则对话串级别评估器将无法工作。您需要更新跟踪到 LangSmith 的方式，以确保每个轨迹的顶层输入和输出包含 `messages` 列表。

有关更多信息，请参阅 [故障排除](#troubleshooting) 部分。
</Note>

### 配置

1. 前往 **Tracing Projects** 选项卡并选择一个追踪项目。
2. 点击追踪项目页面右上角的 **+ New** > **New Evaluator** > **Evaluate a multi-turn thread**（评估多轮次对话串）。
3. **命名您的评估器**。
4. **应用过滤器或采样率**。<br />
使用过滤器或采样来控制评估器的成本。例如，只评估少于 *N* 轮的对话串，或对所有对话串进行 10% 的采样。
5. **配置空闲时间 (idle time)**。<br />
第一次配置对话串级别评估器时，您需要定义空闲时间——即对话串中最后一条轨迹出现后经过多长时间才认为其完成并准备好进行评估的时间。此值应反映应用程序中用户交互的预期长度。它适用于项目中的所有评估器。
<Tip>
在首次测试评估器时，使用较短的空闲时间以便快速看到结果。验证后，增加它以匹配预期的用户交互长度。
</Tip>
6. **配置您的模型**。<br />
选择要用于评估器的提供商和模型。对话串通常很长，因此您应该使用具有更高上下文窗口的模型，以避免达到限制。例如，OpenAI 的 GPT-4o mini 或 Gemini 2.5 Flash 都是不错的选择，因为它们都具有 1M+ token 的上下文窗口。

7. **配置您的 LLM 即判官提示 (prompt)**。<br />
定义您希望评估的内容。此提示将用于评估整个对话串。您还可以配置将 `messages` 列表的哪些部分传递给评估器，以控制它接收到的内容：
    - 所有消息 (All messages)：发送完整的消息列表。
    - 人类和 AI 对 (Human and AI pairs)：仅发送用户和助手的消息（排除系统消息、工具调用等）。
    - 第一个人和最后一个 AI (First human and last AI)：仅发送第一条用户消息和最后一条助手回复。

9. **设置您的反馈配置**。<br />
配置反馈键的名称、要收集的反馈格式，以及可选地启用反馈的推理（reasoning）。

<Warning>
不建议将线程级别评估器和运行级别评估器使用相同的反馈键，因为这会使得区分两者变得困难。
</Warning>

10. **保存您的评估器**。

保存后，您的评估器将出现在 **Evaluators** 选项卡中。对于保存后创建的新对话串，一旦它们的空闲时间过去，您就可以对其进行测试。

### 限制
这些是当前多轮次在线评估器的限制（可能会有所更改）。如果您遇到任何限制，请联系我们。

- **运行时间必须少于一周**：当一个对话串进入空闲状态时，只有过去 7 天内的运行才有资格进行评估。
- **最多同时评估 500 个对话串**：如果在五分钟内有超过 500 个对话串被标记为闲置，我们将自动进行采样，超出 500 个。
- **每个工作区最多 10 个多轮次在线评估器**

### 故障排除

**检查评估器的状态** <br />
您可以通过前往追踪项目中的 **Evaluators** 选项卡，并点击您创建的评估器的 **Logs** 按钮来查看其运行历史，从而检查评估器上次运行的时间。

**检查发送到评估器的数据** <br />
通过前往追踪项目中的 **Evaluators** 选项卡，点击您创建的评估器，然后点击 **Evaluator traces** 选项卡，检查发送到评估器的已检查数据。

在此选项卡中，您可以看到传递给 LLM 即判官评估器的输入。如果您的消息没有正确传递，您将在输入中看到空白值。如果您的消息没有格式化为 [预期格式之一](/langsmith/online-evaluations#prerequisites)，就可能发生这种情况。
