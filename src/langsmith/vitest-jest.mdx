LangSmith 提供了与 Vitest 和 Jest 的集成，允许 JavaScript 和 TypeScript 开发人员使用熟悉的语法定义数据集并进行评估。

![Jest/Vitest reporter output](/langsmith/images/jest-vitest-reporter-output.png)

与 `evaluate()` 评估流程相比，在以下情况下使用此集成更有用：

* **每个示例需要不同的评估逻辑**：标准的评估流程假设在所有数据集示例中都执行一致的应用程序和评估器。对于更复杂的系统或全面的评估，特定的系统子集可能需要使用特定的输入类型和指标进行评估。将这些异构评估编写为跟踪在一起的独立测试用例套件会更简单。
* **您想断言二进制期望**：在 LangSmith 中跟踪断言并在本地抛出断言错误（例如，在 CI 管道中）。当同时评估系统输出并断言其基本属性时，测试工具会很有帮助。
* **您想利用 Vitest/Jest 生态系统的 mocks、watch 模式、本地结果或其他功能**

<Info>
需要 JS/TS SDK 版本 `langsmith>=0.3.1`。
</Info>

<Warning>
Vitest/Jest 集成仍处于 Beta 阶段，在未来的版本中可能会发生变化。
</Warning>

<Info>
Python SDK 有一个类似的 [pytest 集成](/langsmith/pytest)。
</Info>

## 设置

按如下方式设置集成。请注意，虽然您可以使用现有的测试配置文件，将 LangSmith 评估与其他单元测试（作为标准的 `*.test.ts` 文件）放在一起，但以下示例也将设置一个单独的测试配置文件和命令来运行您的评估。它将假定您的测试文件以 `.eval.ts` 结尾。

这可确保自定义测试报告器和其他 LangSmith 接触点不会修改您现有的测试输出。

### Vitest

如果您尚未安装，请安装所需的开发依赖项：

<CodeGroup>

```bash yarn
yarn add -D vitest dotenv
```

```bash npm
npm install -D vitest dotenv
```

```bash pnpm
pnpm add -D vitest dotenv
```

</CodeGroup>

以下示例还需要 `openai`（当然还有 `langsmith`！）作为依赖项：

<CodeGroup>

```bash yarn
yarn add langsmith openai
```

```bash npm
npm install langsmith openai
```

```bash pnpm
pnpm add langsmith openai
```

</CodeGroup>

然后创建一个单独的 `ls.vitest.config.ts` 文件，其中包含以下基本配置：

```typescript
import { defineConfig } from "vitest/config";

export default defineConfig({
  test: {
    include: ["**/*.eval.?(c|m)[jt]s"],
    reporters: ["langsmith/vitest/reporter"],
    setupFiles: ["dotenv/config"],
  },
});
```

* `include` 确保只运行项目中以 `eval.ts` 变体结尾的文件
* `reporters` 负责如上所示美化格式化您的输出
* `setupFiles` 运行 `dotenv` 以在运行评估之前加载环境变量

<Warning>
目前不支持 JSDom 环境。您应该从配置中省略 `"environment"` 字段，或者将其设置为 `"node"`。
</Warning>

最后，将以下内容添加到 `package.json` 的 `scripts` 字段中，以使用您刚才创建的配置运行 Vitest：

```json
{
  "name": "YOUR_PROJECT_NAME",
  "scripts": {
    "eval": "vitest run --config ls.vitest.config.ts"
  },
  "dependencies": {
    ...
  },
  "devDependencies": {
    ...
  }
}
```

请注意，上述脚本禁用了 Vitest 默认的监视模式来运行评估，因为许多评估器可能包含运行时间较长的 LLM 调用。

</CodeGroup>

<CodeGroup>

```

```bash npm
npm install langsmith openai
```

```bash pnpm
pnpm add langsmith openai
```

</CodeGroup>

<Info>
以下设置说明适用于基本的 JS 文件和 CJS。要添加对 TypeScript 和 ESM 的支持，请参阅 Jest 的官方文档或使用 [Vitest](#vitest)。

然后创建一个名为 `ls.jest.config.cjs` 的单独配置文件：

```javascript
module.exports = {
  testMatch: ["**/*.eval.?(c|m)[jt]s"],
  reporters: ["langsmith/jest/reporter"],
  setupFiles: ["dotenv/config"],
};
```

* `testMatch` 确保只运行项目中以 `eval.js` 变体结尾的文件
* `reporters` 负责如上所示美化格式化您的输出
* `setupFiles` 运行 `dotenv` 以在运行评估之前加载环境变量

<Warning>
目前不支持 JSDom 环境。您应该从配置中省略 `"testEnvironment"` 字段，或者将其设置为 `"node"`。
</Warning>

最后，将以下内容添加到 `package.json` 的 `scripts` 字段中，以使用您刚才创建的配置运行 Jest：

```json
{
  "name": "YOUR_PROJECT_NAME",
  "scripts": {
    "eval": "jest --config ls.jest.config.cjs"
  },
  "dependencies": {
    ...
  },
  "devDependencies": {
    ...
  }
}
```

## 定义和运行评估

现在您可以使用熟悉的 Vitest/Jest 语法将评估定义为测试，但有一些注意事项：

* 您应该从 `langsmith/jest` 或 `langsmith/vitest` 入口点导入 `describe` 和 `test`
* 您的测试用例必须包装在 `describe` 块中
* 在声明测试时，签名略有不同——有一个额外的参数包含示例输入和预期的输出

尝试通过创建一个名为 `sql.eval.ts` 的文件（如果使用不带 TypeScript 的 Jest，则为 `sql.eval.js`），并将以下内容粘贴到其中来实现：

```typescript
import * as ls from "langsmith/vitest";
import { expect } from "vitest";
// import * as ls from "langsmith/jest";
// import { expect } from "@jest/globals";
import OpenAI from "openai";
import { traceable } from "langsmith/traceable";
import { wrapOpenAI } from "langsmith/wrappers/openai";

// 将 "openai" 添加为依赖项，并将 OPENAI_API_KEY 设置为环境变量
const tracedClient = wrapOpenAI(new OpenAI());

const generateSql = traceable(
  async (userQuery: string) => {
    const result = await tracedClient.chat.completions.create({
      model: "gpt-4o-mini",
      messages: [
        {
          role: "system",
          content:
            "将用户查询转换为 SQL 查询。不要用任何 markdown 标签包裹。",
        },
        {
          role: "user",
          content: userQuery,
        },
      ],
    });
    return result.choices[0].message.content;
  },
  { name: "generate_sql" }
);

ls.describe("生成 sql 示例", () => {
  ls.test(
    "生成 select all",
    {
      inputs: { userQuery: "从 customers 表中获取所有用户" },
      referenceOutputs: { sql: "SELECT * FROM customers;" },
    },
    async ({ inputs, referenceOutputs }) => {
      const sql = await generateSql(inputs.userQuery);
      ls.logOutputs({ sql }); // <-- 日志运行输出，可选
      expect(sql).toEqual(referenceOutputs?.sql); // <-- 断言结果记录在 'pass' 反馈键下
    }
  );
});
```

您可以将每个 `ls.test()` 用例视为对应于一个数据集示例，将 `ls.describe()` 视为定义一个 LangSmith 数据集。如果在运行测试套件时设置了 LangSmith [跟踪环境变量](/langsmith/evaluation-concepts#3-set-up-your-environment)，SDK 会执行以下操作：

* 如果不存在，则在 LangSmith 中创建一个与传递给 `ls.describe()` 的名称相同的[数据集](/langsmith/evaluation-concepts#datasets)
* 如果不存在匹配项，则为传递给测试用例的每个输入和预期输出创建一个数据集中的示例
* 为每个测试用例创建一个新的[实验](/langsmith/evaluation-concepts#experiment)（包含一个结果）
* 收集每个测试用例的通过/失败率到 `pass` 反馈键下

当您运行此测试时，它将根据测试用例的通过/失败情况，在 `pass` 反馈键下有一个默认的布尔反馈键。它还会将在应用程序中记录的任何输出（使用 `ls.logOutputs()` 记录或从测试函数返回的）作为“实际”结果值进行跟踪。

请创建一个 `.env` 文件，其中包含您的 `OPENAI_API_KEY` 和 LangSmith 凭据（如果您还没有）：

```bash
OPENAI_API_KEY="YOUR_KEY_HERE"
LANGSMITH_API_KEY="YOUR_LANGSMITH_KEY"
LANGSMITH_TRACING="true"
```

现在使用我们在上一步中设置的 `eval` 脚本来运行测试：

<CodeGroup>

```bash yarn
yarn run eval
```

```bash npm
npm run eval
```

```bash pnpm
pnpm run eval
```

</CodeGroup>

您声明的测试将会运行！

完成后，如果您设置了 LangSmith 环境变量，您应该会看到一个链接，指向 LangSmith 中创建的实验，与测试结果一起显示。

这是针对该测试套件的实验外观：

## 跟踪反馈

默认情况下，LangSmith 在 `pass` 反馈键下收集每个测试用例的通过/失败率。您可以使用 `ls.logFeedback()` 或 `wrapEvaluator()` 添加额外的反馈。为此，请尝试使用以下内容作为您的 `sql.eval.ts` 文件（如果使用不带 TypeScript 的 Jest，则为 `sql.eval.js`）：

```typescript
import * as ls from "langsmith/vitest";
// import * as ls from "langsmith/jest";
import OpenAI from "openai";
import { traceable } from "langsmith/traceable";
import { wrapOpenAI } from "langsmith/wrappers/openai";

// 将 "openai" 添加为依赖项，并将 OPENAI_API_KEY 设置为环境变量
const tracedClient = wrapOpenAI(new OpenAI());

const generateSql = traceable(
  async (userQuery: string) => {
    const result = await tracedClient.chat.completions.create({
      model: "gpt-4o-mini",
      messages: [
        {
          role: "system",
          content:
            "将用户查询转换为 SQL 查询。不要用任何 markdown 标签包裹。",
        },
        {
          role: "user",
          content: userQuery,
        },
      ],
    });
    return result.choices[0].message.content ?? "";
  },
  { name: "generate_sql" }
);

const myEvaluator = async (params: {
  outputs: { sql: string };
  referenceOutputs: { sql: string };
}) => {
  const { outputs, referenceOutputs } = params;
  const instructions = [
    "如果 ACTUAL 和 EXPECTED 答案在语义上等价，则返回 1， ",
    "否则返回 0。只返回 0 或 1，不返回其他任何内容。",
  ].join("\n");
  const grade = await tracedClient.chat.completions.create({
    model: "gpt-4o-mini",
    messages: [
      {
        role: "system",
        content: instructions,
      },
      {
        role: "user",
        content: `ACTUAL: ${outputs.sql}\nEXPECTED: ${referenceOutputs?.sql}`,
      },
    ],
  });
  const score = parseInt(grade.choices[0].message.content ?? "");
  return { key: "correctness", score };
};

ls.describe("生成 sql 示例", () => {
  ls.test(
    "生成 select all",
    {
      inputs: { userQuery: "从 customers 表中获取所有用户" },
      referenceOutputs: { sql: "SELECT * FROM customers;" },
    },
    async ({ inputs, referenceOutputs }) => {
      const sql = await generateSql(inputs.userQuery);
      ls.logOutputs({ sql });
      const wrappedEvaluator = ls.wrapEvaluator(myEvaluator);
      // 将自动记录 'correctness' 作为反馈
      await wrappedEvaluator({
        outputs: { sql },
        referenceOutputs,
      });
      // 您也可以使用 `ls.logFeedback()` 手动记录反馈
      ls.logFeedback({
        key: "harmfulness",
        score: 0.2,
      });
    }
  );
  ls.test(
    "跑题输入",
    {
      inputs: { userQuery: "whats up" },
      referenceOutputs: { sql: "sorry that is not a valid query" },
    },
    async ({ inputs, referenceOutputs }) => {
      const sql = await generateSql(inputs.userQuery);
      ls.logOutputs({ sql });
      const wrappedEvaluator = ls.wrapEvaluator(myEvaluator);
      // 将自动记录 'correctness' 作为反馈
      await wrappedEvaluator({
        outputs: { sql },
        referenceOutputs,
      });
      // 您也可以使用 `ls.logFeedback()` 手动记录反馈
      ls.logFeedback({
        key: "harmfulness",
        score: 0.2,
      });
    }
  );
});
```

注意 `myEvaluator` 函数周围使用了 `ls.wrapEvaluator()`。这使得 LLM 裁判调用与测试用例的其余部分分开跟踪，以避免混乱，并方便地创建反馈（如果被包装函数的返回值匹配 `{ key: string; score: number | boolean }`）。在这种情况下，评估器跟踪将不会显示在主要的测试用例运行中，而是在与 `correctness` 反馈键关联的跟踪中显示。

您可以通过单击 UI 中相应的反馈芯片在 LangSmith 中看到评估器运行情况。

## 对一个测试用例运行多个示例

您可以使用 `ls.test.each()` 将相同的测试用例应用于多个示例并参数化您的测试。当您想使用相同的方式针对不同输入评估您的应用程序时，这很有用：

```typescript
import * as ls from "langsmith/vitest";
// import * as ls from "langsmith/jest";

const DATASET = [
  {
    inputs: { userQuery: "whats up" },
    referenceOutputs: { sql: "sorry that is not a valid query" }
  },
  {
    inputs: { userQuery: "what color is the sky?" },
    referenceOutputs: { sql: "sorry that is not a valid query" }
  },
  {
    inputs: { userQuery: "how are you today?" },
    referenceOutputs: { sql: "sorry that is not a valid query" }
  }
];

ls.describe("生成 sql 示例", () => {
  ls.test.each(DATASET)(
    "offtopic inputs",
    async ({ inputs, referenceOutputs }) => {
      ...
    },
  );
});
```

如果您启用了跟踪，本地数据集中的每个示例都将被同步到 LangSmith 中创建的相应示例。

## 记录输出

每次运行测试时，我们都会将其同步到一个数据集示例并将其跟踪为一个运行。要跟踪运行的最终输出，您可以使用 `ls.logOutputs()`，如下所示：

```typescript
import * as ls from "langsmith/vitest";
// import * as ls from "langsmith/jest";

ls.describe("生成 sql 示例", () => {
  ls.test(
    "offtopic input",
    {
      inputs: { userQuery: "..." },
      referenceOutputs: { sql: "..." }
    },
    async ({ inputs, referenceOutputs }) => {
      ls.logOutputs({ sql: "SELECT * FROM users;" })
    },
  );
});
```

记录的输出将显示在您的报告器摘要和 LangSmith 中。

您也可以直接从测试函数返回一个值：

```typescript
import * as ls from "langsmith/vitest";
// import * as ls from "langsmith/jest";

ls.describe("生成 sql 示例", () => {
  ls.test(
    "offtopic input",
    {
      inputs: { userQuery: "..." },
      referenceOutputs: { sql: "..." }
    },
    async ({ inputs, referenceOutputs }) => {
      return { sql: "SELECT * FROM users;" }
    },
  );
});
```

但是请记住，如果由于断言失败或其他错误导致测试未能完成，您的输出将不会出现。

## 跟踪中间调用

LangSmith 将自动跟踪在测试用例执行过程中发生的任何可跟踪的中间调用。

## 聚焦或跳过测试

您可以将 Vitest/Jest 的 `.skip` 和 `.only` 方法链接到 `ls.test()` 和 `ls.describe()`：

```typescript
import * as ls from "langsmith/vitest";
// import * as ls from "langsmith/jest";

ls.describe("生成 sql 示例", () => {
  ls.test.skip(
    "offtopic input",
    {
      inputs: { userQuery: "..." },
      referenceOutputs: { sql: "..." }
    },
    async ({ inputs, referenceOutputs }) => {
      return { sql: "SELECT * FROM users;" }
    },
  );
  ls.test.only(
    "other",
    {
      inputs: { userQuery: "..." },
      referenceOutputs: { sql: "..." }
    },
    async ({ inputs, referenceOutputs }) => {
      return { sql: "SELECT * FROM users;" }
    },
  );
});
```

## 配置测试套件

您可以通过向 `ls.describe()` 传递一个额外参数来配置测试套件（例如元数据或自定义客户端），或者通过向 `ls.test()` 传递一个 `config` 字段来配置单个测试中的测试：

```typescript
ls.describe("test suite name", () => {
  ls.test(
    "test name",
    {
      inputs: { ... },
      referenceOutputs: { ... },
      // 额外的测试运行配置
      config: { tags: [...], metadata: { ... } }
    },
    {
      name: "test name",
      tags: ["tag1", "tag2"],
      skip: true,
      only: true,
    }
  );
}, {
  testSuiteName: "overridden value",
  metadata: { ... },
  // 自定义客户端
  client: new Client(),
});
```

测试套件还将自动从 `process.env.ENVIRONMENT`、`process.env.NODE_ENV` 和 `process.env.LANGSMITH_ENVIRONMENT` 中提取环境变量，并将它们设置为创建的实验的元数据。然后，您可以在 LangSmith UI 中的元数据下筛选实验。

有关配置选项的完整列表，请参阅[API 参考](/reference/js/functions/vitest.describe)。

## 仅运行模式 (Dry-run mode)

如果您想在不将结果同步到 LangSmith 的情况下运行测试，您可以设置（省略）LangSmith 跟踪环境变量，或在环境中设置 `LANGSMITH_TEST_TRACKING=false`。

测试将像往常一样运行，但实验日志不会发送到 LangSmith。
