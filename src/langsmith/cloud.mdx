**云服务 (Cloud)** 选项是一种完全托管的模型，其中 LangChain 托管并运营所有 LangSmith 基础设施和服务：

- **完全托管的基础设施**: LangChain 负责处理所有基础设施、更新、扩展和维护工作。
- **从 GitHub 部署**: 连接您的仓库，只需点击几下即可完成部署。
- **自动化的 CI/CD**: 构建过程由平台自动处理。
- **LangSmith UI**: 完全访问 [可观测性](/langsmith/observability)、[评估](/langsmith/evaluation)、[部署管理](/langsmith/deployments) 和 [Studio](/langsmith/studio)。

| | **谁来管理** | **运行位置** |
|---|---|---|
| **LangSmith 平台 (UI, API, 数据存储)** | LangChain | LangChain 的云端 |
| **您的 Agent 服务器** | LangChain | LangChain 的云端 |
| **应用的 CI/CD** | LangChain | LangChain 的云端 |

![Cloud deployment: LangChain hosts and manages all components including the UI, APIs, and your Agent Servers.](/langsmith/images/langgraph-cloud-architecture.png)

## 开始使用

要将您的第一个应用程序部署到云服务，请遵循 [Cloud 部署快速入门](/langsmith/deployment-quickstart) 或参阅 [全面的设置指南](/langsmith/deploy-to-cloud)。

## 云架构和可扩展性

<Note>
本节仅与 [https://smith.langchain.com](https://smith.langchain.com) 和 [https://eu.smith.langchain.com](https://eu.smith.langchain.com) 上可用的云托管 LangSmith 服务相关。

关于自托管 LangSmith 解决方案的信息，请参阅 [自托管文档](/langsmith/self-hosted)。
</Note>

LangSmith 部署在 Google Cloud Platform (GCP) 上，设计目标是实现高度可扩展性。许多客户在 LangSmith 上运行生产工作负载，用于 LLM 应用的可观测性、评估和代理部署。

### 架构

基于美国的 LangSmith 服务部署在 GCP 的 `us-central1` (爱荷华) 区域。

<Note>
欧盟托管的 LangSmith 服务（[https://eu.smith.langchain.com](https://eu.smith.langchain.com)）现已可用（截至 2024 年 7 月中旬），并已部署在 GCP 的 `europe-west4` (荷兰) 区域。如果您对此区域的企业计划感兴趣，请 [联系我们的销售团队](https://www.langchain.com/contact-sales)。
</Note>

#### GCP 服务

LangSmith 由以下服务组成，所有这些服务都部署在 Google Kubernetes Engine (GKE) 上：

* LangSmith 前端 (Frontend): 提供 LangSmith 用户界面 (UI)。
* LangSmith 后端 (Backend): 提供 LangSmith API。
* LangSmith 平台后端 (Platform Backend): 处理身份验证和其他高频任务。（内部服务）
* LangSmith 游乐场 (Playground): 处理将请求转发到各种 LLM 提供商的功能。
* LangSmith 队列 (Queue): 处理异步任务的执行。（内部服务）

LangSmith 使用以下 GCP 存储服务：

* Google Cloud Storage (GCS)，用于存储运行的输入和输出。
* Google Cloud SQL PostgreSQL，用于事务性工作负载。
* Google Cloud Memorystore for Redis，用于队列和缓存。
* 部署在 GCP 上的 Clickhouse Cloud，用于追踪数据的摄取和分析。我们的服务通过私有端点连接到托管在同一 GCP 区域的 Clickhouse Cloud。

我们使用的一些附加 GCP 服务包括：

* Google Cloud Load Balancer，用于将流量路由到 LangSmith 服务。
* Google Cloud CDN，用于缓存静态资产。
* Google Cloud Armor，用于安全和速率限制。有关我们执行的速率限制的更多信息，请参阅 [本指南](/langsmith/administration-overview#rate-limits)。

### API 速率限制

LangSmith 对 API 端点实施速率限制，以确保服务的稳定性和公平使用。下表显示了美国和欧盟地区不同端点的速率限制。请注意：

- 速率限制的表示方式是 `计数 / 间隔`，其中计数是允许的请求数，间隔是时间（秒）。例如，`2000 / 10` 表示每 10 秒允许 2000 个请求。
- 当端点列中未指定 HTTP 方法时，速率限制适用于所有 HTTP 方法。
- 当指定特定方法（如 `POST`, `GET`）时，速率限制仅适用于该方法。

#### 速率限制类别

- **高吞吐量 (High throughput)**: 核心操作（如身份验证、元数据和反馈）的一般高容量端点。
- **仓库 (Repository)**: 仓库和提示管理操作。
- **运行数据摄取 (Run ingest)**: 用于可观测性的单个追踪/运行数据摄取端点。
- **图表 (Charts)**: 图表生成和可视化端点。
- **多部分数据摄取 (Multipart ingest)**: 通过多部分上传进行的大批量运行数据摄取。
- **运行查询 (API) (Run query (API))**: 使用 API 密钥的运行查询操作，限制更严格，用于复杂查询。
- **运行查询 (用户) (Run query (User))**: 使用用户身份的运行查询操作，限制更高，用于交互式使用。
- **生成 (Generation)**: 人工智能驱动的代码和内容生成端点（限制以防止滥用）。
- **提交 (Commits)**: 提示版本控制和提交操作。
- **删除 (Deletion)**: 会话删除和工作流触发操作。
- **运行查找 (Run lookup)**: 按 UUID 检索特定运行。
- **示例 (Examples)**: 获取用于少样本提示的数据集示例。
- **默认 (API 密钥) (Default (API key))**: 匹配到特定模式以外的已认证 API 请求的默认速率限制。
- **默认 (用户) (Default (User))**: 匹配到特定模式以外的已认证用户请求的默认速率限制。
- **公共下载 (Public download)**: 用于共享资源的大容量公共下载端点。
- **统计数据 (Stats)**: 运行统计数据和分析端点（适用区域特定的限制）。
- **公共 (Catch-all) (Public (catch-all))**: 未经身份验证的公共访问的默认速率限制。

有关速率限制和其他服务限制的更多信息，请参阅 [管理概览](/langsmith/administration-overview#rate-limits)。
