传统的软件应用是通过编写代码构建的，而 AI 应用的逻辑往往来源于提示（Prompts）。

本指南将带您了解 LangSmith 中提示工程的关键概念。

## 为什么需要提示工程？

提示为模型设定了一个场景，就像即兴表演秀中的观众指导演员接下来的表演一样——它指导了模型行为，但并未改变其底层能力。正如告诉演员“扮演一个海盗”会决定他们的表演方式一样，提示提供了指令、示例和上下文，从而塑造模型的响应方式。

提示工程很重要，因为它让您能够改变模型的行为方式。虽然还有其他改变模型行为的方法（例如微调 Fine-tuning），但提示工程通常是最简单的入门方式，并且往往能带来最高的投资回报率（ROI）。

我们通常发现提示工程是多学科交叉的。有时，最棒的提示工程师不是构建应用的软件工程师，而是产品经理或其他领域专家。因此，拥有支持这种跨学科构建的适当工具和基础设施非常重要。

## 提示 vs. 提示模板

尽管我们经常互换使用这些术语，但理解“提示 (Prompts)”和“提示模板 (Prompt Templates)”之间的区别很重要。

**提示**指的是传入语言模型的那些消息（Messages）。

**提示模板**指的是格式化信息的一种方式，目的是让该提示能够容纳您想要的信息。提示模板可以包含用于少样本示例（few shot examples）、外部上下文或提示中所需的任何其他外部数据的变量。

![](/langsmith/images/prompt-vs-prompt-template.png)

## LangSmith 中的提示

您可以在 LangSmith 中存储和版本化提示模板。要理解提示模板，需要了解几个关键方面。

### 聊天 vs. 补全（Chat vs. Completion）

有两种不同类型的提示：`chat` 风格提示和 `completion` 风格提示。

`Chat` 风格提示是**一系列消息（a list of messages）**。这是当今大多数模型 API 支持的提示风格，因此通常应该优先使用它。

`Completion` 风格提示**仅是一个字符串**。这是一种较旧的提示风格，所以它主要出于遗留原因而存在。

### F-string vs. Mustache

您可以使用 [f-string](https://realpython.com/python-f-strings/) 或 [Mustache](https://mustache.github.io/mustache.5.html) 格式，利用输入变量格式化您的提示。以下是一个使用 f-string 格式的示例提示：

```python
Hello, {name}!
```

以下是一个使用 Mustache 的示例：

```python
Hello, {{name}}!
```

要添加一个条件性的 Mustache 提示：

```python
{{#is_logged_in}}  Welcome back, {{name}}!{{else}}  Please log in.{{/is_logged_in}}
```

* Playground UI 会识别出 `is_logged_in` 变量，但任何嵌套的变量都需要您自己指定。请在输入（inputs）中粘贴以下内容，以确保上述条件提示能够正常工作：

```json
{  "name": "Alice"}
```

<Check>
LangSmith Playground 默认使用 `f-string` 作为模板格式，但您可以在提示设置/模板格式部分切换到 `mustache` 格式。`Mustache` 在处理条件变量、循环和嵌套键方面为您提供了更大的灵活性。对于条件变量，您需要在“输入 (inputs)”部分手动添加 JSON 变量。请阅读 [文档](https://mustache.github.io/mustache.5.html)
</Check>

### 工具（Tools）

工具是 LLM 可以用来与外部世界交互的接口。工具由名称、描述以及用于调用该工具的参数的 JSON 模式（JSON schema）组成。

### 结构化输出（Structured output）

结构化输出是大多数最先进 LLM 的一个特性，即它们不会产生纯文本（raw text）作为输出，而是遵循指定的模式（schema）。这可能涉及底层使用 [工具](#tools)，也可能不涉及。

<Check>
结构化输出与工具类似，但在几个关键方面有所不同。在使用工具时，LLM 选择调用哪个工具（或者可能选择不调用任何工具）；而在使用结构化输出时，LLM **总是**以这种格式响应。使用工具时，LLM 可能会选择**多个**工具；而结构化输出只生成一个响应。
</Check>

### 模型（Model）

您可以选择将模型配置与提示模板一起存储。这包括模型名称以及任何其他参数（如 temperature 调温器等）。

## 提示版本控制（Prompt versioning）

版本控制是迭代和协作处理不同提示的关键部分。

### 提交（Commits）

保存提示的每一次更新都会创建一个带有唯一提交哈希（commit hash）的新提交。这使您能够：

- 查看提示更改的完整历史记录。
- 审查早期版本。
- 如果需要，恢复到先前状态。
- 在代码中引用特定版本，使用提交哈希（例如：`client.pull_prompt("prompt_name:commit_hash")`）。

在 UI 中，您可以在 **Commits** 标签页的右上角切换 **Show diff**（显示差异），将一次提交与其前一个版本进行比较。

![The commit hashes list for a prompt with the diff of one commit.](/langsmith/images/commit-diff.png)

### 标签（Tags）

提交标签（Commit tags）是指向您提示历史中特定提交的人类可读的标签。与提交哈希不同，标签可以移动到指向不同的提交，从而允许您在不更改代码的情况下更新代码所引用的版本。

提交标签的用例包括：

- **环境特定的标签**：为 `production` 或 `staging` 环境标记提交，这允许您在不更改代码的情况下切换不同版本。
- **版本控制**：标记稳定的提示版本，例如 `v1`、`v2`，这使您能够在代码中引用特定版本并跟踪随时间的变化。
- **协作**：标记准备好审查的版本，这使您能够与协作者共享特定版本并获取反馈。

<Note>
**不要与资源标签混淆**：提交标签引用特定的提示版本。[资源标签](/langsmith/set-up-resource-tags) 是用于组织工作区资源的键值对。
</Note>

有关创建和管理提交标签的详细信息，请参阅 [管理提示](/langsmith/manage-prompts#commit-tags)。

## 提示 Playground

提示 Playground 使迭代和测试提示的过程变得无缝。您可以从侧边栏或直接从保存的提示进入 Playground。

在 Playground 中，您可以：

* 更改正在使用的模型
* 更改正在使用的提示模板
* 更改输出模式（schema）
* 更改可用的工具
* 输入输入变量以通过提示模板运行
* 通过模型运行提示
* 观察输出结果

## 测试多个提示

## 基于数据集进行测试

要基于数据集进行测试，只需在右上角选择数据集并按下 **Start**（开始）。您可以修改结果是否被流式传输（streamed back）以及测试的重复次数。

![](/langsmith/images/test-over-dataset-in-playground.gif)

您可以点击 “View Experiment”（查看实验）按钮，深入了解测试结果。
