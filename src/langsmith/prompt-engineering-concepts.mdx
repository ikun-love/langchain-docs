传统软件应用程序是通过编写代码构建的，而 AI 应用的逻辑则通常来源于**提示（Prompts）**。

本指南将带您了解 LangSmith 中提示工程的关键概念。

## 为什么需要提示工程？

提示为模型“设定了舞台”，就像即兴表演节目中的观众指导演员接下来的表演一样——它指导了模型的行为，而无需更改其底层的能力。正如告诉演员“扮演一个海盗”会决定其行为方式一样，提示提供了指令、示例和上下文，从而塑造模型的响应方式。

提示工程之所以重要，是因为它允许您改变模型的行为方式。虽然改变模型行为还有其他方法（例如微调/Fine-tuning），但提示工程通常是最容易上手的，并且通常能带来最高的投资回报率（ROI）。

我们通常会发现提示工程是多学科交叉的。有时，最优秀的提示工程师不是构建应用程序的软件工程师，而是产品经理或其他领域专家。因此，拥有支持这种跨学科构建的恰当工具和基础设施非常重要。

## 提示（Prompts）与提示模板（Prompt Templates）

尽管我们经常互换使用这两个术语，但了解“提示”和“提示模板”之间的区别很重要。

**提示（Prompts）**：指的是传递给语言模型的具体消息内容。

**提示模板（Prompt Templates）**：指的是一种格式化信息的方式，旨在让提示包含您需要的信息。提示模板可以包含用于少样本示例（few shot examples）、外部上下文或提示中所需的任何其他外部数据的**变量**。

## LangSmith 中的提示

您可以在 LangSmith 中存储和版本化提示模板。了解提示模板的几个关键方面很重要。

### 聊天（Chat）与补全（Completion）

提示有两种不同的类型：`chat` 风格的提示和 `completion` 风格的提示。

`Chat` 风格的提示是**消息列表**。这是当今大多数模型 API 所支持的提示风格，因此通常应优先使用。

`Completion` 风格的提示只是一个**字符串**。这是一种较旧的提示风格，因此主要出于遗留原因而存在。

### F-string 与 Mustache

您可以使用 [f-string](https://realpython.com/python-f-strings/) 或 [mustache](https://mustache.github.io/mustache.5.html) 格式，使用输入变量来格式化您的提示。下面是一个使用 f-string 格式的示例提示：

```python
Hello, {name}!
```

下面是一个使用 mustache 格式的示例：

```python
Hello, {{name}}!
```

要添加一个条件性的 mustache 提示：

```python
{{#is_logged_in}}  Welcome back, {{name}}!{{else}}  Please log in.{{/is_logged_in}}
```

* 游乐场（Playground）用户界面会识别 `is_logged_in` 变量，但任何嵌套的变量需要您自己指定。请将以下内容粘贴到输入中，以确保上述条件提示能够正常工作：

```json
{  "name": "Alice"}
```

<Check>
LangSmith 游乐场默认使用 `f-string` 作为模板格式，但您可以在提示设置/模板格式部分切换到 `mustache` 格式。`mustache` 为您提供了更多关于条件变量、循环和嵌套键的灵活性。对于条件变量，您需要在“输入（inputs）”部分手动添加 JSON 变量。请阅读 [文档](https://mustache.github.io/mustache.5.html)。
</Check>

### 工具（Tools）

工具是 LLM 可以用来与外部世界交互的接口。工具包括名称、描述以及用于调用该工具的参数的 **JSON 模式（schema）**。

### 结构化输出（Structured output）

结构化输出是大多数最先进 LLM 的一项功能，即模型不会产生原始文本作为输出，而是遵循指定的**模式（schema）**。这可能（或不使用）[工具](#tools)作为底层机制。

<Check>
结构化输出与工具类似，但在几个关键方面有所不同。在使用工具时，LLM 选择调用哪个工具（或者可能选择不调用任何工具）；而使用结构化输出时，LLM **总是**以这种格式响应。在使用工具时，LLM 可能会选择**多个**工具；而在结构化输出中，只生成一个响应。
</Check>

### 模型（Model）

您可以选择将模型配置与提示模板一起存储。这包括模型名称以及任何其他参数（如 temperature 等）。

## 提示版本控制（Prompt versioning）

版本控制是迭代和协作处理不同提示的关键部分。

### 提交（Commits）

每一次保存对提示的更新，都会创建一个带有唯一提交哈希（commit hash）的新**提交（commit）**。这使您能够：

- 查看提示更改的完整历史记录。
- 审查早期版本。
- 根据需要恢复到以前的状态。
- 在代码中使用提交哈希引用特定版本（例如 `client.pull_prompt("prompt_name:commit_hash")`）。

在用户界面中，您可以通过切换“提交（Commits）”选项卡右上角的 **Show diff**（显示差异）来比较当前提交与其前一个版本。

![The commit hashes list for a prompt with the diff of one commit.](/langsmith/images/commit-diff.png)

### 标签（Tags）

提交标签是**人类可读的标签**，指向提示历史记录中的特定提交。与提交哈希不同，标签可以移动到指向不同的提交，从而允许在不更改代码本身的情况下更新代码引用的版本。

提交标签的用例包括：

- **环境特定标签**：为 `production`（生产环境）或 `staging`（暂存环境）环境标记提交，这使得您可以在不更改代码的情况下切换不同版本。
- **版本控制**：标记稳定的提示版本，例如 `v1`、`v2`，这使得您可以在代码中引用特定版本并跟踪随时间的变化。
- **协作**：标记已准备好进行审查的版本，从而可以与协作者共享特定版本并获得反馈。

<Note>
**不要与资源标签混淆**：提交标签引用特定的提示版本。[资源标签](/langsmith/set-up-resource-tags) 是用于组织工作区资源的键值对。
</Note>

有关创建和管理提交标签的详细信息，请参阅 [管理提示](/langsmith/manage-prompts#commit-tags)。

## 提示游乐场（Prompt playground）

提示游乐场使迭代和测试提示的过程变得无缝顺畅。您可以从侧边栏或直接从保存的提示进入游乐场。

在游乐场中，您可以：

* 更改正在使用的模型
* 更改正在使用的提示模板
* 更改输出模式（Schema）
* 更改可用的工具
* 输入输入变量以通过提示模板运行
* 通过模型运行提示
* 观察输出结果

<Callout type="info" icon="bird">
在游乐场中使用 **[Polly](/langsmith/polly)** 来优化提示、生成工具和使用 AI 辅助创建输出模式。
</Callout>

## 基于数据集进行测试

要基于数据集进行测试，只需在右上角选择数据集并按下“Start”（开始）即可。您可以修改结果是否被流式传输（streamed back）以及测试中的重复次数。

![](/langsmith/images/test-over-dataset-in-playground.gif)

您可以点击“View Experiment”（查看实验）按钮，深入了解测试结果。
