LangSmith 支持从单体仓库（Monorepo）结构中部署 Agent。在这种结构下，您的 Agent 代码可能依赖于位于仓库其他位置的共享包。本指南将向您展示如何构建 Monorepo 的结构，并配置 `langgraph.json` 文件以使其能够使用这些共享依赖项。

## 仓库结构

有关完整的可工作示例，请参阅：
- [Python monorepo 示例](https://github.com/langchain-ai/python-langraph-monorepo-example)
- [JS monorepo 示例](https://github.com/langchain-ai/js-langgraph-monorepo-example)

<CodeGroup>
```text Python
my-monorepo/
├── shared-utils/           # 共享的 Python 包
│   ├── __init__.py
│   ├── common.py
│   └── pyproject.toml      # 或 setup.py
├── agents/
│   └── customer-support/   # Agent 目录
│       ├── agent/
│       │   ├── __init__.py
│       │   └── graph.py
│       ├── langgraph.json  # 位于 Agent 目录下的配置文件
│       ├── .env
│       └── pyproject.toml  # Agent 的依赖项
└── other-service/
    └── ...
```
```text JS
my-monorepo/
├── package.json            # 包含 workspaces 的根 package.json
├── shared-utils/           # 共享的 TypeScript 包
│   ├── package.json
│   ├── src/
│   │   └── index.ts
│   └── tsconfig.json
├── agents/
│   └── customer-support/   # Agent 目录
│       ├── src/
│       │   └── agent.ts
│       ├── langgraph.json  # 位于 Agent 目录下的配置文件
│       ├── package.json    # Agent 的依赖项
│       ├── .env
│       └── tsconfig.json
└── other-service/
    └── ...
```
</CodeGroup>

## LangGraph.json 配置

将 `langgraph.json` 文件放置在 Agent 的目录中（而不是 Monorepo 的根目录）。请确保该文件遵循要求的结构：

<CodeGroup>
```json Python
{
  "dependencies": [
    ".",                    # 当前的 Agent 包
    "../../shared-utils"    # 指向共享包的相对路径
  ],
  "graphs": {
    "customer_support": "./agent/graph.py:graph"
  },
  "env": ".env"
}
```
```json JS
{
  "node_version": "20",
  "graphs": {
    "customer_support": "./src/agent.ts:graph"
  },
  "env": ".env"
}
```
</CodeGroup>

Python 实现通过以下方式自动处理父目录中的包：
- 检测以 `"."` 开头的相对路径。
- 根据需要将父目录添加到 Docker 构建上下文中。
- 同时支持真正的包（带有 `pyproject.toml`/`setup.py`）和简单的 Python 模块。

对于 JavaScript Monorepos：
- 共享的工作区依赖项会由您的包管理器自动解析。
- 您的 `package.json` 应该使用工作区语法引用共享包。

Agent 目录中 `package.json` 的示例：
```json
{
  "name": "customer-support-agent",
  "dependencies": {
    "@company/shared-utils": "workspace:*",
    "@langchain/langgraph": "^0.2.0"
  }
}
```

## 构建应用程序

运行 `langgraph build` 命令：

<CodeGroup>
```bash Python
cd agents/customer-support
langgraph build -t my-customer-support-agent
```
```bash JS
# 从 Monorepo 的根目录运行
langgraph build -t my-customer-support-agent -c agents/customer-support/langgraph.json --build-command "yarn run turbo build" --install-command "yarn install"
```
</CodeGroup>

Python 构建过程：
1. 自动检测相对依赖路径。
2. 将共享包复制到 Docker 构建上下文中。
3. 按正确的顺序安装所有依赖项。
4. 不需要特殊的标志或命令。

JavaScript 构建过程：
1. 使用您运行 `langgraph build` 的目录（在本例中为 Monorepo 根目录）作为构建上下文。
2. 自动检测您的包管理器（yarn, npm, pnpm, bun）。
3. 运行适当的安装命令。
    - 如果您有一个或两个自定义的构建/安装命令，它将从您运行 `langgraph build` 的目录中执行这些命令。
    - 否则，它将从 `langgraph.json` 文件所在的目录中执行。
4. 可选：从 `langgraph.json` 文件所在的目录运行自定义构建命令（仅当您传递 `--build-command` 标志时）。

## 技巧和最佳实践

1. **将 Agent 配置放在 Agent 目录中**：将 `langgraph.json` 文件放置在特定的 Agent 目录中，而不是 Monorepo 的根目录。这使您能够在同一个 Monorepo 中支持多个 Agent，而无需在同一个 LangSmith 部署中部署它们。

2. **Python 使用相对路径**：对于 Python Monorepos，在 `dependencies` 数组中使用相对路径，例如 `"../../shared-package"`。

3. **利用 JS 的工作区功能**：对于 JavaScript/TypeScript，请使用包管理器的*工作区*功能来管理包之间的依赖关系。

4. **首先在本地测试**：在部署之前，始终在本地测试您的构建，以确保所有依赖项都已正确解析。

5. **环境变量**：将环境变量文件（`.env`）保留在 Agent 目录中，以进行特定于环境的配置。
