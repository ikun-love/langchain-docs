Insights Agent 会自动分析您的追踪记录（traces），以检测使用模式、常见的 Agent 行为和失败模式——而无需您手动审查数千条追踪记录。
Insights 使用分层分类法来理解您的数据，并突出显示可操作的趋势。

<Note>
Insights 适用于 LangSmith Plus 和 Enterprise [套餐](https://www.langchain.com/pricing)，并且仅适用于 LangSmith SaaS 部署。
</Note>

## 先决条件

- OpenAI API 密钥（请在此处 [生成](https://platform.openai.com/account/api-keys)）或 Anthropic API 密钥（请在此处 [生成](https://console.anthropic.com/settings/keys)）
- 在 LangSmith 中创建规则的权限（生成新的 Insights 报告所需）
- 查看 LangSmith 追踪项目的权限（查看现有 Insights 报告所需）

## 生成您的第一个 Insights 报告

<Frame caption="Insights Agent 的自动配置流程"><img src="/langsmith/images/insights-autogenerate-config.png" /> </Frame>

#### 从 [LangSmith UI](https://smith.langchain.com) 进行操作：

1. 在左侧菜单中导航至 **Tracing Projects**（追踪项目），然后选择一个追踪项目。
2. 在右上角点击 **+New**（新建），然后选择 **New Insights Report**（新建 Insights 报告）以针对该项目生成新的洞察。
3. 为您的作业输入一个名称。
4. 点击作业创建窗格右上角的 <Icon icon="key" /> 图标，将您的 OpenAI（或 Anthropic）API 密钥设置为 [工作区秘密（workspace secret）](/langsmith/administration-overview#workspaces)。如果您的工作区已设置 OpenAI API 密钥，则可以跳过此步骤。
5. 回答引导式问题，将您的 Insights 报告集中在您想了解有关 Agent 的内容上，然后点击 **Run job**（运行作业）。

<Tip>切换到 Manual 模式以尝试针对常见用例的[预构建配置（prebuilt configs）](#using-a-prebuilt-config) 或[从头开始构建配置（build your own）](#building-a-config-from-scratch)。</Tip>

这将启动一个后台的 Insights 报告生成过程。报告可能需要长达 30 分钟才能完成。

#### 从 [LangSmith SDK](https://reference.langchain.com/python/langsmith/observability/sdk/client/#langsmith.client.Client) 进行操作：
您可以使用 Python SDK 对存储在 LangSmith 之外的数据生成 Insights 报告。这使您能够分析来自生产系统、日志或其他来源的聊天历史记录。

当您调用 `generate_insights()` 时，SDK 将会：
1. 将您的聊天历史记录作为追踪记录上传到一个新的 LangSmith 项目中
2. 在这些上传的追踪记录上生成一个 Insights 报告
3. 返回一个指向 LangSmith UI 中结果的链接

<CodeGroup>

```python Python
import os
from langsmith import Client

client = Client()

chat_histories = [
    [
        {"role": "user", "content": "how are you"},
        {"role": "assistant", "content": "good!"},
    ],
    [
        {"role": "user", "content": "do you like art"},
        {"role": "assistant", "content": "only Tarkovsky"},
    ],
]

report = client.generate_insights(
    chat_histories=chat_histories,
    name="Customer Support Topics - March 2024",
    instructions="What are the main topics and questions users are asking about?",
    openai_api_key=os.environ["OPENAI_API_KEY"],  # optional if already set as workspace secret
)

# client.poll_insights(report=report)
```


</CodeGroup>

<Note>使用 OpenAI 模型对 1,000 个对话串（threads）生成洞察的费用通常约为 \$1.00-\$2.00，使用当前的 Anthropic 模型约为 \$3.00-\$4.00。成本与采样的对话串数量和每个对话串的大小成正比。</Note>


## 理解结果
一旦您的作业完成，您就可以导航到 **Insights**（洞察）选项卡，在那里您将看到一个 Insights 报告的表格。每个报告都包含对特定追踪样本生成的洞察信息。

<Frame caption="单个追踪项目的 Insights 报告"><img src="/langsmith/images/insights-job-results.png" /> </Frame>

点击进入您的作业，您将看到按一组自动生成的类别组织的追踪记录。
您可以深入研究类别和子类别，以查看底层追踪记录、反馈和运行统计数据。

<Frame caption="与 https://chat.langchain.com 聊天机器人对话的常见主题"><img src="/langsmith/images/insights-nav.gif" /> </Frame>

### 执行摘要
在每个报告的顶部，您会找到一个执行摘要，其中会浮现所发现的最重要的模式。这包括：

- 关键发现，带有百分比，显示每种模式出现的频率。
- 可点击的引用（例如 #1、#2、#3），指向 Agent 识别为与您的问题特别相关的追踪记录。

<Frame caption="显示带有追踪记录引用的关键模式的执行摘要"><img src="/langsmith/images/insights-summary.png" /> </Frame>


### 顶级类别
您的追踪记录会自动分组到代表数据中最广泛模式的顶级类别中。

分布条形图显示了每种模式出现的频率，使您可以轻松发现发生频率高于或低于预期的行为。

每个类别都有简短的描述，并显示其中包含的追踪记录的聚合指标，包括：
- 典型的追踪统计数据（如错误率、延迟、成本）
- 来自评估器的反馈分数
- 在作业过程中提取的 [属性（Attributes）](#attributes)

### 子类别
点击任何类别会显示细分到子类别的视图，从而让您对该类别追踪记录中的交互模式有更细粒度的了解。

在上述 [Chat Langchain](https://chat.langchain.com) 示例中，在“数据与检索 (Data & Retrieval)”下，存在“向量存储 (Vector Stores)”和“数据摄取 (Data Ingestion)”等子类别。

### 单个追踪记录
您可以通过点击进入追踪记录表来查看分配给每个类别或子类别的追踪记录。从那里，您可以点击任何追踪记录以查看完整的对话详情。

## 配置作业
您可以通过三种方式创建 Insights 报告。首先使用自动生成流程启动基线，然后随着您的完善，使用保存的或手动配置进行迭代。

### 自动生成配置
1. 打开 **New Insights**（新建洞察），并确保 **Auto**（自动）切换按钮处于激活状态。
2. 回答有关 Agent 目的、您想了解的内容以及追踪记录的结构等自然语言问题。Insights 会将您的答案转换为草稿配置（作业名称、摘要提示、属性和采样默认值）。
3. 选择一个提供商，然后点击 **Generate config**（生成配置）进行预览或点击 **Run job**（运行作业）立即启动。

**提供有用的上下文**

为获得最佳结果，请为每个提示撰写一两句话，为 Agent 提供它需要的上下文——您试图了解的内容、哪些信号或字段最重要，以及您已经知道哪些信息不重要。您对 Agent 的功能及其追踪记录结构描述得越清晰，Insights Agent 就能以与您推理数据的方式更具体、更具操作性并更一致的方式来分组示例。

**描述您的追踪记录**

解释您的数据是如何组织的——它们是单次运行还是多轮对话？哪些输入和输出包含关键信息？这有助于 Insights Agent 生成关注重点的摘要提示和属性。如果需要，您也可以直接在 [摘要提示](#summary-prompt) 部分指定变量。

### 选择模型提供商

您可以选择 OpenAI 或 Anthropic 模型来驱动 Agent。对于选择的提供商（`OPENAI_API_KEY` 或 `ANTHROPIC_API_KEY`），您必须设置相应的 [工作区秘密](/langsmith/administration-overview#workspaces)。

请注意，使用当前的 Anthropic 模型比使用 OpenAI 模型费用高出约 3 倍。

### 使用预构建配置

<Frame caption="Manual 模式下的预构建配置"><img src="/langsmith/images/insights-manual-config.png" /> </Frame>

使用 **Saved configurations**（已保存的配置）下拉菜单加载常见作业（如**使用模式 (Usage Patterns)** 或**错误分析 (Error Analysis)**）的预设。您可以直接运行它们以快速开始，或者在保存自定义版本之前调整过滤器、提示和提供商。要了解您可以自定义哪些内容的更多信息，请阅读下面的部分。


### 从头开始构建配置
当您需要更多控制时（例如，预定义您希望数据分组的类别或定位与特定反馈分数和过滤器匹配的追踪记录），从头开始构建配置会很有帮助。

#### 选择追踪记录
- **Sample size**（样本大小）：要分析的最大追踪记录数。当前限制为 1,000
- **Time range**（时间范围）：从中采样追踪记录的时间范围
- **Filters**（过滤器）：额外的追踪记录过滤器。当您调整过滤器时，您会看到有多少追踪记录符合您的条件

#### 类别
默认情况下，顶级类别是根据底层追踪记录自下而上自动生成的。
在某些情况下，您事先知道特定的类别，并希望作业将追踪记录分桶到这些预定义的类别中。

配置的 **Categories**（类别）部分允许您通过列出所需顶级类别的名称和描述来实现这一点。
子类别仍然由算法在预定义的顶级类别内自动生成。

#### 摘要提示
作业的第一步是为每个追踪记录创建一个简短摘要——正是这些摘要随后被分类。
从摘要中提取正确的信息对于获得有用的类别至关重要。
可编辑用于生成这些摘要的提示。

在编辑提示时需要考虑两件事：
- 摘要说明：摘要中不存在的任何信息都不会影响所生成的类别，因此请确保提供清晰的说明，说明应从每个追踪记录中提取哪些信息。
- 追踪记录内容：使用胡须（mustache）格式指定每个追踪记录的哪些部分会传递给摘要器。包含大量输入和输出的大型追踪记录可能会产生高昂的成本和噪音。将提示减少到只包含追踪记录中最相关部分可以改善您的结果。

Insights Agent 会分析 [对话串（threads）](https://docs.langchain.com/langsmith/threads)——代表多轮对话的相关追踪记录组。您必须使用以下至少一个模板变量来指定应将对话串的哪些部分发送给摘要器：

| 变量 | 最适合 | 示例 |
| --- | --- | --- |
| run.* | 访问对话串中最近的根运行（即最后一轮）的数据 | `{{run.inputs}}` `{{run.outputs}}` `{{run.error}}`|

您也可以使用点表示法访问嵌套字段。例如，提示 `"Summarize this: {{run.inputs.foo.bar}}"` 将只包含最后一次运行的输入中 "foo" 值内的 "bar" 值。

#### 属性
除了摘要之外，您可以定义要从每个追踪记录中提取的其他分类、数值和布尔属性。
这些属性将影响分类步骤——属性值相似的追踪记录倾向于被归为一类。
您还可以查看每个类别的这些属性的聚合情况。

例如，您可能希望从每个追踪记录中提取属性 `user_satisfied: boolean`，以引导算法区分正面和负面的用户体验类别，并查看每个类别的平均用户满意度。

#### 过滤属性

您可以使用布尔属性上的 `filter_by` 参数在生成洞察之前预先过滤追踪记录。启用后，只有属性评估为 `true` 的追踪记录才会被包含在分析中。

当您想将 Insights 报告的重点放在特定子集的追踪记录时，这非常有用——例如，仅分析错误、仅检查英语对话，或仅包含满足特定质量标准的追踪记录。

<Frame caption="使用过滤属性仅针对具有 Agent 错误的追踪记录生成洞察"><img src="/langsmith/images/insights-filter-by-attribute.png" /> </Frame>

**工作原理：**
- 在为 Insights Agent 创建配置时，向任何布尔属性添加 `"filter_by": true`
- LLM 在摘要过程中评估每个追踪记录是否与属性描述匹配
- 属性值为 `false` 或缺失的追踪记录将在生成洞察之前被排除

## 保存配置

您可以通过使用“另存为 (save as)”按钮来选择保存配置以供将来使用。
如果您想随时间推移比较 Insights 报告以识别用户和 Agent 行为的变化，这尤其有用。

在创建新的 Insights 报告时，请从左上角窗格的下拉菜单中选择先前保存的配置。
