## 可观测性 (Observability)

### *我无法在 UI 中创建 API 密钥或管理用户，这是怎么回事？*

* 您很可能在部署 LangSmith 时没有设置 SSO（单点登录）。LangSmith 要求配置 SSO 才能管理用户和 API 密钥。您可以在 [配置部分](/langsmith/self-host-sso) 找到有关设置 SSO 的更多信息。

### *负载均衡/入口（Ingress）是如何工作的？*

* 您需要将前端容器/服务暴露给您的应用程序/用户。这将处理到所有下游服务的路由。
* 您需要在入口级别终止 SSL。我们建议使用托管服务，例如 AWS ALB、GCP Load Balancer 或 Nginx。

### *我们如何对应用程序进行身份验证？*

* 目前，我们的自托管解决方案支持将 OAuth2.0 和 OIDC 作为认证（Authn）解决方案的 SSO。请注意，我们确实提供了一个无需身份验证的解决方案，但强烈建议在投入生产环境之前设置 OAuth。

您可以在 [配置部分](/langsmith/self-host-sso) 找到有关设置 SSO 的更多信息。

### *我可以使用外部存储服务吗？*

* 您可以将 LangSmith 配置为使用所有存储服务的外部版本。在生产环境中，我们强烈建议使用外部存储服务。请查看 [配置部分](/langsmith/self-hosted) 了解更多信息。

### *我的应用程序正常运行需要出站（egress）连接吗？*

我们的部署仅在少数情况下需要出站连接（其中大部分可以位于您的 VPC 内部）：

* 拉取镜像（如果您镜像了镜像，则可能不需要此项）

* 与任何 LLM 端点通信

* 与您配置的任何外部存储服务通信

* 拉取 OAuth 信息

* 订阅指标和操作元数据（如果未在离线模式下运行）

  * 需要出站连接到 `https://beacon.langchain.com`
  * 有关更多信息，请参阅 [出站连接](/langsmith/self-host-egress)

您的 VPC 可以设置规则来限制任何其他访问。注意：我们要求允许将 `X-Organization-Id` 和 `X-Tenant-Id` 标头传递到后端服务。这些标头用于确定请求是针对哪个组织和工作区（先前称为“租户”）。

### *应用程序的资源要求是多少？*

* 在 Kubernetes 中，我们推荐在 [此处](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/examples/medium_size.yaml) 找到的最小 Helm 配置。对于 Docker，我们建议至少需要 16GB 内存和 4 个 CPU。
* 对于 Postgres，我们建议至少需要 8GB 内存和 2 个 CPU。
* 对于 Redis，我们建议 4GB 内存和 2 个 CPU。
* 对于 Clickhouse，我们建议 32GB 内存和 8 个 CPU。

### SAML SSO 常见问题

#### *如何更改 SAML SSO 用户的电子邮件地址？*

一些身份提供商（IdP）会在电子邮件更改时保留原始的 `User ID`，而另一些则不会。因此，我们建议您遵循以下步骤，以避免 LangSmith 中出现重复用户：

1. 从组织中移除该用户（请参阅 [此处](/langsmith/set-up-a-workspace#manage-users)）
2. 在 IdP 中更改他们的电子邮件地址
3. 让其通过 SAML SSO 再次登录 LangSmith —— 这将触发带有他们新电子邮件地址的常规 [JIT 预配](#just-in-time-jit-provisioning) 流程

目前不支持通过 SCIM 或其他方式更改具有多个关联登录方式的用户的电子邮件地址。系统会显示此错误消息：`email update not supported with linked login methods`（不支持更改链接了登录方式的用户的电子邮件地址）。例如，如果用户之前通过电子邮件/密码或 Google 社交登录，然后又使用相同的电子邮件地址通过 SSO 添加，则不支持更改其电子邮件地址。这同时适用于自托管和云部署。

#### *我能更换身份提供商吗？*

请联系 LangChain 支持团队 [support@langchain.dev](mailto:support@langchain.dev) 寻求迁移支持。

#### *如何修复“405 Method Not Allowed”（405 不允许此方法）错误？*

确保您使用的是正确的 ACS URL：[https://auth.langchain.com/auth/v1/sso/saml/acs](https://auth.langchain.com/auth/v1/sso/saml/acs)

### SCIM 常见问题

#### *我可以在没有 SAML SSO 的情况下使用 SCIM 吗？*

* **云端部署**：不可以，云端部署的 SCIM 必需 SAML SSO
* **自托管**：可以，SCIM 与带有 Client Secret 的 OAuth 身份验证模式兼容

#### *如果同时启用 JIT 预配和 SCIM 会发生什么？*

JIT 预配和 SCIM 可能会相互冲突。我们建议在启用 SCIM 之前禁用 JIT 预配，以确保一致的用户预配行为。

#### *如何更改用户的角色或工作区访问权限？*

在您的 IdP 中更新用户的组（Group）成员资格。更改将根据 [角色优先级规则](#role-precedence) 同步到 LangSmith。

#### *当用户从所有组中移除时会发生什么？*

用户将根据您的 IdP 中的预配设置从您的 LangSmith 组织中取消预配。

#### *我可以使用自定义组名称吗？*

可以。如果您的身份提供商支持将备用字段同步到 `displayName` 组属性，您可以使用备用属性（如 `description`）作为 LangSmith 中的 `displayName`，从而完全保留身份提供商组名称的自定义性。否则，组名称必须遵循 [组命名约定](#group-naming-convention) 部分中所述的特定命名约定，才能正确映射到 LangSmith 的角色和工作区。

#### *为什么我的 Okta 集成不起作用？*

请参阅 Okta 的故障排除指南：https://help.okta.com/en-us/content/topics/users-groups-profiles/usgp-group-push-troubleshoot.htm。

## 部署 (Deployment)

### 我可以使用 LangGraph 就必须使用 LangChain 吗？它们有什么区别？

不需要。LangGraph 是一个用于复杂智能体系统的编排框架，它比 LangChain 的智能体更底层、更具可控性。LangChain 提供了一个标准的接口来与模型和其他组件交互，适用于直接的链式调用和检索流程。

### LangGraph 与其他智能体框架有何不同？

其他智能体框架可能适用于简单、通用的任务，但在处理公司特定或复杂的任务时会显得力不从心。LangGraph 提供了一个更具表达力的框架，可以处理公司独有的任务，而不会限制用户只能使用单一的“黑盒”认知架构。

### LangGraph 会影响我应用程序的性能吗？

LangGraph 不会对您的代码增加任何开销，并且专为流式（streaming）工作流程而设计。

### LangGraph 是开源的吗？是免费的吗？

是的。LangGraph 是一个 MIT 许可的开源库，可以免费使用。

### LangGraph 和 LangSmith 有何不同？

LangGraph 是一个**有状态的编排框架**，为智能体工作流程带来了额外的控制力。LangSmith 是用于部署和扩展智能体应用程序的**服务**，提供用于构建智能体用户体验（UX）的特定于设计的 API，以及集成的开发者 UI。

| 特性 | LangGraph（开源） | LangSmith |
|---|---|---|
| 描述 | 用于智能体应用程序的有状态编排框架 | 用于部署 LangGraph 应用程序的可扩展基础设施 |
| SDK | Python 和 JavaScript | Python 和 JavaScript |
| HTTP API | 无 | 有 —— 适用于检索和更新状态、长期记忆或创建可配置的助手 |
| 流式传输 | 基础 | 用于逐个 token 消息的专用模式 |
| 检查点（Checkpointer） | 社区贡献 | 开箱即用支持 |
| 持久层 | 自我管理 | 托管的 Postgres 数据库，具有高效存储 |
| 部署 | 自我管理 | • 云端 <br /> • 免费自托管 <br /> • 企业版（付费自托管） |
| 可伸缩性 | 自我管理 | 任务队列和服务器的自动扩展 |
| 容错性 | 自我管理 | 自动重试 |
| 并发控制 | 简单线程 | 支持双向处理（Double-texting，此术语可能指某种并发处理机制） |
| 调度 | 无 | Cron 调度 |
| 监控 | 无 | 与 LangSmith 集成，实现可观测性 |
| IDE 集成 | Studio | Studio |

### LangSmith 是开源的吗？

不是。LangSmith 是专有软件。

有一个免费的自托管版本 LangSmith，可访问基本功能。云端部署选项和自托管部署选项是付费服务。[联系我们的销售团队](https://www.langchain.com/contact-sales) 了解详情。

有关更多信息，请参阅我们的 [LangSmith 定价页面](https://www.langchain.com/pricing)。

### LangGraph 是否适用于不支持工具调用的 LLM？

是的！您可以将 LangGraph 用于任何 LLM。我们主要使用支持工具调用的 LLM 的原因在于，这是让 LLM 就要做什么做出决定的最方便的方式。如果您的 LLM 不支持工具调用，您仍然可以使用它 —— 您只需编写一些逻辑，将原始 LLM 字符串响应转换为要执行的操作决策。

### LangGraph 是否适用于开源 LLM？

是的！LangGraph 对于底层使用的 LLM 完全是中立的。我们在大多数教程中使用闭源 LLM 的主要原因在于它们无缝支持工具调用，而开源 LLM 通常不支持。但工具调用不是必需的（参阅 [本节](#does-langgraph-work-with-llms-that-dont-support-tool-calling)），所以您完全可以使用 LangGraph 和开源 LLM。

### 我可以在不登录 LangSmith 的情况下使用 Studio 吗？

可以！您可以使用 [Agent Server 的开发版本](/langsmith/local-server) 在本地运行后端。
这将连接到作为 LangSmith 一部分的 Studio 前端。
如果您设置环境变量 `LANGSMITH_TRACING=false`，则不会有任何追踪信息发送到 LangSmith。

### 什么是 Agent Run（智能体运行）？

Agent Run 是通过 LangSmith Deployment 部署的 LangGraph 智能体的单次端到端调用。节点和子图不会单独收费。对其他 LangGraph 智能体的调用（通过 RemoteGraph、LangGraph SDK 或直接通过 API）将单独向托管被调用智能体的部署收费。为人机交互创建的中断，在恢复时会创建一个独立的 Agent Run。
