**控制平面** (Control Plane) 是 LangSmith 中用于管理部署的那一部分。它包括控制平面 UI（用户在此创建和更新 [Agent Server](/langsmith/agent-server)）以及支持 UI 并提供编程访问的控制平面 API。

当您通过控制平面进行更新时，该更新会存储在控制平面状态中。[数据平面](/langsmith/data-plane) 的“监听器”会通过调用控制平面 API 来轮询这些更新。

## 控制平面 UI

在控制平面 UI 中，您可以：

* 查看待处理部署的列表。
* 查看单个部署的详细信息。
* 创建新部署。
* 更新部署。
* 更新部署的环境变量。
* 查看部署的构建和服务器日志。
* 查看部署指标，例如 CPU 和内存使用情况。
* 删除部署。

控制平面 UI 已嵌入到 [LangSmith](https://docs.smith.langchain.com) 中。

## 控制平面 API

本节介绍控制平面 API 的数据模型。该 API 用于创建、更新和删除部署。有关更多详细信息，请参阅 [控制平面 API 参考](/langsmith/api-ref-control-plane)。

### 集成 (Integrations)

集成是对 `git` 仓库提供商（例如 GitHub）的一种抽象。它包含连接到 `git` 仓库并从中部署所需的所有元数据。

### 部署 (Deployments)

部署是 Agent Server 的一个实例。一个部署可以有多个修订版本（revisions）。

### 修订版本 (Revisions)

修订版本是部署的一个迭代。当创建一个新部署时，会自动创建一个初始修订版本。若要部署代码更改或更新部署的密钥（secrets），必须创建一个新的修订版本。

### 监听器 (Listeners)

监听器是["监听器"应用程序](/langsmith/data-plane#”listener”-application)的一个实例。监听器包含有关应用程序的元数据（例如版本）以及它可以部署到的计算基础设施的元数据（例如 Kubernetes 命名空间）。

监听器数据模型仅适用于 [混合](/langsmith/hybrid) 和 [自托管](/langsmith/self-hosted) 部署。

## 控制平面功能

本节介绍控制平面的各种功能。

### 部署类型

为简化起见，控制平面提供了两种具有不同资源分配的部署类型：`Development`（开发）和 `Production`（生产）。

| **部署类型** | **CPU/内存** | **扩展性** | **数据库** |
|---|---|---|---|
| Development | 1 CPU, 1 GB RAM | 最多 1 个副本 | 10 GB 磁盘，无备份 |
| Production | 2 CPU, 2 GB RAM | 最多 10 个副本 | 磁盘自动扩缩容，自动备份，高可用性（多可用区配置） |

CPU 和内存资源是按副本计算的。

<Warning>
**不可变的部署类型**
一旦创建了部署，部署类型就不能更改。
</Warning>

<Info>
**自托管部署**
[混合](/langsmith/hybrid) 和 [自托管](/langsmith/self-hosted) 部署的资源可以完全自定义。部署类型仅适用于 [云端](/langsmith/cloud) 部署。
</Info>

#### Production

`Production` 类型的部署适用于“生产”工作负载。例如，对于关键路径上的面向客户的应用程序，请选择 `Production`。

`Production` 类型的部署资源可以根据用例和容量限制，在个案基础上手动增加。请通过 [support.langchain.com](https://support.langchain.com) 联系支持人员以请求增加资源。

#### Development

`Development` 类型的部署适用于开发和测试。例如，内部测试环境可以选择 `Development`。`Development` 类型的部署不适用于“生产”工作负载。

<Danger>
**可抢占式计算基础设施**
`Development` 类型的部署（API 服务器、队列服务器和数据库）被配置在可抢占式（preemptible）计算基础设施上。这意味着计算基础设施**可能随时被终止，恕不另行通知**。这可能导致间歇性的……

* Redis 连接超时/错误
* Postgres 连接超时/错误
* 失败或重试的后台运行

此行为是预期的。可抢占式计算基础设施**显著降低了配置 `Development` 类型部署的成本**。按设计，Agent Server 是容错的。实现将自动尝试从 Redis/Postgres 连接错误中恢复，并重试失败的后台运行。

`Production` 类型的部署配置在持久性计算基础设施上，而不是可抢占式计算基础设施上。
</Danger>

`Development` 类型的部署的数据库磁盘大小可以根据具体用例和容量限制，在个案基础上手动增加。对于大多数用例，建议配置 [TTLs](/langsmith/configure-ttl) 来管理磁盘使用量。请通过 [support.langchain.com](https://support.langchain.com) 联系支持人员以请求增加资源。

### 数据库配置

控制平面和 [数据平面](/langsmith/data-plane) 的“监听器”应用程序协同工作，自动为每个部署创建一个 Postgres 数据库。该数据库充当部署的[持久化层](/oss/langgraph/persistence#memory-store)。

在实现 LangGraph 应用程序时，开发者**不需要**单独配置 [检查点器](/oss/langgraph/persistence#checkpointer-libraries)。相反，检查点器是为图自动配置的。任何为图配置的检查点器都将被自动配置的检查点器替换。

无法直接访问数据库。所有对数据库的访问都通过 [Agent Server](/langsmith/agent-server) 进行。

数据库在部署本身被删除之前永远不会被删除。

<Info>
可以为 [混合](/langsmith/hybrid) 和 [自托管](/langsmith/self-hosted) 部署配置自定义的 Postgres 实例。
</Info>

### 异步部署

部署和修订的基础设施都是异步配置和部署的。它们不会在提交后立即部署。目前，部署可能需要几分钟时间。

* 创建新部署时，将为该部署创建一个新数据库。数据库创建是一个一次性步骤。此步骤延长了部署的初始修订版本的部署时间。
* 创建部署的后续修订版本时，没有数据库创建步骤。后续修订版本的部署时间比初始修订版本的部署时间明显要快。
* 每个修订版本的部署过程包含一个构建步骤，该步骤可能需要几分钟时间。

控制平面和 [数据平面](/langsmith/data-plane) 的“监听器”应用程序协同工作，以实现异步部署。

### 监控

部署准备就绪后，控制平面会监控该部署并记录各种指标，例如：

* 部署的 CPU 和内存使用情况。
* 容器重新启动次数。
* 副本数量（此数量会随着 [自动扩缩容](/langsmith/data-plane#autoscaling) 而增加）。
* [PostgreSQL](/langsmith/data-plane#postgres) 的 CPU、内存使用情况和磁盘使用情况。
* [Agent Server 队列](/langsmith/agent-server#persistence-and-task-queue) 中待处理/活动的运行次数。
* [Agent Server API](/langsmith/agent-server) 的成功响应次数、错误响应次数和延迟。

这些指标会以图表的形式显示在控制平面 UI 中。

### LangSmith 集成

每个部署都会自动创建一个 [LangSmith](/langsmith/home) 追踪项目。追踪项目的名称与部署的名称相同。创建部署时，**不需要**指定 `LANGCHAIN_TRACING` 和 `LANGSMITH_API_KEY`/`LANGCHAIN_API_KEY` 环境变量；控制平面会自动设置它们。

删除部署时，追踪记录（traces）和追踪项目不会被删除。
