<Warning>
**本节仅适用于 Kubernetes 部署。**
</Warning>

自托管（Self-Hosted）的 LangSmith 实例会产生日志、指标（Metrics）和追踪（Traces）形式的遥测数据。本节将指导您如何访问这些数据，并将其导出到可观测性收集器或后端。

本节假设您已经设置了监控基础设施，或者您将设置此基础设施，并希望了解如何配置 LangSmith 以便从该基础设施收集数据。

基础设施指的是：

* 收集器（Collectors），例如 [OpenTelemetry](https://opentelemetry.io/docs/collector/)、[FluentBit](https://docs.fluentbit.io/manual) 或 [Prometheus](https://prometheus.io/)。
* 可观测性后端（Observability backends），例如 [Datadog](https://www.datadoghq.com/) 或 [Grafana](https://grafana.com/) 生态系统。

# 日志：[OTel 示例](/langsmith/langsmith-collector#logs)

LangSmith 自托管部署中的所有服务都将其日志写入其节点的**文件系统**和 **stdout**（标准输出）。为了访问这些日志，您需要设置收集器，使其能够从文件系统或 stdout 读取数据。最流行的收集器大多支持从文件系统读取日志。

* **OpenTelemetry**: [文件日志接收器 (File Log Receiver)](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/filelogreceiver)
* **FluentBit**: [Tail 输入 (Tail Input)](https://docs.fluentbit.io/manual/pipeline/inputs/tail)
* **Datadog**: [Kubernetes 日志收集 (Kubernetes Log Collection)](https://docs.datadoghq.com/containers/kubernetes/log/?tab=datadogoperator)

# 指标 (Metrics)：[OTel 示例](/langsmith/langsmith-collector#metrics)

## LangSmith 服务

以下 LangSmith 服务会在特定的端点暴露指标，格式为 Prometheus 指标格式。前端服务目前不暴露指标。

* **Backend (后端)**: `http://<langsmith_release_name>-backend.<namespace>.svc.cluster.local:1984/metrics`
* **Platform Backend (平台后端)**: `http://<langsmith_release_name>-platform-backend.<namespace>.svc.cluster.local:1986/metrics`
* **Playground (游乐场)**: `http://<langsmith_release_name>-playground.<namespace>.svc.cluster.local:1988/metrics`
* **(仅限 LangSmith Control Plane) Host Backend (宿主后端)**: `http://<langsmith_release_name>-host-backend.<namespace>.svc.cluster.local:1985/metrics`

您可以使用 [Prometheus](https://prometheus.io/docs/prometheus/latest/getting_started/#configure-prometheus-to-monitor-the-sample-targets) 或 [OpenTelemetry](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/prometheusreceiver) 收集器来抓取（scrape）这些端点，并将指标导出到您选择的后端。

## 前端 Nginx

前端服务在其端点 `langsmith-frontend.langsmith.svc.cluster.local:80/nginx_status` 暴露其 Nginx 指标。您可以选择自行抓取这些指标，或者使用 [LangSmith 可观测性 Helm Chart](/langsmith/observability-stack) 部署一个 Prometheus Nginx 导出器（exporter）。

<Warning>
**以下部分仅适用于集群内部数据库（in-cluster databases）。如果您使用的是外部数据库，则需要自行配置指标的暴露和获取方式。**
</Warning>

## Postgres + Redis

如果您使用的是集群内部的 Postgres/Redis 实例，您可以使用 Prometheus 导出器来暴露来自其实例的指标。您可以部署自己的导出器，或者如果您愿意，可以使用 [LangSmith 可观测性 Helm Chart](/langsmith/observability-stack) 自动为您部署一个导出器。

## Clickhouse

集群内部的 Clickhouse 已配置为无需导出器即可暴露指标。您可以使用收集器在以下地址抓取指标：`http://<langsmith_release_name>-clickhouse.<namespace>.svc.cluster.local:9363/metrics`

# 追踪 (Traces)：[OTel 示例](/langsmith/langsmith-collector#traces)

LangSmith 后端、平台后端、游乐场和 LangSmith 队列部署都已进行**插桩（instrumented）**，可以发出 [Otel](https://opentelemetry.io/do/langsmith/observability-concepts/signals/traces/) 追踪。跟踪默认是关闭的，您可以通过在 `langsmith_config.yaml`（或等效文件）中添加以下配置来为所有 LangSmith 服务启用跟踪：

```yaml
config:
  tracing:
    enabled: true
    endpoint: "<your_collector_endpoint>"
    useTls: true # / false
    env: "ls_self_hosted" # 此值将作为 "env" 属性设置在您的 Span 中
    exporter: "http" # 必须是 http 或 grpc
```
