ClickHouse 是一个高性能的面向列的数据库系统。它支持快速的数据摄取，并针对分析查询进行了优化。

LangSmith 使用 ClickHouse 作为跟踪记录（traces）和反馈（feedback）的主要数据存储。默认情况下，自托管的 LangSmith 会使用一个内部的 ClickHouse 数据库，该数据库与 LangSmith 实例捆绑在一起。它作为有状态集（stateful set）在 LangSmith 应用程序所在的同一个 Kubernetes 集群中运行，或者在与 LangSmith 应用程序位于同一主机的 Docker 容器中运行。

然而，您可以配置 LangSmith 以使用外部 ClickHouse 数据库，以便于管理和扩展。通过配置外部 ClickHouse 数据库，您可以管理数据库的备份、扩展以及其他操作任务。虽然 Clickhouse 尚未成为 Azure、AWS 或 Google Cloud 中的原生服务，但您可以通过以下方式使用外部 ClickHouse 数据库来运行 LangSmith：

* [LangSmith 管理的 ClickHouse](/langsmith/langsmith-managed-clickhouse)

* 直接或通过云提供商市场部署 [ClickHouse Cloud](https://clickhouse.cloud/)：

    * [Azure Marketplace](https://azuremarketplace.microsoft.com/en-us/marketplace/apps/clickhouse.clickhouse_cloud?tab=Overview)
  * [Google Cloud Marketplace](https://console.cloud.google.com/marketplace/product/clickhouse-public/clickhouse-cloud)
  * [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-jettukeanwrfc)

* 在您云提供商的虚拟机（VM）上

<Note>
使用前两个选项（LangSmith 管理的 ClickHouse 或 ClickHouse Cloud）将会在您的 VPC **外部** 部署 Clickhouse 服务。但是，这两个选项都支持私有链接（private endpoints），这意味着您可以将流量导向 ClickHouse 服务，而无需将其暴露给公共互联网（例如通过 AWS PrivateLink 或 GCP Private Service Connect）。

此外，敏感信息可以配置为不存储在 Clickhouse 中。请通过 [support.langchain.com](https://support.langchain.com) 联系支持人员以获取更多信息。
</Note>

## 要求

* 一个已部署的 ClickHouse 实例，您的 LangSmith 应用程序需要能够访问该实例的网络（参见上文选项）。
* 一个拥有 ClickHouse 数据库管理员权限的用户。该用户将用于创建必要的表、索引和视图。
* 我们支持 Standalone ClickHouse 和外部管理的集群部署。对于集群部署，请确保所有节点运行相同的版本。请注意，捆绑的 ClickHouse 安装不支持集群设置。
* 我们仅支持 ClickHouse 版本 >= 23.9。使用 ClickHouse 版本 >= 24.2 需要 LangSmith v0.6 或更高版本。
* 我们依赖于在您的 ClickHouse 实例上设置的几个配置参数。这些参数在下面详细说明：

```xml
<profiles>
  <default>
      <async_insert>1</async_insert> # 开启异步插入
      <async_insert_max_data_size>25000000</async_insert_max_data_size> # 达到 25MB 后刷新数据到磁盘。您可能需要根据您的工作负载进行调整。
      <wait_for_async_insert>0</wait_for_async_insert> # 默认禁用等待异步插入
      <parallel_view_processing>1</parallel_view_processing> # 启用并行视图处理
      <materialize_ttl_after_modify>0</materialize_ttl_after_modify> # 修改后禁用 TTL 物化
      <wait_for_async_insert_timeout>120</wait_for_async_insert_timeout> # 设置等待异步插入的超时时间
      <lightweight_deletes_sync>0</lightweight_deletes_sync> # 禁用轻量级删除同步
      <allow_materialized_view_with_bad_select>1</allow_materialized_view_with_bad_select> # 允许具有导致 CH 失败的旧版 SELECT 语句的物化视图
  </default>
</profiles>
```

<Warning>
我们的系统已针对上述配置参数进行了优化。更改这些参数可能会导致意外行为。
</Warning>

## 高可用性（HA）复制的 Clickhouse 集群

<Warning>
默认情况下，上述设置过程仅适用于单节点 Clickhouse 集群。
</Warning>

如果您想使用多节点 Clickhouse 集群来实现高可用性（HA），我们需要额外的配置支持。此设置可以使用具有多个节点、数据通过 Zookeeper 或 Clickhouse Keeper 复制的 Clickhouse 集群。有关 Clickhouse 复制的更多信息，请参阅 [Clickhouse 数据复制文档](https://clickhouse.com/docs/architecture/replication)。

为了使用复制的多节点 Clickhouse 设置来配置 LangSmith：

* 您需要有一个已设置了 Keeper 或 Zookeeper 用于数据复制和适当设置的 Clickhouse 集群。请参阅 [Clickhouse 复制设置文档](https://clickhouse.com/docs/en/architecture/replication)。
* 您需要在 [配置（Configuration）](#configuration) 部分设置集群设置，特别是将 `cluster` 设置更改为与您的 Clickhouse 集群名称匹配的名称。这将在使用 Clickhouse 迁移时使用 `Replicated` 表引擎。
* 如果除了高可用性外，您还想在 Clickhouse 节点之间进行负载均衡（以分配读或写），我们建议使用负载均衡器或 DNS 负载均衡在 Clickhouse 服务器之间进行轮询。
* **注意**：在首次启动 LangSmith 并运行 Clickhouse 迁移之前，您需要启用 `cluster` 设置。这是一个要求，因为表引擎需要创建为 `Replicated` 表引擎类型，而不是非复制引擎类型。

当启用 `cluster` 运行迁移时，迁移将创建 `Replicated` 表引擎的变体。这意味着数据将在集群中的服务器之间复制。这是一种主-主（master-master）设置，任何服务器都可以处理读取、写入或合并。

<Note>
有关复制的 ClickHouse 集群设置示例，请参阅 LangSmith Helm chart 仓库中 `langsmith` 目录下的例子，具体是 [复制的 ClickHouse 部分](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/examples/replicated-clickhouse/README.md)。
</Note>

## LangSmith 管理的 ClickHouse

* 如果使用 LangSmith 管理的 ClickHouse，您需要在 LangSmith VPC 和 ClickHouse VPC 之间设置 VPC 对等连接（VPC peering connection）。请通过 [support.langchain.com](https://support.langchain.com) 联系支持人员以获取更多信息。
* 您还需要设置对象存储（Blob Storage）。您可以在 [对象存储文档](/langsmith/self-host-blob-storage) 中了解更多关于对象存储的信息。

<Note>
由 LangSmith 管理的 ClickHouse 安装使用 `SharedMerge` 引擎，该引擎会自动对其进行集群化，并将计算与存储分离。
</Note>

有关更多信息，请参阅 [托管的 ClickHouse](/langsmith/langsmith-managed-clickhouse) 页面。

## 参数

您需要向 LangSmith 安装提供几个参数来配置外部 ClickHouse 数据库。这些参数包括：

* **Host（主机）**: ClickHouse 数据库的主机名或 IP 地址
* **HTTP Port（HTTP 端口）**: ClickHouse 数据库用于 HTTP 连接监听的端口
* **Native Port（原生端口）**: ClickHouse 数据库用于 [原生连接](https://clickhouse.com/docs/en/interfaces/tcp) 监听的端口
* **Database（数据库）**: LangSmith 应使用的 ClickHouse 数据库的名称
* **Username（用户名）**: 用于连接到 ClickHouse 数据库的用户名
* **Password（密码）**: 用于连接到 ClickHouse 数据库的密码
* **Cluster (可选)**: 如果使用外部 Clickhouse 集群，则是 ClickHouse 集群的名称。设置后，LangSmith 将在集群上运行迁移并将数据复制到各个实例。

<Warning>
集群部署的重要注意事项：

* 集群设置必须在**全新的 Schema** 上配置——现有的独立 ClickHouse 实例不能转换为集群模式。

* 集群仅支持外部部署的 ClickHouse。它与捆绑的 ClickHouse 安装不兼容，因为后者不包含必需的 ZooKeeper 配置。

* 使用集群部署时，LangSmith 将自动执行以下操作：

    * 在集群的所有节点上执行数据库迁移
    * 配置表以便在集群中复制数据

请注意，虽然数据在各个节点之间是复制的，但 LangSmith **不**会配置分布式表或处理查询路由——查询将定向到指定的宿主机。如果需要，您需要在基础设施层面处理任何负载均衡或查询分发。
</Warning>

## 配置

有了这些参数后，您可以配置您的 LangSmith 实例以使用已部署的 ClickHouse 数据库。您可以通过修改 LangSmith Helm Chart 安装的 `config.yaml` 文件或 Docker 安装的 `.env` 文件来实现。

<CodeGroup>

```yaml Helm
clickhouse:
  external:
    enabled: true
    host: "host"
    port: "http port"
    nativePort: "native port"
    user: "default"
    password: "password"
    database: "default"
    tls: false
    cluster: "my_cluster_name"  # 可选：如果使用外部 Clickhouse 集群，请设置此项
```

```bash Docker
# 在您的 .env 文件中
CLICKHOUSE_HOST=langchain-clickhouse # 如果使用外部 Clickhouse，请更改为您自己的 Clickhouse 主机。否则保持原样
CLICKHOUSE_USER=default # 如果需要，请更改为您自己的 Clickhouse 用户
CLICKHOUSE_DB=default # 如果需要，请更改为您自己的 Clickhouse 数据库
CLICKHOUSE_PORT=8123 # 如果需要，请更改为您自己的 Clickhouse 端口
CLICKHOUSE_TLS=false # 如果您使用 TLS 连接到 Clickhouse，请更改为 true。否则保持原样
CLICKHOUSE_PASSWORD=password # 如果需要，请更改为您自己的 Clickhouse 密码
CLICKHOUSE_NATIVE_PORT=9000 # 如果需要，请更改为您自己的 Clickhouse 原生端口
CLICKHOUSE_CLUSTER=my_cluster_name # 可选：如果使用外部 Clickhouse 集群，请设置此项
```

</CodeGroup>

配置完成后，您应该能够重新安装您的 LangSmith 实例。如果所有配置正确，您的 LangSmith 实例现在应该正在使用您的外部 ClickHouse 数据库。

## ClickHouse 的 TLS

使用本节配置 ClickHouse 连接的 TLS。有关挂载内部/公共 CA 以使 LangSmith 信任您的 ClickHouse 服务器证书，请参阅 [配置自定义 TLS 证书](/langsmith/self-host-custom-tls-certificates#mount-internal-cas-for-tls)。

### 服务器 TLS（单向）

要为 ClickHouse 连接启用 TLS：

- 在您的配置中设置 `tls: true`（或使用带有外部 Secret 的 `tlsSecretKey`）。
- 使用适当的 TLS 端口（HTTP 通常为 `8443`，原生 TCP 连接通常为 `9440`）。
- 如果使用内部 CA，请使用 `config.customCa.secretName` 和 `config.customCa.secretKey` 提供 CA 捆绑包。

<Warning>
仅当您的 ClickHouse 服务器使用内部或私有 CA 时才挂载自定义 CA。公开信任的 CA 不需要此配置。
</Warning>

<CodeGroup>

```yaml Helm (服务器 TLS)
config:
  customCa:
    secretName: "langsmith-custom-ca"  # 包含您的 CA 捆绑包的 Secret
    secretKey: "ca.crt"    # 包含 CA 捆绑包的 Secret 中的 Key
clickhouse:
  external:
    enabled: true
    host: "your-clickhouse-host.example.com"
    port: "8443"
    nativePort: "9440"
    user: "default"
    password: "password"
    database: "default"
    tls: true
```

```yaml Kubernetes Secret (CA 捆绑包)
apiVersion: v1
kind: Secret
metadata:
  name: langsmith-custom-ca
type: Opaque
stringData:
  ca.crt: |
    -----BEGIN CERTIFICATE-----
    <ROOT_OR_INTERMEDIATE_CA_CERT_CHAIN>
    -----END CERTIFICATE-----
```

</CodeGroup>

### 互相信任的 TLS（mTLS）带客户端认证

从 LangSmith helm chart 版本 **0.12.29** 开始，我们支持 ClickHouse 客户端的 mTLS。对于 mTLS 中的服务器端身份验证，请在遵循以下客户端证书配置的同时，使用[服务器 TLS 步骤](#server-tls-one-way)（自定义 CA）。

如果您的 ClickHouse 服务器需要客户端证书身份验证：

- 提供一个包含客户端证书和密钥的 Secret。
- 通过 `clickhouse.external.clientCert.secretName` 引用它，并使用 `certSecretKey` 和 `keySecretKey` 指定密钥。

<CodeGroup>

```yaml Helm (客户端认证)
clickhouse:
  external:
    enabled: true
    host: "your-clickhouse-host.example.com"
    port: "8443"
    nativePort: "9440"
    user: "default"
    password: "password"
    database: "default"
    tls: true
    clientCert:
      secretName: "clickhouse-client-cert"
      certSecretKey: "tls.crt"
      keySecretKey: "tls.key"
```

```yaml Kubernetes Secret (客户端证书/密钥)
apiVersion: v1
kind: Secret
metadata:
  name: clickhouse-client-cert
type: Opaque
stringData:
  tls.crt: |
    -----BEGIN CERTIFICATE-----
    <CLIENT_CERT>
    -----END CERTIFICATE-----
  tls.key: |
    -----BEGIN PRIVATE KEY-----
    <CLIENT_KEY>
    -----END PRIVATE KEY-----
```

</CodeGroup>

#### 迁移的非 TLS 原生端口

<Warning>
在使用 ClickHouse 的 mTLS 时，您必须为我们的迁移作业（在 helm install 和 upgrade 时运行）**保持一个非 TLS 的原生（TCP）端口**是开放的。应用程序本身不会通过此端口通信，它**仅供迁移作业使用**。
</Warning>

默认情况下，迁移作业连接到端口 `9000` 进行迁移。如果您的 ClickHouse 实例使用不同的非 TLS 原生端口，您可以使用 `CLICKHOUSE_MIGRATE_NATIVE_PORT` 环境变量进行配置：

```yaml
backend:
  clickhouseMigrations:
    extraEnv:
      - name: CLICKHOUSE_MIGRATE_NATIVE_PORT
        value: "9000"  # 更改为您自己的非 TLS 原生端口
```

#### 证书卷的 Pod 安全上下文

为 mTLS 挂载的证书卷受到文件访问限制的保护。为确保所有 LangSmith Pod 都能读取证书文件，您必须在 Pod 安全上下文中设置 `fsGroup: 1000`。

您可以通过以下两种方式配置此项：

**选项 1：使用 `commonPodSecurityContext`**

在顶层设置 `fsGroup` 以将其应用于所有 Pod：

```yaml
commonPodSecurityContext:
  fsGroup: 1000
```

**选项 2：添加到单个 Pod 的安全上下文中**

如果您需要更精细的控制，可以将 `fsGroup` 添加到每个 Pod 的安全上下文。有关完整参考，请参阅[mTLS 配置示例](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/examples/mtls_config.yaml)。
