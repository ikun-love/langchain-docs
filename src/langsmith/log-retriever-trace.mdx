<Note>
如果检索器追踪（retriever traces）没有以正确的格式记录日志，系统不会出错，数据仍然会被记录。但是，数据将不会以特定于检索步骤的方式进行渲染展示。
</Note>

许多大型语言模型（LLM）应用需要从向量数据库、知识图谱或其他类型的索引中查找文档。检索器追踪是一种记录检索器（retriever）所检索到的文档的方式。LangSmith 为追踪中的检索步骤提供了特殊的渲染功能，以便更容易理解和诊断检索相关问题。为了让检索步骤能够正确渲染，需要执行以下几个小步骤：

1.  使用 `run_type="retriever"` 来注解（Annotate）该检索器步骤。

2.  从检索器步骤返回一个 Python 字典列表或 TypeScript 对象列表。每个字典（或对象）应包含以下键（Keys）：

    *   `page_content`: 文档的文本内容。
    *   `type`: 此值应始终为 `"Document"`。
    *   `metadata`: 一个 Python 字典或 TypeScript 对象，包含有关该文档的元数据（metadata）。这些元数据将在追踪（trace）中显示出来。

下面的代码片段展示了如何在 Python 和 TypeScript 中记录检索步骤。

<CodeGroup>

```python Python
from langsmith import traceable

def _convert_docs(results):
    return [
        {
            "page_content": r,
            "type": "Document",
            "metadata": {"foo": "bar"}
        }
        for r in results
    ]

@traceable(run_type="retriever")
def retrieve_docs(query):
    # Foo 检索器返回硬编码的虚拟文档。
    # 在生产环境中，这可能是一个真正的向量数据库或其他文档索引。
    contents = ["Document contents 1", "Document contents 2", "Document contents 3"]
    return _convert_docs(contents)

retrieve_docs("User query")
```

```typescript TypeScript
import { traceable } from "langsmith/traceable";

interface Document {
    page_content: string;
    type: string;
    metadata: { foo: string };
}

function convertDocs(results: string[]): Document[] {
    return results.map((r) => ({
        page_content: r,
        type: "Document",
        metadata: { foo: "bar" }
    }));
}

const retrieveDocs = traceable((query: string): Document[] => {
    // Foo 检索器返回硬编码的虚拟文档。
    // 在生产环境中，这可能是一个真正的向量数据库或其他文档索引。
    const contents = ["Document contents 1", "Document contents 2", "Document contents 3"];
    return convertDocs(contents);
},{
    name: "retrieveDocs",
    run_type: "retriever"
} // traceable 的配置参数
);

await retrieveDocs("User query");
```
