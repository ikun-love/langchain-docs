在本教程中，我们将构建一个**只允许特定用户访问**的聊天机器人。我们将从 LangGraph 模板开始，逐步添加基于令牌的安全机制。完成之后，您将拥有一个正常工作的聊天机器人，它会在允许访问前检查有效的令牌。

这是我们认证系列的第一部分：

1. 设置自定义认证（您当前所在位置）- 控制谁可以访问您的机器人
2. [使对话私密化](/langsmith/resource-auth) - 允许用户拥有私密对话
3. [连接认证提供商](/langsmith/add-auth-server) - 添加真实的**用户账户**并使用 OAuth2 进行验证以用于生产环境

本指南假设您对以下概念有基本的了解：

* [**认证和访问控制**](/langsmith/auth)
* [**LangSmith**](/langsmith/home)

<Note>
自定义认证仅适用于 LangSmith SaaS 部署或企业自托管部署。
</Note>

## 1. 创建您的应用

使用 LangGraph 启动模板创建一个新的聊天机器人：

<CodeGroup>
```bash pip
pip install -U "langgraph-cli[inmem]"
langgraph new --template=new-langgraph-project-python custom-auth
cd custom-auth
```

```bash uv
uv add langgraph-cli[inmem]
langgraph new --template=new-langgraph-project-python custom-auth
cd custom-auth
```
</CodeGroup>

该模板会提供一个占位的 LangGraph 应用。您可以通过安装本地依赖项并运行开发服务器来试用它：

<CodeGroup>
```bash pip
pip install -e .
langgraph dev
```

```bash uv
uv add .
langgraph dev
```

```bash npm
npx @langchain/langgraph-cli dev
```
</CodeGroup>

服务器将启动并在您的浏览器中打开 [Studio](/langsmith/studio)：

```
> - 🚀 API: http://127.0.0.1:2024
> - 🎨 Studio UI: https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024
> - 📚 API Docs: http://127.0.0.1:2024/docs
>
> 此内存服务器专为开发和测试而设计。
> 如需用于生产环境，请使用 LangSmith。
```

如果您将此服务自托管在公共互联网上，任何人都可能访问它。

## 2. 添加认证

现在您有了一个基础的 LangGraph 应用，可以为其添加认证功能了。

<Note>
在本教程中，出于示例目的，您将从一个硬编码的令牌开始。您将在第三个教程中过渡到一个“可用于生产环境”的认证方案。
</Note>

`@[Auth]` 对象允许您注册一个认证函数，LangSmith 部署将在每次请求时运行此函数。此函数接收每个请求并决定是接受还是拒绝。

创建一个新文件 `src/security/auth.py`。您检查用户是否被允许访问机器人的代码将位于此处：

```python {highlight={10,15-16}} title="src/security/auth.py"
from langgraph_sdk import Auth

# 这是我们的玩具用户数据库。请勿在生产环境中使用此方式
VALID_TOKENS = {
    "user1-token": {"id": "user1", "name": "Alice"},
    "user2-token": {"id": "user2", "name": "Bob"},
}

# "Auth" 对象是 LangGraph 将用于标记我们认证函数的容器
auth = Auth()


# `authenticate` 装饰器告诉 LangGraph 将此函数作为中间件调用
# 以处理每个请求。这将决定请求是否被允许或被拒绝
@auth.authenticate
async def get_current_user(authorization: str | None) -> Auth.types.MinimalUserDict:
    """检查用户的令牌是否有效。"""
    assert authorization
    scheme, token = authorization.split()
    assert scheme.lower() == "bearer"
    # 检查令牌是否有效
    if token not in VALID_TOKENS:
        raise Auth.exceptions.HTTPException(status_code=401, detail="Invalid token")

    # 如果有效，返回用户信息
    user_data = VALID_TOKENS[token]
    return {
        "identity": user_data["id"],
    }
```

请注意，您的 `@[Auth.authenticate]` 处理程序执行了两件重要的事情：

1. 检查请求的 [Authorization 标头](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Authorization) 中是否提供了有效的令牌
2. 返回用户的 @[MinimalUserDict]

现在，通过在 `@[langgraph.json]` 配置中添加以下内容，告诉 LangGraph 使用认证：

```json {highlight={7-9}} title="langgraph.json"
{
  "dependencies": ["."],
  "graphs": {
    "agent": "./src/agent/graph.py:graph"
  },
  "env": ".env",
  "auth": {
    "path": "src/security/auth.py:auth"
  }
}
```

## 3. 测试您的机器人

再次启动服务器以测试所有功能：

```bash
langgraph dev --no-browser
```

如果您没有添加 `--no-browser` 标志，Studio UI 将会在浏览器中打开。默认情况下，即使在使用自定义认证时，我们也允许从 Studio 进行访问。这使得在 Studio 中开发和测试您的机器人更加容易。您可以通过在认证配置中设置 `disable_studio_auth: true` 来移除此备用认证选项：

```json
{
    "auth": {
        "path": "src/security/auth.py:auth",
        "disable_studio_auth": true
    }
}
```

## 4. 与您的机器人聊天

现在您应该只能在请求标头中提供有效令牌的情况下才能访问机器人。但是，在您在教程的下一部分添加 [资源授权处理程序](/langsmith/auth#resource-specific-handlers) 之前，用户仍然可以访问彼此的资源。

在文件或 Notebook 中运行以下代码：

```python
from langgraph_sdk import get_client

# 尝试不带令牌访问（应该失败）
client = get_client(url="http://localhost:2024")
try:
    thread = await client.threads.create()
    print("❌ 没有令牌应该失败！")
except Exception as e:
    print("✅ 正确阻止访问:", e)

# 尝试使用有效令牌
client = get_client(
    url="http://localhost:2024", headers={"Authorization": "Bearer user1-token"}
)

# 创建一个线程并聊天
thread = await client.threads.create()
print(f"✅ 以 Alice 身份创建线程: {thread['thread_id']}")

response = await client.runs.create(
    thread_id=thread["thread_id"],
    assistant_id="agent",
    input={"messages": [{"role": "user", "content": "Hello!"}]},
)
print("✅ 机器人回应:")
print(response)
```

您应该看到以下情况：

1. 没有有效令牌，我们无法访问机器人。
2. 有效令牌，我们可以创建线程并聊天。

恭喜！您已经构建了一个**只允许“已认证”用户访问**的聊天机器人。虽然此系统目前尚未实现可用于生产环境的安全方案，但我们已经了解了控制机器人访问权限的基本机制。在下一个教程中，我们将学习如何为每个用户提供他们自己的私密对话。
