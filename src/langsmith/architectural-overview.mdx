## 存储服务

<Note>
LangSmith 自托管版默认会捆绑所有存储服务。您可以配置 LangSmith 以使用外部版本的存储服务。在生产环境中，我们 **强烈建议使用外部存储服务**。
</Note>

### ClickHouse

[ClickHouse](https://clickhouse.com/docs/en/intro) 是一个高性能的、面向列的 SQL 数据库管理系统 (DBMS)，用于在线分析处理 (OLAP)。

LangSmith 将 ClickHouse 用作（高容量数据）跟踪 (traces) 和反馈的主要数据存储。

### PostgreSQL

[PostgreSQL](https://www.postgresql.org/about/) 是一个强大的、开源的对象关系数据库系统，它使用并扩展了 SQL 语言，并结合了许多功能，可以安全地存储和扩展最复杂的数据工作负载。

LangSmith 将 PostgreSQL 用作事务性工作负载和操作数据（除跟踪和反馈之外的几乎所有内容）的主要数据存储。

### Redis

[Redis](https://github.com/redis/redis) 是一个强大的内存键值数据库，它会持久化到磁盘。通过将数据保留在内存中，Redis 为缓存等操作提供了高性能。

LangSmith 使用 Redis 来支持队列和缓存操作。

### Blob 存储

LangSmith 支持多种 Blob 存储提供商，包括 [AWS S3](https://aws.amazon.com/s3/)、[Azure Blob Storage](https://azure.microsoft.com/en-us/services/storage/blobs/) 和 [Google Cloud Storage](https://cloud.google.com/storage)。

LangSmith 使用 Blob 存储来存储大文件，例如跟踪工件 (trace artifacts)、反馈附件和其他大型数据对象。Blob 存储是可选的，但在生产部署中强烈推荐使用。

## 服务

### LangSmith 前端

前端使用 Nginx 来服务 LangSmith UI 并将 API 请求路由到其他服务器。这作为应用程序的入口点，也是唯一必须向用户暴露的组件。

### LangSmith 后端

后端是处理 CRUD API 请求的主要入口点，并处理应用程序的大部分业务逻辑。这包括处理来自前端和 SDK 的请求、准备要摄入的跟踪数据，以及支持 Hub API。

### LangSmith 队列

队列负责处理传入的跟踪数据和反馈，以确保它们被异步地摄入并持久化到跟踪和反馈数据存储中。它会处理数据完整性检查，确保成功写入数据存储，并在出现数据库错误或暂时无法连接到数据库等情况时处理重试。

### LangSmith 平台后端

平台后端是另一个关键服务，主要处理身份验证、运行数据摄入和其他高容量任务。

### LangSmith 游乐场 (Playground)

游乐场是负责将请求转发到各种 LLM API 的服务，以支持 LangSmith Playground 功能。它也可以用来连接到您自己的自定义模型服务器。

### LangSmith ACE（任意代码执行）后端

ACE 后端是一个服务，负责在安全的环境中执行任意代码。这用于支持在 LangSmith 内部运行自定义代码。
