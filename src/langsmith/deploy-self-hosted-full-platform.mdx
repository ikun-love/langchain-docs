本指南将向您展示如何在您的[自托管 LangSmith 实例](/langsmith/kubernetes)上启用 **LangSmith 部署**。这会添加一个[控制平面](/langsmith/control-plane)和[数据平面](/langsmith/data-plane)，使您能够直接通过 LangSmith UI 部署、扩展和管理智能体（Agent）和应用程序。

完成本指南后，您将可以使用 LangSmith 的 [可观测性](/langsmith/observability)、[评估](/langsmith/evaluation) 和 [部署](/langsmith/deployments) 功能。

<Info>**重要提示**<br></br> 启用 LangSmith 部署需要 [企业版](https://langchain.com/pricing) 计划。 </Info>

<Note>
**此设置页面用于在现有 LangSmith 实例上启用 [LangSmith 部署](/langsmith/deployments)。**

请查阅[自托管选项](/langsmith/self-hosted)以了解：
- [LangSmith (可观测性)](/langsmith/self-hosted#langsmith)：您应该首先安装的内容。
- [LangSmith 部署](/langsmith/self-hosted#langsmith-deployment)：本指南所启用的功能。
- [独立服务器](/langsmith/self-hosted#standalone-server)：轻量级替代方案，不包含 UI。
</Note>

## 概述

本指南基于[Kubernetes 安装指南](/langsmith/kubernetes)。在继续操作之前，**您必须先完成该指南**。本文档涵盖了启用 LangSmith 部署所需的额外设置步骤：
- 安装 LangGraph 操作器（Operator）
- 配置您的入口（Ingress）
- 连接到控制平面

## 先决条件

1. 您正在使用 Kubernetes。
2. 您有一个正在运行的[自托管 LangSmith 实例](/langsmith/kubernetes)。
3. 您的集群中已安装了 `KEDA`。
```bash
  helm repo add kedacore https://kedacore.github.io/charts
  helm install keda kedacore/keda --namespace keda --create-namespace
```
6. 入口（Ingress）配置
    1. 您必须为您的 LangSmith 实例设置入口（ingress）、网关（gateway）或使用 Istio。所有智能体都将作为 Kubernetes Service 部署在此入口之后。请使用此指南来为您的实例[设置入口](/langsmith/self-host-ingress)。
7. 您的集群中必须有可用的空闲空间以支持多个部署。建议使用 `Cluster-Autoscaler` 以自动配置新节点。
8. 一个有效的动态 PV 供应器（provisioner）或集群中可用的 PV。您可以通过运行以下命令进行验证：
```bash
  kubectl get storageclass
```
9. 您的网络可以访问 `https://beacon.langchain.com`（出口流量/Egress）。如果不是在隔离模式（air-gapped mode）下运行，这是进行许可证验证和使用情况报告所必需的。有关详细信息，请参阅[出口文档](/langsmith/self-host-egress)。

## 设置

1. 在配置自托管 LangSmith 实例时，您需要启用 `deployment` 选项。这将配置几个关键资源：
    1. `listener`：这是一个监听来自[控制平面](/langsmith/control-plane)的部署更改的服务，用于创建/更新下游的 CRD（自定义资源定义）。
    2. `LangGraphPlatform CRD`：LangSmith 部署的一个 CRD。它包含管理 LangSmith 部署实例的规范（spec）。
    3. `operator`：此操作器负责处理 LangSmith CRD 的更改。
    4. `host-backend`：这是[控制平面](/langsmith/control-plane)。

<Note>
从 v0.12.0 开始，`langgraphPlatform` 选项已被弃用。对于 v0.12.0 之后的任何版本，请使用 `config.deployment`。
</Note>

2. Helm Chart 将使用另外两个镜像。请使用最新版本中指定的镜像：
```bash
  hostBackendImage:
    repository: "docker.io/langchain/hosted-langserve-backend"
    pullPolicy: IfNotPresent
  operatorImage:
    repository: "docker.io/langchain/langgraph-operator"
    pullPolicy: IfNotPresent
```
3. 在 LangSmith 的配置文件中（通常是 `langsmith_config.yaml`），启用 `deployment` 选项。请注意，您还必须设置了有效的入口配置：
```yaml
  config:
    deployment:
      enabled: true
    # 从 v0.12.0 开始，此部分已弃用。对于 v0.12.0 之后的版本，请使用 config.deployment。
    langgraphPlatform:
      enabled: true
      langgraphPlatformLicenseKey: "YOUR_LANGGRAPH_PLATFORM_LICENSE_KEY"
```
4. 在您的 `values.yaml` 文件中，配置 `hostBackendImage` 和 `operatorImage` 选项（如果您需要镜像私有化）。如果您使用的是需要身份验证的私有容器注册表，还必须配置 `imagePullSecrets`，请参阅[可选：配置私有注册表身份验证](#optional-configure-authentication-for-private-registries)。

5. 您还可以通过覆盖[此处](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/values.yaml#L898)的默认模板来配置智能体的基础模板。

    您的自托管基础设施现已准备好创建部署。

## (可选) 配置附加数据平面

除了在上一步骤中已创建的现有数据平面之外，您可以创建驻留在不同 Kubernetes 集群或同一集群中不同命名空间中的更多数据平面。

### 先决条件
1. 阅读[混合部署文档](/langsmith/hybrid#listeners)中的集群组织指南，以了解如何根据您的用例最佳地组织结构。
2. 验证[混合部署部分](/langsmith/deploy-hybrid#prerequisites)中提到的先决条件是否已满足新集群的要求。请注意，在[此部分](/langsmith/deploy-hybrid#prerequisites)的步骤 5 中，您需要启用到您的[自托管 LangSmith 实例](/langsmith/self-host-usage#configuring-the-application-you-want-to-use-with-langsmith)的出站连接，而不是连接到 `https://api.host.langchain.com` 和 `https://api.smith.langchain.com`。
3. 在您的 LangSmith Postgres 实例上运行以下命令以启用此功能。这是随自托管 LangSmith 设置一起提供的[Postgres 实例](/langsmith/kubernetes#validate-your-deployment%3A)。
```sql
update organizations set config = config || '{"enable_lgp_listeners_page": true}' where id = '<org id here>';
update tenants set config = config || '{"langgraph_remote_reconciler_enabled": true}' where id = '<workspace id here>';
```
记下您选择的工作区 ID（workspace ID），因为在后续步骤中会用到它。

### 部署到不同的集群
1. 遵循[混合设置指南](/langsmith/deploy-hybrid#setup)中的步骤 2-6。`config.langsmithWorkspaceId` 的值应设置为您在先决条件中记录的工作区 ID。
2. 要部署多个数据平面到同一集群，请遵循[此处](/langsmith/deploy-hybrid#configuring-additional-data-planes-in-the-same-cluster)列出的规则。

### 部署到同一集群中的不同命名空间
1. 您需要修改在[上述设置说明](/langsmith/deploy-self-hosted-full-platform#setup)第 3 步中创建的 `langsmith_config.yaml` 文件：
    - 将 `operator.watchNamespaces` 字段设置为自托管 LangSmith 实例当前运行的命名空间。这是为了防止与新数据平面操作器将要添加的那个操作器发生冲突。
    - **必须**使用[网关 API](/langsmith/self-host-ingress#option-2%3A-gateway-api) 或 [Istio 网关](/langsmith/self-host-ingress#option-3%3A-istio-gateway)。请相应地调整您的 `langsmith_config.yaml` 文件。
2. 运行 `helm upgrade` 以使用新配置更新您的自托管 LangSmith 实例。
3. 遵循[混合设置指南](/langsmith/deploy-hybrid#setup)中的步骤 2-6。`config.langsmithWorkspaceId` 的值应设置为您在先决条件中记录的工作区 ID。请记住，`config.watchNamespaces` 必须设置为与现有数据平面使用的命名空间不同的命名空间！

## (可选) 配置私有注册表身份验证

如果您的[智能体服务器部署](/langsmith/agent-server)将使用来自私有容器注册表的镜像（例如 AWS ECR、Azure ACR、GCP Artifact Registry、私有 Docker 注册表），则需要配置镜像拉取密钥（image pull secrets）。这是一次性的基础设施配置，允许所有部署自动向您的私有注册表进行身份验证。

**步骤 1：创建 Kubernetes 镜像拉取密钥**

```bash
kubectl create secret docker-registry langsmith-registry-secret \
    --docker-server=myregistry.com \
    --docker-username=your-username \
    --docker-password=your-password \
    --docker-email=your-email@example.com \
    -n langsmith
```

将值替换为您注册表的凭据：
- `myregistry.com`：您的注册表 URL
- `your-username`：您的注册表用户名
- `your-password`：您的注册表密码或访问令牌
- `langsmith`：安装 LangSmith 的 Kubernetes 命名空间

**步骤 2：在 `values.yaml` 文件中配置部署模板**

为了使智能体服务器部署能够使用私有注册表密钥，您必须将 `imagePullSecrets` 添加到操作器的部署模板中：

```yaml {21-22}
operator:
  templates:
    deployment: |
      apiVersion: apps/v1
      kind: Deployment
      metadata:
        name: ${name}
        namespace: ${namespace}
      spec:
        replicas: ${replicas}
        revisionHistoryLimit: 10
        selector:
          matchLabels:
            app: ${name}
        template:
          metadata:
            labels:
              app: ${name}
          spec:
            enableServiceLinks: false
            imagePullSecrets:
            - name: langsmith-registry-secret
            containers:
            - name: api-server
              image: ${image}
              ports:
              - name: api-server
                containerPort: 8000
                protocol: TCP
              livenessProbe:
                httpGet:
                  path: /ok
                  port: 8000
                periodSeconds: 15
                timeoutSeconds: 5
                failureThreshold: 6
              readinessProbe:
                httpGet:
                  path: /ok
                  port: 8000
                periodSeconds: 15
                timeoutSeconds: 5
                failureThreshold: 6
```

**步骤 3：在 Helm 安装/升级期间应用**

当您使用 Helm 部署或升级 LangSmith 实例时，将应用此配置。通过 LangSmith UI 创建的所有用户部署都将自动继承这些注册表凭据。

有关特定于注册表的身份验证方法（AWS ECR、Azure ACR、GCP Artifact Registry 等），请参阅[Kubernetes 关于从私有注册表拉取镜像的文档](https://kubernetes.io/docs/tasks/configure-pod-container/pull-image-private-registry/)。
