本指南将向您展示如何向 LangSmith 应用程序添加自定义认证。本页上的步骤同时适用于 [云端 (cloud)](/langsmith/cloud) 和 [自托管 (self-hosted)](/langsmith/self-hosted) 部署。它不适用于在您自己的自定义服务器中独立使用 [LangGraph 开源库](/oss/langgraph/overview)。

## 为您的部署添加自定义认证

要利用自定义认证并在部署中访问用户级别元数据，请设置自定义认证，以便通过自定义认证处理器自动填充 `config["configurable"]["langgraph_auth_user"]` 对象。然后，您可以在图中通过 `langgraph_auth_user` 键来访问此对象，以[允许代理代表用户执行已认证的操作](#enable-agent-authentication)。

1. 实现认证：

    <Note>
    如果没有自定义的 `@auth.authenticate` 处理器，LangGraph 只会看到 API 密钥的所有者（通常是开发者），因此请求不会限定到单个最终用户。要传播自定义令牌，您必须实现自己的处理器。
    </Note>

    ```python
    from langgraph_sdk import Auth
    import requests

    auth = Auth()

    def is_valid_key(api_key: str) -> bool:
        is_valid = # 您的 API 密钥验证逻辑
        return is_valid

    @auth.authenticate # (1)!
    async def authenticate(headers: dict) -> Auth.types.MinimalUserDict:
        api_key = headers.get(b"x-api-key")
        if not api_key or not is_valid_key(api_key):
            raise Auth.exceptions.HTTPException(status_code=401, detail="Invalid API key")

        # 从您的秘密存储中获取用户特定的令牌
        user_tokens = await fetch_user_tokens(api_key)

        return { # (2)!
            "identity": api_key,  # 从 LangSmith 获取用户 ID
            "github_token" : user_tokens.github_token
            "jira_token" : user_tokens.jira_token
            # ... 在此处放置自定义字段/密钥
        }
    ```
  - 此处理器接收请求（请求头等）、验证用户，并返回一个包含至少一个 `identity` 字段的字典。
  - 您可以添加任何所需的自定义字段（例如：OAuth 令牌、角色、组织 ID 等）。

2. 在您的 [`langgraph.json`](/langsmith/application-structure#configuration-file) 文件中，添加您的认证文件的路径：

    ```json highlight={7-9}
    {
        "dependencies": ["."],
        "graphs": {
        "agent": "./agent.py:graph"
        },
        "env": ".env",
        "auth": {
            "path": "./auth.py:my_auth"
        }
    }
    ```
3. 在服务器上设置好认证后，请求必须包含基于您所选方案所需的授权信息。假设您正在使用 JWT 令牌认证，您可以使用以下任一方法访问您的部署：

    <Tabs>
        <Tab title="Python Client">
      ```python

      my_token = "your-token" # 实际上，您会使用您的认证提供商生成一个带签名的令牌
      client = get_client(
          url="http://localhost:2024",
          headers={"Authorization": f"Bearer {my_token}"}
      )
      threads = await client.threads.search()
      ```
        </Tab>
        <Tab title="Python RemoteGraph">
      ```python

          "agent",

      ```
        </Tab>

## 启用代理认证

在 [认证](#add-custom-authentication-to-your-deployment) 之后，平台会创建一个特殊的配置对象 (`config`) 并传递给 LangSmith 部署。此对象包含当前用户的信息，包括您从 `@auth.authenticate` 处理器返回的任何自定义字段。

若要允许代理代表用户执行已认证的操作，请通过 `langgraph_auth_user` 键在图中访问此对象：

```python
def my_node(state, config):
    user_config = config["configurable"].get("langgraph_auth_user")
    # token 在 @auth.authenticate 函数期间已解析
    token = user_config.get("github_token","")
    ...
```

<Note>
请从安全的秘密存储中获取用户凭证。不建议将密钥存储在图状态中。
</Note>

### 为 Studio 授权用户

默认情况下，如果您为资源添加了自定义授权，这将也适用于从 [Studio](/langsmith/studio) 进行的交互。如果需要，您可以通过检查 [is_studio_user()](https://langchain-ai.github.io/langgraph/cloud/reference/sdk/python_sdk_ref/#langgraph_sdk.auth.types.StudioUser) 来区别对待已登录的 Studio 用户。

<Note>
`is_studio_user` 是在 `langgraph-sdk` 的 0.1.73 版本中添加的。如果您使用的是旧版本，仍然可以检查 `isinstance(ctx.user, StudioUser)`。
</Note>

```python
from langgraph_sdk.auth import is_studio_user, Auth
auth = Auth()

# ... 设置 authenticate 等

@auth.on
async def add_owner(
    ctx: Auth.types.AuthContext,
    value: dict  # 要发送到此访问方法的有效负载
) -> dict:  # 返回一个限制对资源访问的筛选器字典
    if is_studio_user(ctx.user):
        return {}

    filters = {"owner": ctx.user.identity}
    metadata = value.setdefault("metadata", {})
    metadata.update(filters)
    return filters
```

仅当您希望允许开发人员访问部署在托管 LangSmith SaaS 上的图形时，才使用此方法。
