**上下文工程（Context engineering）** 是构建动态系统的实践，旨在以正确的格式提供正确的信息和工具，以便 AI 应用能够完成任务。上下文可以沿着两个关键维度进行表征：

1. 按**可变性（mutability）**：
  * **静态上下文（Static context）**：在执行期间不会改变的**不可变**数据（例如：用户元数据、数据库连接、工具）。
  * **动态上下文（Dynamic context）**：随着应用程序的运行而**可变**的数据（例如：对话历史、中间结果、工具调用观察值）。
2. 按**生命周期（lifetime）**：
  * **运行时上下文（Runtime context）**：作用域限定在**单次运行或调用**中的数据。
  * **跨对话上下文（Cross-conversation context）**：在**多个对话或会话中持续存在**的数据。

<Tip>
    运行时上下文指的是**本地上下文**：即代码运行所需的那些数据和依赖项。它**不**指的是：

    * **LLM 上下文**：即传递给 LLM 提示词（prompt）的数据。
    * **“上下文窗口”（context window）**：即可以传递给 LLM 的最大 token 数量。

    :::python
    运行时上下文是依赖注入（dependency injection）的一种形式，可用于优化 LLM 上下文。它允许你在运行时将依赖项（如数据库连接、用户 ID 或 API 客户端）提供给工具和节点，而不是将它们硬编码。例如，你可以使用运行时上下文中的用户元数据来获取用户偏好设置并将它们馈送到上下文窗口中。
    :::

    :::js
    运行时上下文是你在代理（agent）中传递数据的方式。与其将内容存储在全局状态中，不如将值（如数据库连接、用户会话或配置）附加到上下文并从工具和中间件中访问它们。这使得系统保持**无状态（stateless）、可测试和可重用**。例如，你可以使用运行时上下文中的用户元数据来获取用户偏好设置并将它们馈送到上下文窗口中。
    :::

</Tip>

LangGraph 提供了三种管理上下文的方式，这些方式结合了可变性和生命周期维度：

:::python
| 上下文类型                                                                        | 描述                                           | 可变性 | 生命周期           | 访问方法                               |
| --------------------------------------------------------------------------------- | ---------------------------------------------- | ------ | ------------------ | --------------------------------------- |
| [**静态运行时上下文**](#static-runtime-context)                                   | 启动时传入的用户元数据、工具、数据库连接         | 静态   | 单次运行           | `invoke`/`stream` 的 `context` 参数     |
| [**动态运行时上下文（状态）**](#dynamic-runtime-context-state)                    | 在单次运行中演变的可变数据                     | 动态   | 单次运行           | LangGraph 状态对象（state object）      |
| [**动态跨对话上下文（存储）**](#dynamic-cross-conversation-context-store)         | 在多个对话中持久化的共享数据                   | 动态   | 跨对话             | LangGraph 存储（store）                 |

## 静态运行时上下文

**静态运行时上下文**代表**不可变**数据，例如用户元数据、工具和数据库连接，这些数据是通过对 `invoke`/`stream` 的 `context` 参数在运行开始时传递给应用的。此数据在执行期间不会改变。

```python
@dataclass
class ContextSchema:
    user_name: str

graph.invoke(
    {"messages": [{"role": "user", "content": "hi!"}]},
    context={"user_name": "John Smith"}  # [!code highlight]
)
```

<Tabs>
    <Tab title="代理 Prompt">
    ```python
    from dataclasses import dataclass
    from langchain.agents import create_agent
    from langchain.agents.middleware import dynamic_prompt, ModelRequest


    @dataclass
    class ContextSchema:
        user_name: str

    @dynamic_prompt  # [!code highlight]
    def personalized_prompt(request: ModelRequest) -> str:  # [!code highlight]
        user_name = request.runtime.context.user_name
        return f"你是一个有帮助的助手。请按 {user_name} 来称呼用户。"

    agent = create_agent(
        model="claude-sonnet-4-5-20250929",
        tools=[get_weather],
        middleware=[personalized_prompt],
        context_schema=ContextSchema
    )

    agent.invoke(
        {"messages": [{"role": "user", "content": "sf 天气怎么样"}]},
        context=ContextSchema(user_name="John Smith")  # [!code highlight]
    )
```

    有关详细信息，请参阅 [Agents](/oss/langchain/agents)。

<a id="static-context"></a>
## 配置 (Config)

Config 用于用户元数据或 API 密钥等**不可变**数据。当你有一些在运行中途不会改变的值时，请使用它。

使用一个称为 **"configurable"** 的键来指定配置，该键为此目的被保留。

```typescript
await graph.invoke(
  { messages: [{ role: "user", content: "hi!" }] },
  { configurable: { user_id: "user_123" } } // [!code highlight]
);
```
:::

## 动态运行时上下文

**动态运行时上下文**代表可以在单次运行中演变的可变数据，并通过 LangGraph 状态对象进行管理。这包括对话历史、中间结果以及从工具或 LLM 输出派生的值。在 LangGraph 中，状态对象充当运行期间的[短期记忆](/oss/concepts/memory)。

<Tabs>
    <Tab title="在代理中">
    示例展示了如何将状态整合到代理的**提示词（prompt）**中。

    代理的**工具**也可以访问状态，工具可以根据需要读取或更新状态。有关详细信息，请参阅[工具调用指南](/oss/langchain/tools#short-term-memory)。

    :::python

    ```python
    from langchain.agents import create_agent
    from langchain.agents.middleware import dynamic_prompt, ModelRequest
    from langchain.agents import AgentState


    class CustomState(AgentState):  # [!code highlight]
        user_name: str

    @dynamic_prompt  # [!code highlight]
    def personalized_prompt(request: ModelRequest) -> str:  # [!code highlight]
        user_name = request.state.get("user_name", "User")
        return f"你是一个有帮助的助手。用户的名字是 {user_name}"

    agent = create_agent(
        model="claude-sonnet-4-5-20250929",
        tools=[...],
        state_schema=CustomState,  # [!code highlight]
        middleware=[personalized_prompt],  # [!code highlight]
    )

    agent.invoke({
        "messages": "hi!",
        "user_name": "John Smith"
    })
    ```
    :::

    :::js

    ```typescript
    import { createAgent, createMiddleware } from "langchain";
    import type { AgentState } from "langchain";
    import * as z from "zod";

    const CustomState = z.object({ // [!code highlight]
      userName: z.string(),
    });

    const personalizedPrompt = createMiddleware({ // [!code highlight]
      name: "PersonalizedPrompt",
      stateSchema: CustomState,
      wrapModelCall: (request, handler) => {
        const userName = request.state.userName || "User";
        const systemPrompt = `你是一个有帮助的助手。用户的名字是 ${userName}`;
        return handler({ ...request, systemPrompt });
      },
    });

    const agent = createAgent({  // [!code highlight]
      model: "claude-sonnet-4-5-20250929",
      tools: [/* 你的工具在这里 */],
      middleware: [personalizedPrompt] as const, // [!code highlight]
    });

    await agent.invoke({
      messages: [{ role: "user", content: "hi!" }],
      userName: "John Smith",
    });
    ```
    :::
    </Tab>
    <Tab title="在工作流中">
    :::python
    ```python
    from typing_extensions import TypedDict
    from langchain.messages import AnyMessage
    from langgraph.graph import StateGraph

    class CustomState(TypedDict):  # [!code highlight]
        messages: list[AnyMessage]
        extra_field: int

    def node(state: CustomState):  # [!code highlight]
        messages = state["messages"]
        ...
        return {  # [!code highlight]
            "extra_field": state["extra_field"] + 1  # [!code highlight]
        }

    builder = StateGraph(State)
    builder.add_node(node)
    builder.set_entry_point("node")
    graph = builder.compile()
    ```
    :::

    :::js
    ```typescript
    import type { BaseMessage } from "@langchain/core/messages";
    import { StateGraph, MessagesZodMeta, START } from "@langchain/langgraph";
    import { registry } from "@langchain/langgraph/zod";
    import * as z from "zod";

    const CustomState = z.object({  // [!code highlight]
      messages: z
        .array(z.custom<BaseMessage>())
        .register(registry, MessagesZodMeta),
      extraField: z.number(),
    });

    const builder = new StateGraph(CustomState)
      .addNode("node", async (state) => {  // [!code highlight]
        const messages = state.messages;
        // ...
        return {  // [!code highlight]
          extraField: state.extraField + 1,
        };
      })
      .addEdge(START, "node");

    const graph = builder.compile();
    ```

## 动态跨对话上下文

**动态跨对话上下文**代表跨多个对话或会话持久化且可变的数据，通过 LangGraph 存储（store）进行管理。这包括用户配置文件、偏好设置和历史交互记录。LangGraph 存储充当多个运行期间的[长期记忆](/oss/concepts/memory#long-term-memory)。可用于读取或更新持久性事实（例如：用户配置文件、偏好设置、先前的交互）。
