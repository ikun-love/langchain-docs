LangChain 受以下几个核心信念驱动：

- 大型语言模型（LLM）是出色、强大的新技术。
- 将 LLM 与外部数据源结合使用时，它们的性能更佳。
- LLM 将会改变未来应用的形态。具体来说，未来的应用将越来越具有“智能体”（Agentic）的特性。
- 我们仍处于这场变革的早期阶段。
- 尽管构建这些智能体应用的**原型**很容易，但要构建出足够可靠、可以投入生产的智能体仍然非常困难。

LangChain 主要关注两个核心目标：

<Steps>
    <Step title="我们希望赋能开发者使用最好的模型进行构建。">
        不同的提供商暴露了不同的 API 接口，具有不同的模型参数和消息格式。
        标准化这些模型输入和输出是我们的核心关注点，这样开发者可以轻松切换到最新的 SOTA（State-of-the-Art，最先进的）模型，避免被特定提供商锁定。
    </Step>
    <Step title="我们希望让模型更易于用于编排更复杂的、需要与其他数据和计算交互的流程。">
        模型的使用不应仅限于*文本生成*——它们还应该被用来编排更复杂的、需要与其他数据交互的工作流。LangChain 使得定义 [工具](/oss/langchain/tools) 供 LLM 动态使用变得容易，同时也帮助处理非结构化数据的解析和访问。
    </Step>
</Steps>

## 历史沿革

鉴于该领域的快速变化，LangChain 也经历了持续的演进。下面是 LangChain 如何随着时间推移而发展的简要时间线，反映了使用 LLM 进行构建的理念变化：

<Update label="2022-10-24" description="v0.0.1">
    在 ChatGPT 发布前的一个月，**LangChain 作为 Python 包正式发布**。它主要包含两个核心组件：

    - LLM 抽象层
    - “链”（Chains），即针对常见用例预先设定的计算步骤。例如 RAG（检索增强生成）：先运行一个检索步骤，再运行一个生成步骤。

    LangChain 这个名字来源于“Language”（指语言模型）和“Chains”（链）。
</Update>

<Update label="2022-12">
    LangChain 中添加了第一个通用智能体。

    这些通用智能体基于 [ReAct 论文](https://arxiv.org/abs/2210.03629)（ReAct 代表 Reasoning and Acting，即推理与行动）。它们使用 LLM 生成代表工具调用的 JSON，然后解析该 JSON 以确定要调用哪些工具。
</Update>

<Update label="2023-01">
    OpenAI 发布了“聊天补全”（Chat Completion）API。

    在此之前，模型接收字符串并返回字符串。在 ChatCompletions API 中，模型演变为接收消息列表并返回一条消息。其他模型提供商也纷纷效仿，LangChain 随之更新以支持消息列表格式。
</Update>

<Update label="2023-01">
    LangChain 发布了 JavaScript 版本。

    LLM 和智能体将改变应用的构建方式，而 JavaScript 是应用开发者的主要语言。
</Update>

<Update label="2023-02">
    **LangChain Inc. 公司围绕开源的 LangChain 项目成立**。

    主要目标是“让智能代理无处不在”（make intelligent agents ubiquitous）。团队意识到，虽然 LangChain 是一个关键组成部分（它简化了 LLM 的上手过程），但还需要其他组件的配合。
</Update>

<Update label="2023-03">
    OpenAI 在其 API 中发布了“函数调用”（function calling）功能。

    这使得 API 能够明确生成代表工具调用的数据包（payloads）。其他模型提供商也遵循了这一做法，LangChain 被更新为将此作为工具调用的首选方法（而不是解析 JSON）。
</Update>

<Update label="2023-06">
    LangChain Inc. 以闭源平台的形式**发布了 LangSmith**，提供可观测性和评估（observability and evals）。

    构建智能体的核心难题在于提高其可靠性，LangSmith 正是为了解决这一需求而构建的，它提供了可观测性和评估功能。LangChain 也被更新为与 LangSmith 无缝集成。
</Update>

<Update label="2024-01" description="v0.1.0">
    **LangChain 发布 0.1.0 版本**，这是首个非 0.0.x 版本。

    随着行业从原型设计转向生产部署的成熟，LangChain 加强了对稳定性的关注。
</Update>

<Update label="2024-02">
    **LangGraph 作为开源库发布**。

    最初的 LangChain 关注两个方面：LLM 抽象层，以及快速上手常见应用的更高级接口；但它缺少一个允许开发者精确控制智能体流程的底层编排层。LangGraph 应运而生。

    在构建 LangGraph 时，我们吸取了构建 LangChain 的经验教训，并增加了我们认为必需的功能：流式传输（streaming）、持久化执行（durable execution）、短期记忆（short-term memory）、人机协作循环（human-in-the-loop）等等。
</Update>

<Update label="2024-10">
    LangGraph 成为构建任何多于一次 LLM 调用的 AI 应用的首选方式。

    随着开发者试图提高其应用的可靠性，他们比高级接口所能提供的需要更多的控制。LangGraph 提供了这种底层的灵活性。LangChain 中大多数原有的链 (chains) 和智能体 (agents) 被标记为弃用，并提供了迁移到 LangGraph 的指南。LangChain 中仍然保留了一个基于 LangGraph 创建的高级抽象：一个智能体抽象。它构建在底层 LangGraph 之上，并具有与 LangChain 中 ReAct 智能体相同的接口。
</Update>

<Update label="2025-10-20" description="v1.0.0">
    **LangChain 发布 1.0 版本**，包含两大核心变更：

    1. 对 `langchain` 中所有链和智能体进行了彻底的改造。所有链和智能体现在仅由一个高级抽象替代：即构建在 LangGraph 之上的智能体抽象。这是最初在 LangGraph 中创建的高级抽象，现已迁移到 LangChain 中。

</Update>
