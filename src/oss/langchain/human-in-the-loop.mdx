---
title: 人在回路 (Human-in-the-loop)
---

`Human-in-the-Loop` (HITL) [中间件](/oss/langchain/middleware/built-in#human-in-the-loop) 允许您为智能体（Agent）的工具调用添加人工干预和审核机制。当模型建议执行一个可能需要审查的操作时（例如写入文件或执行 SQL），中间件可以暂停执行，等待人工决策。

它通过将每个工具调用与可配置的策略进行比对来实现这一点。如果需要人工干预，中间件会发出一个 @[interrupt]（中断）信号，从而停止当前执行流程。系统的图状态会使用 LangGraph 的 [持久化层](/oss/langgraph/persistence) 进行保存，因此执行可以安全地暂停并稍后恢复。

接下来的人工决策将决定流程的走向：操作可以按原样批准 (`approve`)、修改后再运行 (`edit`)，或者附带反馈被拒绝 (`reject`)。

## 中断决策类型

[中间件](/oss/langchain/middleware/built-in#human-in-the-loop) 定义了三种内置的人工对中断的响应方式：

| 决策类型 | 描述 | 示例用例 |
|---|---|---|
| ✅ `approve` | 操作按原样批准并执行，不做任何更改。 | 批准发送的邮件草稿，一字不差地发送出去 |
| ✏️ `edit` | 工具调用在修改后执行。 | 修改发送邮件前的收件人信息 |
| ❌ `reject` | 工具调用被拒绝，并在对话中添加解释性反馈。 | 拒绝邮件草稿，并说明应如何重写 |

每个工具可用的决策类型取决于您在 `interrupt_on` 中配置的策略。当多个工具调用同时暂停时，每个操作都需要一个单独的决策。决策的顺序必须与中断请求中操作出现的顺序保持一致。

<Tip>
在**编辑**工具参数时，请谨慎修改。对原始参数进行大幅度修改可能会导致模型重新评估其方法，并可能导致工具被执行多次或产生意料之外的行为。
</Tip>


## 配置中断

要使用 HITL，在创建 Agent 时，需要将 [中间件](/oss/langchain/middleware/built-in#human-in-the-loop) 添加到 Agent 的 `middleware` 列表中。

您需要配置一个映射，将工具的操作名称与其允许的决策类型进行关联。当工具调用匹配此映射中的操作时，中间件就会中断执行。

:::python
```python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware # [!code highlight]
from langgraph.checkpoint.memory import InMemorySaver # [!code highlight]


agent = create_agent(
    model="gpt-4o",
    tools=[write_file_tool, execute_sql_tool, read_data_tool],
    middleware=[
        HumanInTheLoopMiddleware( # [!code highlight]
            interrupt_on={
                "write_file": True,  # 允许所有决策 (approve, edit, reject)
                "execute_sql": {"allowed_decisions": ["approve", "reject"]},  # 不允许编辑
                # 安全操作，无需批准
                "read_data": False,
            },
            # 中断消息的前缀 - 将与工具名称和参数组合形成完整的消息
            # 例如: "Tool execution pending approval: execute_sql with query='DELETE FROM...'"
            # 单个工具可以通过在其中断配置中指定 "description" 来覆盖此项
            description_prefix="Tool execution pending approval",
        ),
    ],
    # 人在回路功能需要检查点（checkpointing）来处理中断。
    # 在生产环境中，请使用如 AsyncPostgresSaver 这样的持久化检查点。
    checkpointer=InMemorySaver(),  # [!code highlight]
)
```
:::

:::js
```ts

            },
            // 中断消息的前缀 - 将与工具名称和参数组合形成完整的消息
            // 例如: "Tool execution pending approval: execute_sql with query='DELETE FROM...'"
            // 单个工具可以通过在其中断配置中指定 "description" 来覆盖此项
            descriptionPrefix: "Tool execution pending approval",
        }),
    ],
    // 人在回路功能需要检查点（checkpointing）来处理中断。
    // 在生产环境中，请使用如 AsyncPostgresSaver 这样的持久化检查点。
    checkpointer: new MemorySaver(), // [!code highlight]
});
```
:::

## 响应中断

当您调用 Agent 时，它会一直运行，直到完成或触发中断。当中断工具调用匹配您在 `interrupt_on` 中配置的策略时，会触发中断。在这种情况下，调用结果将包含一个 `__interrupt__` 字段，其中包含需要审查的操作。然后，您可以将这些操作展示给审阅者，并在提供决策后恢复执行。


:::python
```python
from langgraph.types import Command

# 人在回路功能利用了 LangGraph 的持久化层。
# 您必须提供一个线程 ID 来将执行与对话线程关联起来，
# 这样对话才能暂停和恢复（以便进行人工审查）。
config = {"configurable": {"thread_id": "some_id"}} # [!code highlight]
# 运行图，直到命中中断。
result = agent.invoke(
    {
        "messages": [
            {
                "role": "user",
                "content": "Delete old records from the database",
            }
        ]
    },
    config=config # [!code highlight]
)

# 中断包含完整的 HITL 请求，内含 action_requests 和 review_configs
print(result['__interrupt__'])
# > [
# >    Interrupt(
# >       value={
# >          'action_requests': [
# >             {
# >                'name': 'execute_sql',
# >                'arguments': {'query': 'DELETE FROM records WHERE created_at < NOW() - INTERVAL \'30 days\';'},
# >                'description': 'Tool execution pending approval\n\nTool: execute_sql\nArgs: {...}'
# >             }
# >          ],
# >          'review_configs': [
# >             {
# >                'action_name': 'execute_sql',
# >                'allowed_decisions': ['approve', 'reject']
# >             }
# >          ]
# >       }
# >    )
# > ]


# 使用批准决策恢复
agent.invoke(
    Command( # [!code highlight]
        resume={"decisions": [{"type": "approve"}]}  # 或 "reject" [!code highlight]
    ), # [!code highlight]
    config=config # 使用相同的线程 ID 来恢复暂停的对话
)
```
:::

:::js
```typescript

```

## 结合人机回路的流式处理 (Streaming)

您可以使用 `stream()` 代替 `invoke()` 来实时获取 Agent 运行和处理中断时的更新。使用 `stream_mode=['updates', 'messages']` 可以同时流式传输 Agent 进度和 LLM 令牌。

:::python
```python
from langgraph.types import Command

config = {"configurable": {"thread_id": "some_id"}}

# 流式传输 Agent 进度和 LLM 令牌，直到发生中断
for mode, chunk in agent.stream(
    {"messages": [{"role": "user", "content": "Delete old records from the database"}]},
    config=config,
    stream_mode=["updates", "messages"],  # [!code highlight]
):
    if mode == "messages":
        # LLM 令牌
        token, metadata = chunk
        if token.content:
            print(token.content, end="", flush=True)
    elif mode == "updates":
        # 检查是否发生中断
        if "__interrupt__" in chunk:
            print(f"\n\nInterrupt: {chunk['__interrupt__']}")

# 人工决策后，以流式方式恢复
for mode, chunk in agent.stream(
    Command(resume={"decisions": [{"type": "approve"}]}),
    config=config,
    stream_mode=["updates", "messages"],
):
    if mode == "messages":
        token, metadata = chunk
        if token.content:
            print(token.content, end="", flush=True)
```
:::

:::js
```typescript
import { Command } from "@langchain/langgraph";

const config = { configurable: { thread_id: "some_id" } };

// 流式传输 Agent 进度和 LLM 令牌，直到发生中断
for await (const [mode, chunk] of await agent.stream(
    { messages: [{ role: "user", content: "Delete old records from the database" }] },
    { ...config, streamMode: ["updates", "messages"] }  // [!code highlight]
)) {
    if (mode === "messages") {
        // LLM 令牌
        const [token, metadata] = chunk;
        if (token.content) {
            process.stdout.write(token.content);
        }
    } else if (mode === "updates") {
        // 检查是否发生中断
        if ("__interrupt__" in chunk) {
            console.log(`\n\nInterrupt: ${JSON.stringify(chunk.__interrupt__)}`);
        }
    }
}

// 人工决策后，以流式方式恢复
for await (const [mode, chunk] of await agent.stream(
    new Command({ resume: { decisions: [{ type: "approve" }] } }),
    { ...config, streamMode: ["updates", "messages"] }
)) {
    if (mode === "messages") {
        const [token, metadata] = chunk;
        if (token.content) {
            process.stdout.write(token.content);
        }
    }
}
```
:::

有关流模式的更多详细信息，请参见 [流式处理](/oss/langchain/streaming) 指南。

## 执行生命周期

中间件定义了一个 `after_model` 钩子，它在模型生成响应之后但在任何工具调用执行之前运行：

1. Agent 调用模型生成响应。
2. 中间件检查响应中是否存在工具调用。
3. 如果任何调用需要人工输入，中间件会构建一个包含 `action_requests` 和 `review_configs` 的 `HITLRequest` 并调用 @[interrupt]。
4. Agent 等待人工决策。
5. 根据 `HITLResponse` 中的决策，中间件执行被批准或编辑的调用，为被拒绝的调用合成 @[ToolMessage]，然后恢复执行。



## 自定义 HITL 逻辑

对于更专业的流程，您可以通过直接使用 @[interrupt] 原语和 [中间件](/oss/langchain/middleware) 抽象来构建自定义的 HITL 逻辑。

请参考上面的 [执行生命周期](#execution-lifecycle)，以了解如何将中断集成到 Agent 的操作中。
