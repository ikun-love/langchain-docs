`langchain-nvidia-ai-endpoints` 包中包含了 LangChain 的集成，用于使用 NVIDIA NIM 推理微服务上的模型来构建应用程序。NIM 支持来自社区以及 NVIDIA 的跨越聊天、嵌入和重排序等领域的模型。这些模型经过 NVIDIA 的优化，可在 NVIDIA 加速基础设施上提供最佳性能，并作为 NIM 部署。NIM 是一种易于使用的预构建容器，只需在 NVIDIA 加速基础设施上使用**单条命令**即可在任何地方部署。

您可以在 [NVIDIA API 目录](https://build.nvidia.com/) 上测试 NVIDIA 托管的 NIM 部署。测试后，NIMs 可以使用 NVIDIA AI Enterprise 许可证从 NVIDIA API 目录导出，并在本地或云端运行，从而使企业能够拥有并完全控制其知识产权（IP）和 AI 应用。

NIMs 是**按模型**打包为容器镜像，并通过 NVIDIA NGC Catalog 作为 NGC 容器镜像分发。NIM 的核心在于为 AI 模型推理提供简单、一致且熟悉的人机接口（API）。

本示例将介绍如何使用 LangChain 通过 `NVIDIAEmbeddings` 类与受支持的 [NVIDIA 检索问答嵌入模型 (NVIDIA Retrieval QA Embedding Model)](https://build.nvidia.com/nvidia/embed-qa-4) 针对 [检索增强生成 (retrieval-augmented generation)](https://developer.nvidia.com/blog/build-enterprise-retrieval-augmented-generation-apps-with-nvidia-retrieval-qa-embedding-model/) 进行交互。

有关如何通过此 API 访问聊天模型的更多信息，请参阅 [ChatNVIDIA](https://python.langchain.com/docs/integrations/chat/nvidia_ai_endpoints/) 文档。

## 设置

**开始操作：**

1. 在 [NVIDIA](https://build.nvidia.com/) 注册一个免费账户，NVIDIA 托管着 NVIDIA AI 基础模型。

2. 选择 `Retrieval` 选项卡，然后选择您希望使用的模型。

3. 在 `Input` 下，选择 `Python` 选项卡，然后点击 `Get API Key`。接着点击 `Generate Key`。

4. 复制生成的密钥并将其保存为 `NVIDIA_API_KEY`。完成此操作后，您应该就可以访问相应的端点了。

```python
import getpass
import os

# del os.environ['NVIDIA_API_KEY']  ## 删除密钥并重置
if os.environ.get("NVIDIA_API_KEY", "").startswith("nvapi-"):
    print("环境中已存在有效的 NVIDIA_API_KEY。删除以重置")
else:
    nvapi_key = getpass.getpass("NVAPI 密钥 (以 nvapi- 开头): ")
    assert nvapi_key.startswith("nvapi-"), f"{nvapi_key[:5]}... 不是一个有效的密钥"
    os.environ["NVIDIA_API_KEY"] = nvapi_key
```

## 使用 NVIDIA API Catalog 上的 NIM

在初始化嵌入模型时，您可以传入一个模型名称来选择模型，例如下面的 `NV-Embed-QA`，或者通过不传入任何参数来使用默认模型。

```python
from langchain_nvidia_ai_endpoints import NVIDIAEmbeddings

embedder = NVIDIAEmbeddings(model="NV-Embed-QA")
```

该模型是经过微调的 E5-large 模型，支持预期的 @[`Embeddings`] 方法，包括：

- `embed_query`: 为单个查询样本生成查询嵌入。

- `embed_documents`: 为您希望搜索的一系列文档生成文档嵌入（批量处理）。

- `aembed_query`/`aembed_documents`: 上述方法的异步版本。

## 使用自托管的 NVIDIA NIM

当准备部署时，您可以使用 NVIDIA NIM（包含在 NVIDIA AI Enterprise 软件许可证中）自托管模型，并在任何地方运行它们，从而拥有您定制化的控制权，并完全掌控您的知识产权（IP）和 AI 应用。

[了解更多关于 NIM 的信息](https://developer.nvidia.com/blog/nvidia-nim-offers-optimized-inference-microservices-for-deploying-ai-models-at-scale/)

```python
from langchain_nvidia_ai_endpoints import NVIDIAEmbeddings

# 连接到在 localhost:8080 运行的嵌入 NIM
embedder = NVIDIAEmbeddings(base_url="http://localhost:8080/v1")
```

### 嵌入运行时

```python
print("\n顺序嵌入 (Sequential Embedding): ")
q_embeddings = [
    embedder.embed_query("What's the weather like in Komchatka?"),
    embedder.embed_query("What kinds of food is Italy known for?"),
    embedder.embed_query("What's my name? I bet you don't remember..."),
    embedder.embed_query("What's the point of life anyways?"),
    embedder.embed_query("The point of life is to have fun :D"),
]
print("形状 (Shape):", (len(q_embeddings), len(q_embeddings[0])))
```

### 文档嵌入

```python
print("\n批量文档嵌入 (Batch Document Embedding): ")

```

## 截断 (Truncation)

嵌入模型通常有一个固定的上下文窗口，它决定了可以嵌入的最大输入 Token 数。这个限制可能是一个硬性限制（等于模型的最大输入 Token 长度），也可能是一个有效限制（超过此限制后嵌入的准确性会下降）。

由于模型处理的是 Token，而应用程序通常处理的是文本，应用程序很难确保其输入始终在模型的 Token 限制之内。默认情况下，如果输入过大，将抛出异常。

为了提供帮助，NVIDIA 的 NIM（API Catalog 或本地）提供了一个 `truncate` 参数，该参数会在服务器端截断过大的输入。

`truncate` 参数有三种选项：

- "NONE": 默认选项。如果输入过大，将抛出异常。
- "START": 服务器从开头（左侧）截断输入，根据需要丢弃 Token。
- "END": 服务器从末尾（右侧）截断输入，根据需要丢弃 Token。

```python
long_text = "AI is amazing, amazing is " * 100
```

```python
strict_embedder = NVIDIAEmbeddings()
try:
    strict_embedder.embed_query(long_text)
except Exception as e:
    print("错误 (Error):", e)
```

```python
truncating_embedder = NVIDIAEmbeddings(truncate="END")
truncating_embedder.embed_query(long_text)[:5]
```

## RAG 检索

以下是对 [LangChain 表达式语言检索食谱条目 (LangChain Expression Language Retrieval Cookbook entry)](
https://python.langchain.com/docs/expression_language/cookbook/retrieval) 初始示例的重新利用，但使用 AI Foundation Models 中可用于其游乐场环境的 [Mixtral 8x7B Instruct](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/ai-foundation/models/mixtral-8x7b) 和 [NVIDIA Retrieval QA Embedding](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/ai-foundation/models/nvolve-40k) 模型来执行。食谱中的后续示例也能如期运行，我们鼓励您使用这些选项进行探索。

**提示 (TIP):** 我们建议使用 Mixtral 进行内部推理（例如，用于数据提取、工具选择的指令遵循），并使用 Llama-Chat 模型来生成一个最终的、简单的响应，该响应基于历史记录和上下文来满足用户的需求。

```python
pip install -qU  langchain faiss-cpu tiktoken langchain-community

from operator import itemgetter

from langchain_community.vectorstores import FAISS
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_nvidia_ai_endpoints import ChatNVIDIA
```

```python
vectorstore = FAISS.from_texts(
    ["harrison worked at kensho"],
    embedding=NVIDIAEmbeddings(model="NV-Embed-QA"),
)
retriever = vectorstore.as_retriever()

prompt = ChatPromptTemplate.from_messages(
    [
        (
            "system",
            "仅根据以下上下文回答:\n<Documents>\n{context}\n</Documents>",
        ),
        ("user", "{question}"),
    ]
)

model = ChatNVIDIA(model="ai-mixtral-8x7b-instruct")

chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | prompt
    | model
    | StrOutputParser()
)

chain.invoke("harrison 在哪里工作？")
```

```python
prompt = ChatPromptTemplate.from_messages(
    [
        (
            "system",

            "\n仅使用以下语言回答: {language}",

    ]

    {

        "question": itemgetter("question"),
        "language": itemgetter("language"),
    }
    | prompt
    | model
    | StrOutputParser()
)

chain.invoke({"question": "where did harrison work", "language": "italian"})
```
