>[Activeloop Deep Memory（Activeloop 深度内存）](https://docs.activeloop.ai/performance-features/deep-memory) 是一套工具集，它能帮助你根据特定用例优化 Vector Store（向量存储），从而提高 LLM 应用的准确性。

`Retrieval-Augmented Generation`（检索增强生成，简称 `RAG`）最近受到了广泛关注。随着先进 RAG 技术和 Agent（智能体）的出现，RAGs 所能实现的功能潜力正在扩大。然而，在将 RAGs 应用于生产环境时，有几个挑战可能会限制其集成。在生产环境中实施 RAG 时需要考虑的首要因素是准确性（召回率）、成本和延迟。对于基本用例，OpenAI 的 Ada 模型配合朴素的相似性搜索就能产生令人满意的结果。然而，如果需要更高的搜索准确性或召回率，可能需要采用高级检索技术。这些方法可能涉及改变数据块（chunk）大小、多次重写查询等，这可能会增加延迟和成本。Activeloop 的 [Deep Memory（深度内存）](https://www.activeloop.ai/resources/use-deep-memory-to-boost-rag-apps-accuracy-by-up-to-22/) 是 `Activeloop Deep Lake` 用户可用的一个特性，它通过引入一个微小的神经网络层来解决这些问题。这个网络层经过训练，可以将用户查询与语料库中相关数据进行匹配。虽然这种添加在搜索过程中仅会带来极小的延迟增加，但它可以将检索准确性提高多达 27%，并且在不要求任何额外的先进 RAG 技术的情况下，仍然保持成本效益和易用性。

对于本教程，我们将解析 `DeepLake` 文档，并创建一个 RAG 系统，该系统能够回答文档中的问题。

from urllib.parse import urljoin

import requests
from bs4 import BeautifulSoup


def get_all_links(url):
    response = requests.get(url)
    if response.status_code != 200:
        print(f"未能检索页面: {url}")
        return []

    soup = BeautifulSoup(response.content, "html.parser")

    # 查找所有通常包含链接 href 属性的 'a' 标签
    links = [
        urljoin(url, a["href"]) for a in soup.find_all("a", href=True) if a["href"]
    ]

    return links

我们在上面展示了 `deep_memory` 的整体工作原理图。因此，要训练它，您需要相关性（relevance）、查询以及语料库数据（我们希望查询的数据）。语料库数据已在上一节中填充，这里我们将生成问题和相关性信息。

1. `questions` - 是一个字符串文本列表，其中每个字符串代表一个查询。
2. `relevance` - 包含每个问题真实答案（ground truth）的链接。可能有多篇文档包含给定问题的答案。因此，relevance 是一个 `List[List[tuple[str, float]]]`，其中外层列表代表查询，内层列表代表相关文档。元组包含 `(str, float)` 对，其中字符串代表源文档的 ID（对应于数据集中的 `id` 张量），而 float 表示当前文档与该问题的相关程度。

现在，让我们生成合成问题和相关性信息：

# 如果明确传入模型，我们需要确保它支持 OpenAI 函数调用 API。

```python
import random

from langchain_openai import OpenAIEmbeddings
from tqdm import tqdm


def generate_queries(docs: List[str], ids: List[str], n: int = 100):
    questions = []
    relevances = []
    pbar = tqdm(total=n)
    while len(questions) < n:
        # 1. 随机抽取一小段文本和相关 ID
        r = random.randint(0, len(docs) - 1)
        text, label = docs[r], ids[r]

        # 2. 生成查询并分配相关 ID
        generated_qs = [chain.run(input=text).question]
        questions.extend(generated_qs)
        relevances.extend([[(label, 1)] for _ in generated_qs])
        pbar.update(len(generated_qs))
        if len(questions) % 10 == 0:
            print(f"q: {len(questions)}")
    return questions[:n], relevances[:n]


chain = create_structured_output_chain(Questions, llm, prompt, verbose=False)
questions, relevances = generate_queries(docs, ids, n=200)

train_questions, train_relevances = questions[:100], relevances[:100]
test_questions, test_relevances = questions[100:], relevances[100:]
```

### 3.2 Deep Memory + RAGas

```python
from ragas.langchain import RagasEvaluatorChain
from ragas.metrics import (
    context_recall,
)
```

让我们将召回率转换为真实答案（ground truths）：

```python
def convert_relevance_to_ground_truth(docs, relevance):
    ground_truths = []

    for rel in relevance:
        ground_truth = []
        for doc_id, _ in rel:
            # 注意：这里的 doc_id 对应于 docs 列表的索引
            # 原始代码中 id/doc_id 的对应关系需要根据实际 ID 映射来确认，此处按索引对齐处理
            ground_truth.append(docs[doc_id])
        ground_truths.append(ground_truth)
    return ground_truths
```

```python
ground_truths = convert_relevance_to_ground_truth(docs, test_relevances)

for deep_memory in [False, True]:
    print("\nEvaluating with deep_memory =", deep_memory)
    print("===================================")

    retriever = db.as_retriever()
    retriever.search_kwargs["deep_memory"] = deep_memory

    qa_chain = RetrievalQA.from_chain_type(
        llm=ChatOpenAI(model="gpt-3.5-turbo"),
        chain_type="stuff",
        retriever=retriever,
        return_source_documents=True,
    )

    metrics = {
        "context_recall_score": 0,
    }

    eval_chains = {m.name: RagasEvaluatorChain(metric=m) for m in [context_recall]}

    for question, ground_truth in zip(test_questions, ground_truths):
        result = qa_chain({"query": question})
        result["ground_truths"] = ground_truth
        for name, eval_chain in eval_chains.items():
            score_name = f"{name}_score"
            metrics[score_name] += eval_chain(result)[score_name]

    for metric in metrics:
        metrics[metric] /= len(test_questions)
        print(f"{metric}: {metrics[metric]}")
    print("===================================")
```

### 3.4 Deep Memory 节省成本

Deep Memory 在不改变现有工作流程的情况下提高了检索准确性。此外，通过减小输入到 LLM 的 `top_k` 值，您可以通过减少 Token 使用量来显著削减推理成本。
