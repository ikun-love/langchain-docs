Oracle AI Vector Search 专为人工智能（AI）工作负载而设计，它允许您根据**语义**而非关键词来查询数据。
Oracle AI Vector Search 最大的优势之一是，可以将**非结构化数据**上的语义搜索与**结构化业务数据**上的关系搜索结合在同一个系统中。
这不仅功能强大，而且效率更高，因为它无需引入专门的向量数据库，从而消除了在多个系统之间进行数据碎片化的痛苦。

def manage_texts(vector_stores):
    """
    向每个向量存储中添加文本，演示重复添加的错误处理，并执行文本删除。
    为每个向量存储展示相似性搜索和索引创建。

    Args:
    - vector_stores (list): OracleVS 实例列表。
    """
    texts = ["Rohan", "Shailendra"]
    metadata = [
        {"id": "100", "link": "Document Example Test 1"},
        {"id": "101", "link": "Document Example Test 2"},
    ]

    for i, vs in enumerate(vector_stores, start=1):
        # 添加文本
        try:
            vs.add_texts(texts, metadata)
            print(f"\n\n\n向量存储 {i} 添加文本完成\n\n\n")
        except Exception as ex:
            print(f"\n\n\n向量存储 {i} 重复添加预期错误\n\n\n")

        # 使用 'id' 的值删除文本
        vs.delete([metadata[0]["id"]])
        print(f"\n\n\n向量存储 {i} 删除文本完成\n\n\n")

        # 相似性搜索
        results = vs.similarity_search("How are LOBS stored in Oracle Database", 2)
        print(f"\n\n\n向量存储 {i} 的相似性搜索结果: {results}\n\n\n")


vector_store_list = [

### 使用特定参数创建索引 (Index creation with specific parameters)

```python
def create_search_indices(connection):
    """
    为向量存储创建搜索索引，每个索引都有特定的参数，以适应其距离策略。
    """
    # DOT_PRODUCT 策略的索引
    # 注意我们正在创建一个带有默认参数的 HNSW 索引
    # 这将默认创建具有 8 个并行工作线程并使用 Oracle AI Vector Search 默认准确率的 HNSW 索引
    oraclevs.create_index(
        connection,
        vector_store_dot,
        params={"idx_name": "hnsw_idx1", "idx_type": "HNSW"},
    )

    # COSINE 策略的索引，带有特定参数
    # 注意我们正在创建一个并行数 16、目标准确率为 97% 的 HNSW 索引
    oraclevs.create_index(
        connection,
        vector_store_max,
        params={
            "idx_name": "hnsw_idx2",
            "idx_type": "HNSW",
            "accuracy": 97,
            "parallel": 16,
        },
    )

    # EUCLIDEAN_DISTANCE 策略的索引，带有特定参数
    # 注意我们通过指定邻居数 = 64 和 efConstruction = 100 的高级用户参数来创建 HNSW 索引
    oraclevs.create_index(
        connection,
        vector_store_euclidean,
        params={
            "idx_name": "hnsw_idx3",
            "idx_type": "HNSW",
            "neighbors": 64,
            "efConstruction": 100,
        },
    )

    # DOT_PRODUCT 策略的索引
    # 注意我们正在创建一个带有默认参数的 IVF 索引
    # 这将默认创建具有 8 个并行工作线程并使用 Oracle AI Vector Search 默认准确率的 IVF 索引
    oraclevs.create_index(
        connection,
        vector_store_dot_ivf,
        params={
            "idx_name": "ivf_idx1",
            "idx_type": "IVF",
        },
    )

    # COSINE 策略的索引，带有特定参数
    # 注意我们正在创建一个并行数 32、目标准确率为 90% 的 IVF 索引
    oraclevs.create_index(
        connection,
        vector_store_max_ivf,
        params={
            "idx_name": "ivf_idx2",
            "idx_type": "IVF",
            "accuracy": 90,
            "parallel": 32,
        },
    )

    # EUCLIDEAN_DISTANCE 策略的索引，带有特定参数
    # 注意我们通过指定高级用户参数 neighbor_part = 64 来创建 IVF 索引
    oraclevs.create_index(
        connection,
        vector_store_euclidean_ivf,
        params={"idx_name": "ivf_idx3", "idx_type": "IVF", "neighbor_part": 64},
    )

    print("索引创建完成。")


create_search_indices(connection)
```

### 高级搜索 (Advanced search)

Oracle Database 23ai 支持**预过滤 (pre-filtering)**、**内嵌过滤 (in-filtering)** 和**后过滤 (post-filtering)**，以增强 AI 向量搜索功能。这些过滤机制允许用户在执行向量相似性搜索之前、期间和之后应用约束，从而提高搜索性能和准确性。

Oracle 23ai 中过滤的关键点：

1. 预过滤 (Pre-filtering)
    将传统的 SQL 过滤器应用于向量相似性搜索之前的数据集，以缩小范围。
    通过限制 AI 算法处理的数据量来提高效率。
2. 内嵌过滤 (In-filtering)
    利用 AI 向量搜索，直接在向量嵌入上执行相似性搜索，使用优化的索引和算法。
    高效地根据向量相似性过滤结果，而无需执行完整数据集扫描。
3. 后过滤 (Post-filtering)
    在向量相似性搜索之后，应用额外的 SQL 过滤来完善结果。
    允许根据业务逻辑或其他元数据条件进行进一步的精炼。

**为什么这很重要？**

* 性能优化：预过滤显著减少了查询执行时间，使大规模数据集上的搜索更加高效。
* 准确性增强：内嵌过滤确保向量搜索具有语义意义，从而提高了搜索结果的质量。

#### 过滤详细信息 (Filter Details)

`OracleVS` 支持一组过滤器，可以使用 `filter` 参数应用于 `metadata` 字段。这些过滤器允许您根据各种标准选择和精炼数据。

**可用过滤运算符：**

| 运算符 (Operator) | 描述 (Description) |
| :--- | :--- |
| `\$exists` | 字段存在。 |
| `\$eq` | 字段值等于操作数的值 (`=`)。 |
| `\$ne` | 字段存在且值不等于操作数的值 (`!=`)。 |
| `\$gt` | 字段值大于操作数的值 (`>`)。 |
| `\$lt` | 字段值小于操作数的值 (`<`)。 |
| `\$gte` | 字段值大于或等于操作数的值 (`>=`)。 |
| `\$lte` | 字段值小于或等于操作数的值 (`<=`)。 |
| `\$between` | 字段值在操作数数组中的两个值之间（或等于）。 |
| `\$startsWith` | 字段值以操作数的值开头。 |
| `\$hasSubstring` | 字段值包含操作数作为子字符串。 |
| `\$instr` | 字段值包含操作数作为子字符串。（*注：在中文环境中，这通常与 `\$hasSubstring` 相似*） |
| `\$regex` | 字段值与给定的正则表达式模式匹配。 |
| `\$like` | 字段值匹配使用 SQL 风格语法的操作数模式。 |
| `\$in` | 字段值等于操作数数组中的至少一个值。 |
| `\$nin` | 字段存在，但其值不等于操作数数组中的任何值，或者字段不存在。 |
| `\$all` | 字段值是一个包含操作数数组中所有项的数组，或者与单个操作数匹配的标量值。 |

* 您可以使用逻辑运算符组合这些过滤器：

| 逻辑运算符 (Logical Operator) | 描述 (Description) |
| :--- | :--- |
| `\$and` | 逻辑 AND |
| `\$or` | 逻辑 OR |
| `\$nor` | 逻辑 NOR |

**示例过滤器：**

```json
{
  "age": 65,
  "name": {"$regex": "*rk"},
  "$or": [
    {
      "$and": [
        {"name": "Jason"},
        {"drinks": {"$in": ["tea", "soda"]}}
      ]
    },
    {
      "$nor": [
        {"age": {"$lt": 65}},
        {"name": "Jason"}
      ]
    }
  ]
}
```

**其他使用提示：**

* 当所有过滤器都必须满足时，可以省略 `$and`。以下两者是等效的：

```json
{ "$and": [
    { "name": { "$startsWith": "Fred" } },
    { "salary": { "$gt": 10000, "$lte": 20000 } }
]}
```

```json
{
  "name": { "$startsWith": "Fred" },
  "salary": { "$gt": 10000, "$lte": 20000 }
}
```

* `$not` 子句可以否定比较运算符：

```json
{ "address.zip": { "$not": { "$eq": "90001" } } }
```

* 使用 `field: scalar` 等同于 `field: { "$eq": scalar }`：

```json
{ "animal": "cat" }
```

有关更多过滤示例，请参阅 [测试规范 (test specification)](https://github.com/oracle/langchain-oracle/blob/main/libs/oracledb/tests/integration_tests/vectorstores/test_oraclevs.py)。

```python
# 索引创建后进行高级搜索
def conduct_advanced_searches(vector_stores):
    query = "How are LOBS stored in Oracle Database"
    # 构造一个过滤器，用于与文档元数据进行直接比较
    # 此过滤器旨在包含元数据 'id' 精确为 '2' 的文档
    db_filter = {
        "$and": [
            {"id": "101"},  # 过滤条件 (FilterCondition)
            {
                "$or": [  # 过滤组 (FilterGroup)
                    {"status": "approved"},
                    {"link": "Document Example Test 2"},
                    {
                        "$and": [  # 嵌套过滤组 (Nested FilterGroup)
                            {"status": "approved"},
                            {"link": "Document Example Test 2"},
                        ]
                    },
                ]
            },
        ]
    }

    for i, vs in enumerate(vector_stores, start=1):
        print(f"\n--- 向量存储 {i} 高级搜索 ---")
        # 不带过滤器的相似性搜索
        print("\n不带过滤器的相似性搜索结果:")
        print(vs.similarity_search(query, 2))

        # 带过滤器的相似性搜索
        print("\n带过滤器的相似性搜索结果:")
        print(vs.similarity_search(query, 2, filter=db_filter))

        # 带相关性分数的相似性搜索
        print("\n带相关性分数的相似性搜索结果:")
        print(vs.similarity_search_with_score(query, 2))

        # 带相关性分数和过滤器的相似性搜索
        print("\n带相关性分数和过滤器的相似性搜索结果:")
        print(vs.similarity_search_with_score(query, 2, filter=db_filter))

        # 最大边际相关性搜索 (Max marginal relevance search)
        print("\n最大边际相关性搜索结果:")
        print(vs.max_marginal_relevance_search(query, 2, fetch_k=20, lambda_mult=0.5))

        # 带过滤器的最大边际相关性搜索
        print("\n带过滤器的最大边际相关性搜索结果:")
        print(
            vs.max_marginal_relevance_search(
                query, 2, fetch_k=20, lambda_mult=0.5, filter=db_filter
            )
        )


conduct_advanced_searches(vector_store_list)
```
