## 设置

您需要注册 Anthropic 账户并获取 [Anthropic API 密钥](https://www.anthropic.com/)，然后安装 `@langchain/anthropic` 集成包。

### 凭证 (Credentials)

前往 [Anthropic 网站](https://www.anthropic.com/) 注册 Anthropic 账户并生成 API 密钥。完成此操作后，设置 `ANTHROPIC_API_KEY` 环境变量：

```bash
export ANTHROPIC_API_KEY="your-api-key"
```

如果您希望对模型的调用进行自动追踪，可以取消注释以下内容来设置您的 [LangSmith](https://docs.langchain.com/langsmith/home) API 密钥：

```bash
# export LANGSMITH_TRACING="true"
# export LANGSMITH_API_KEY="your-api-key"
```

### 安装

LangChain 的 `ChatAnthropic` 集成位于 `@langchain/anthropic` 包中：

<CodeGroup>
```bash npm
npm install @langchain/anthropic @langchain/core
```
```bash yarn
yarn add @langchain/anthropic @langchain/core
```
```bash pnpm
pnpm add @langchain/anthropic @langchain/core
```
</CodeGroup>

## 内容块 (Content blocks)

需要注意的一个关键差异是，Anthropic 模型中单个 @[`AIMessage`] 的内容可以是一个字符串，也可以是**一个内容块 (content block) 的列表**。例如，当 Anthropic 模型 [调用工具](/oss/langchain/tools) 时，工具调用是消息内容的一部分（同时也会在标准化的 `AIMessage.tool_calls` 字段中暴露出来）：

```typescript
import { ChatAnthropic } from "@langchain/anthropic";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import * as z from "zod";
import { zodToJsonSchema } from "zod-to-json-schema";

const calculatorSchema = z.object({
  operation: z
    .enum(["add", "subtract", "multiply", "divide"])
    .describe("要执行的操作类型。"),
  number1: z.number().describe("要操作的第一个数字。"),
  number2: z.number().describe("要操作的第二个数字。"),
});

const calculatorTool = {
  name: "calculator",
  description: "一个简单的计算器工具",
  input_schema: zodToJsonSchema(calculatorSchema),
};

const toolCallingLlm = new ChatAnthropic({
  model: "claude-haiku-4-5-20251001",
}).bindTools([calculatorTool]);

const toolPrompt = ChatPromptTemplate.fromMessages([
  [
    "system",
    "You are a helpful assistant who always needs to use a calculator.",
  ],
  ["human", "{input}"],
]);

// 将您的提示和模型链接起来
const toolCallChain = toolPrompt.pipe(toolCallingLlm);

await toolCallChain.invoke({
  input: "What is 2 + 2?",
});
```

## 提示缓存 (Prompt caching)

<Warning>
**兼容性**: 此功能目前处于 Beta 阶段。
</Warning>

Anthropic 支持 [缓存提示的一部分内容](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)，以降低对需要长上下文的用例的成本。您可以缓存工具以及整个消息或单个内容块。

包含一个或多个内容块或工具定义的初始请求，如果带有 `"cache_control": { "type": "ephemeral" }` 字段，将自动缓存该提示的一部分。初始缓存步骤会产生额外费用，但后续请求将以降低的费率计费。缓存的有效期为 5 分钟，但每次缓存命中时都会刷新此时间。

目前还有一个可缓存提示的最小长度，该长度因模型而异。您可以在 [此处](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#structuring-your-prompt) 查看此信息。

这目前要求您使用 Beta 请求头初始化模型。以下是缓存系统消息一部分的示例，其中包含 LangChain [概念文档](/oss/concepts/)：

```typescript
let CACHED_TEXT = "...";
```

```typescript
LangChain 为构建 LLM 时有用的各种组件提供了标准化的、可扩展的接口和外部集成。

### Chat models (聊天模型)

<span data-heading-keywords="chat model,chat models"></span>

使用消息序列作为输入并返回聊天消息作为输出（而不是使用纯文本）的语言模型。
这些通常是较新的模型（较旧的模型通常是 \`LLMs\`，见下文）。
聊天模型支持为对话消息分配不同的角色，有助于区分来自 AI、用户和系统消息等指令的消息。

尽管底层模型是输入消息、输出消息，但 LangChain 的包装器也允许这些模型接受字符串作为输入。
这使它们具有与 LLM 相同的接口（并且更易于使用）。
当将字符串作为输入传入时，它会在内部转换为 \`HumanMessage\`，然后再传递给底层模型。

LangChain 不托管任何聊天模型，而是依赖第三方集成。

我们在构造 ChatModels 时有一些标准化的参数：

- \`model\`：模型的名称

聊天模型还接受特定于该集成的其他参数。

<Warning>
**有些聊天模型经过了**工具调用**的微调，并为此提供了专用的 API。**

通常，此类模型在工具调用方面比未经微调的模型表现更好，并且推荐用于需要工具调用的用例。
有关更多信息，请参阅 [工具调用部分](/oss/langchain/tools)。
</Warning>

有关如何使用聊天模型的具体信息，请参阅 [此处相关的操作指南](/oss/langchain/models)。

#### Multimodality (多模态)

有些聊天模型是多模态的，可以接受图像、音频甚至视频作为输入。
这些仍然比较少见，意味着模型提供商尚未在定义 API 的“最佳”方式上实现标准化。
多模态输出更为罕见。因此，我们将多模态抽象设计得相当轻量级，并计划随着该领域的成熟进一步巩固多模态 API 和交互模式。

在 LangChain 中，大多数支持多模态输入的聊天模型也接受 OpenAI 内容块格式中的这些值。
到目前为止，这仅限于图像输入。对于支持视频和其他字节输入的 Gemini 等模型，API 也支持原生的、特定于模型的表示形式。

有关如何使用多模态模型的具体信息，请参阅 [此处相关的操作指南](/oss/how-to/#multimodal)。

### LLMs

<span data-heading-keywords="llm,llms"></span>

<Warning>
**纯文本输入/文本输出的 LLM 倾向于较旧或更底层的模型。许多流行的模型最好作为 [聊天补全模型](/oss/langchain/models) 使用，**

即使对于非聊天用例也是如此。

您可能在寻找 [上面的部分](/oss/langchain/models)。
</Warning>

接受字符串作为输入并返回字符串的语言模型。
这些传统上是较旧的模型（较新的模型通常是 [聊天模型](/oss/langchain/models)，见上文）。

尽管底层模型是输入字符串、输出字符串，但 LangChain 的包装器也允许这些模型接受消息作为输入。

### Message types (消息类型)

有些语言模型接受消息数组作为输入并返回一条消息。
有几种不同类型的消息。
所有消息都具有 \`role\`（角色）、\`content\`（内容）和 \`response_metadata\`（响应元数据）属性。

\`role\` 描述是谁在说这条消息。
LangChain 为不同的角色提供不同的消息类。

\`content\` 属性描述消息的内容。
这可以是几种不同的东西：

- 一个字符串（大多数模型处理此类内容）
- 一个对象列表（用于多模态输入，其中对象包含有关该输入类型和输入位置的信息）

#### HumanMessage (人类消息)

这代表来自用户的消息。

#### AIMessage (AI 消息)

这代表来自模型的响应消息。除了 \`content\` 属性外，这些消息还具有：

**\`response_metadata\`**

\`response_metadata\` 属性包含有关响应的附加元数据。这里的数据通常特定于每个模型提供商。
这是存储日志概率和 Token 用量等信息的地方。

**\`tool_calls\`**

这代表语言模型调用工具的决定。它们作为 \`AIMessage\` 输出的一部分包含在内。
可以通过 \`.tool_calls\` 属性从那里访问它们。

此属性返回一个 \`ToolCall\` 列表。\`ToolCall\` 是一个具有以下参数的对象：

- \`name\`：应调用的工具的名称。
- \`args\`：该工具调用的参数。
- \`id\`：该工具调用的 ID。

#### SystemMessage (系统消息)

这代表一条系统消息，用于告诉模型如何表现。并非所有模型提供商都支持此项。

#### ToolMessage (工具消息)

这代表工具调用的结果。除了 \`role\` 和 \`content\` 之外，此消息还具有：

- 一个 \`tool_call_id\` 字段，用于传达调用工具以产生此结果的 ID。
- 一个 \`artifact\` 字段，可用于传递工具执行的任意工件（Artifacts），这些工件有助于跟踪但应避免发送给模型。

#### (Legacy) FunctionMessage (遗留函数消息)

这是一个遗留消息类型，对应于 OpenAI 的遗留函数调用 API。应使用 \`ToolMessage\` 来对应更新的工具调用 API。

这代表函数调用的结果。除了 \`role\` 和 \`content\` 之外，此消息还有一个 \`name\` 参数，用于传达调用以产生此结果的函数的名称。

### Prompt templates (提示模板)

<span data-heading-keywords="prompt,prompttemplate,chatprompttemplate"></span>

提示模板有助于将用户输入和参数转换为语言模型的指令。
这可用于指导模型的响应，帮助它理解上下文并生成相关且连贯的基于语言的输出。

提示模板接收一个对象作为输入，其中每个键代表提示模板中要填充的变量。

提示模板输出一个 `PromptValue`。此 `PromptValue` 可以传递给 LLM 或 ChatModel，也可以转换为字符串或消息数组。
存在 `PromptValue` 的原因是为了方便在字符串和消息之间切换。

有几种不同类型的提示模板：

#### String PromptTemplates (字符串提示模板)

这些提示模板用于格式化单个字符串，通常用于更简单的输入。
例如，构建和使用 `PromptTemplate` 的常见方法如下：

\`\`\`typescript
import { PromptTemplate } from "@langchain/core/prompts";

const promptTemplate = PromptTemplate.fromTemplate(
  "Tell me a joke about {topic}"
);

await promptTemplate.invoke({ topic: "cats" });
\`\`\`

#### ChatPromptTemplates (聊天提示模板)

这些提示模板用于格式化消息数组。这些“模板”由一个模板数组组成。
例如，构建和使用 `ChatPromptTemplate` 的常见方法如下：

\`\`\`typescript
import { ChatPromptTemplate } from "@langchain/core/prompts";

const promptTemplate = ChatPromptTemplate.fromMessages([
  ["system", "You are a helpful assistant"],
  ["user", "Tell me a joke about {topic}"],
]);

await promptTemplate.invoke({ topic: "cats" });
\`\`\`

在上面的例子中，当调用此 `ChatPromptTemplate` 时，它将构建两条消息。
第一条是系统消息，没有需要格式化的变量。
第二条是 `HumanMessage`，将由用户传入的 \`topic\` 变量进行格式化。

#### MessagesPlaceholder (消息占位符)

<span data-heading-keywords="messagesplaceholder"></span>

此提示模板负责在特定位置添加一组消息。
在上面的 `ChatPromptTemplate` 中，我们看到了如何格式化两条消息，每条消息都是一个字符串。
但是，如果我们希望用户传入一个我们想插入到特定位置的消息数组该怎么办呢？
这就是使用 `MessagesPlaceholder` 的方式。

\`\`\`typescript
import {
  ChatPromptTemplate,
  MessagesPlaceholder,
} from "@langchain/core/prompts";
import { HumanMessage } from "@langchain/core/messages";

const promptTemplate = ChatPromptTemplate.fromMessages([
  ["system", "You are a helpful assistant"],
  new MessagesPlaceholder("msgs"),
]);

promptTemplate.invoke({ msgs: [new HumanMessage({ content: "hi!" })] });
\`\`\`

这将生成一个包含两条消息的数组，第一条是系统消息，第二条是我们传入的 `HumanMessage`。
如果我们传入 5 条消息，那么总共将生成 6 条消息（系统消息加上传入的 5 条消息）。
这有助于将一组消息插入到特定位置。

实现相同目的的另一种方法是不显式使用 `MessagesPlaceholder` 类：

\`\`\`typescript
const promptTemplate = ChatPromptTemplate.fromMessages([
  ["system", "You are a helpful assistant"],
  ["placeholder", "{msgs}"], // <-- 这是更改的部分
]);
\`\`\`

有关如何使用提示模板的具体信息，请参阅 [此处相关的操作指南](/oss/how-to/#prompt-templates)。

### 示例选择器 (Example Selectors)

实现更好性能的一种常见提示技术是将示例包含在提示中。
这为语言模型提供了有关其应如何表现的具体示例。
有时这些示例是硬编码到提示中的，但对于更高级的情况，动态选择它们可能很有用。
示例选择器是负责选择然后将示例格式化为提示的类。

有关如何使用示例选择器的具体信息，请参阅 [此处相关的操作指南](/oss/how-to/#example-selectors)。

<span data-heading-keywords="output parser"></span>

<Note>

越来越多的模型开始支持函数（或工具）调用，这可以自动处理此问题。

负责获取模型的输出并将其转换为更适合下游任务的格式。
当您使用 LLM 生成结构化数据，或者需要标准化聊天模型和 LLM 的输出时非常有用。

输出解析器必须实现两个主要方法：

- “获取格式说明 (Get format instructions)”：返回一个字符串的方法，该字符串包含有关语言模型输出应如何格式化的说明。
- “解析 (Parse)”：接收一个字符串（假定是语言模型的响应）并将其解析为某种结构的方法。

然后是一个可选方法：

- “带提示解析 (Parse with prompt)”：接收一个字符串（假定是语言模型的响应）和一个提示（假定是生成该响应的提示），并将其解析为某种结构的方法。提供提示主要是为了在 `OutputParser` 需要重试或以某种方式修复输出的情况下，它需要来自提示的信息才能这样做。

输出解析器接受字符串或 \`BaseMessage\` 作为输入，并可以返回任意类型。

LangChain 有许多不同类型的输出解析器。以下是 LangChain 支持的输出解析器列表。下表包含各种信息：

**名称 (Name)**：输出解析器的名称

**支持流式传输 (Supports Streaming)**：输出解析器是否支持流式传输。

**输入类型 (Input Type)**：预期的输入类型。大多数输出解析器都适用于字符串和消息，但有些（如 OpenAI Functions）需要具有特定参数的消息。

**输出类型 (Output Type)**：解析器返回的对象的输出类型。

**描述 (Description)**：我们对该输出解析器的评论以及何时使用它。

当前日期是 ${new Date().toISOString()}`;

// 无操作语句，用于隐藏输出
void 0;
```

```typescript
const modelWithCaching = new ChatAnthropic({

const LONG_TEXT = `You are a pirate. Always respond in pirate dialect.
```

### 工具缓存 (Tool caching)

您还可以通过在工具定义中设置相同的 `"cache_control": { "type": "ephemeral" }` 来缓存工具。这目前要求您以 [Anthropic 的原始工具格式](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) 绑定工具。以下是一个示例：

```typescript
const SOME_LONG_DESCRIPTION = "...";

// Anthropic 格式的工具
const anthropicTools = [{
  name: "get_weather",
  description: SOME_LONG_DESCRIPTION,
  input_schema: {
    type: "object",
    properties: {
      location: {
        type: "string",
        description: "获取天气的地点",
      },
      unit: {
        type: "string",
        description: "返回的温度单位",
      },
    },
    required: ["location"],
  },
  // 告诉 Anthropic 缓存此工具
  cache_control: { type: "ephemeral" },
}]

const modelWithCachedTools = modelWithCaching.bindTools(anthropicTools);

await modelWithCachedTools.invoke("what is the weather in SF?");
```

有关提示缓存工作原理的更多信息，请参阅 [Anthropic 的文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#how-prompt-caching-works)。

## 自定义客户端 (Custom clients)

Anthropic 模型 [可能托管在 Google Vertex 等云服务上](https://platform.claude.com/docs/en/build-with-claude/claude-on-vertex-ai)，这些服务依赖于具有与主要 Anthropic 客户端相同接口的不同底层客户端。您可以通过提供一个返回已初始化 Anthropic 客户端实例的 `createClient` 方法来访问这些服务。示例如下：

```typescript
import { AnthropicVertex } from "@anthropic-ai/vertex-sdk";

const customClient = new AnthropicVertex();

const modelWithCustomClient = new ChatAnthropic({
  modelName: "claude-3-sonnet@20240229",
  maxRetries: 0,
  createClient: () => customClient,
});

await modelWithCustomClient.invoke([{ role: "user", content: "Hello!" }]);
```

## 引用 (Citations)

Anthropic 支持一个 [引用 (citations)](https://platform.claude.com/docs/en/build-with-claude/citations) 功能，该功能允许 Claude 根据用户提供的源材料为其答案附加上下文。这些源材料可以作为 [文档内容块](https://platform.claude.com/docs/en/build-with-claude/citations#document-types)（描述完整文档）或 [搜索结果](https://platform.claude.com/docs/en/build-with-claude/search-results)（描述从检索系统中返回的相关段落或片段）提供。当查询中包含 `"citations": { "enabled": true }` 时，Claude 可能会在其响应中生成对所提供材料的直接引用。

### 文档示例

在此示例中，我们传递一个 [纯文本文档](https://platform.claude.com/docs/en/build-with-claude/citations#plain-text-documents)。在后台，Claude 会将输入文本 [自动分块](https://platform.claude.com/docs/en/build-with-claude/citations#plain-text-documents) 成句子，这些句子用于生成引用。

```typescript
import { ChatAnthropic } from "@langchain/anthropic";

const citationsModel = new ChatAnthropic({
  model: "claude-haiku-4-5-20251001",
});

const messagesWithCitations = [
  {
    role: "user",
    content: [
      {
        type: "document",
        source: {
          type: "text",
          media_type: "text/plain",
          data: "The grass is green. The sky is blue.",
        },
        title: "My Document",
        context: "This is a trustworthy document.",
        citations: {
          enabled: true,
        },
      },
      {
        type: "text",
        text: "What color is the grass and sky?",
      },
    ],
  }
];

const responseWithCitations = await citationsModel.invoke(messagesWithCitations);

console.log(JSON.stringify(responseWithCitations.content, null, 2));
```

### 搜索结果示例

在此示例中，我们将 [搜索结果](https://platform.claude.com/docs/en/build-with-claude/search-results) 作为消息内容的一部分传入。这使 Claude 能够引用您自己的检索系统中特定的段落或片段。

当您希望 Claude 引用特定知识集中的信息，但希望直接传入您自己预先获取/缓存的内容，而不是让模型自动搜索或检索时，这种方法非常有用。当将信息作为 [搜索结果](https://platform.claude.com/docs/en/build-with-claude/search-results) 返回时，它使 Claude 能够从工具返回的材料中创建引用。

以下是如何创建一个工具，以 Anthropic 引用 API 所需的格式返回搜索结果：

```typescript
import { ChatAnthropic } from "@langchain/anthropic";
import { tool } from "@langchain/core/tools";

// 创建一个返回搜索结果的工具
const ragTool = tool(
  () => [
    {
      type: "search_result",
      title: "History of France",
      source: "https://some-uri.com",
      citations: { enabled: true },
      content: [
        {
          type: "text",
          text: "The capital of France is Paris.",
        },
        {
          type: "text",
          text: "The old capital of France was Lyon.",
        },
      ],
    },
    {
      type: "search_result",
      title: "Geography of France",
      source: "https://some-uri.com",
      citations: { enabled: true },
      content: [
        {
          type: "text",
          text: "France is a country in Europe.",
        },
        {
          type: "text",
          text: "The capital of France is Paris.",
        },
      ],
    },
  ],
  {
    name: "my_rag_tool",
    description: "访问我的知识库的检索系统。",
    schema: z.object({
      query: z.string().describe("用于在知识库中搜索的查询"),
    }),
  }
);

// 创建带有搜索结果 Beta 请求头的模型
const model = new ChatAnthropic({
  model: "claude-haiku-4-5-20251001",
}).bindTools([ragTool]);

const result = await model.invoke([
  {
    role: "user",
    content: "What is the capital of France?",
  },
]);

console.log(JSON.stringify(result.content, null, 2));

```

了解更多关于 LangChain 中 RAG（[检索增强生成](https://en.wikipedia.org/wiki/Retrieval-augmented_generation)）的工作原理，请参见 [此处](https://js.langchain.com/docs/concepts/rag/)

### 与文本分割器一起使用

Anthropic 还允许您使用 [自定义文档](https://platform.claude.com/docs/en/build-with-claude/citations#custom-content-documents) 类型来指定自己的分割。LangChain 文本分割器可用于为此目的生成有意义的分割。请看下面的示例，我们在这里分割 LangChain.js README（一个 Markdown 文档），并将其作为上下文传递给 Claude：

```typescript
import { ChatAnthropic } from "@langchain/anthropic";
import { MarkdownTextSplitter } from "@langchain/classic/text_splitter";

function formatToAnthropicDocuments(documents: string[]) {
  return {
    type: "document",
    source: {
      type: "content",
      content: documents.map((document) => ({ type: "text", text: document })),
    },
    citations: { enabled: true },
  };
}

// 获取 readme
const readmeResponse = await fetch(
  "https://raw.githubusercontent.com/langchain-ai/langchainjs/master/README.md"
);

const readme = await readmeResponse.text();

// 分割成块
const splitter = new MarkdownTextSplitter({
  chunkOverlap: 0,
  chunkSize: 50,
});
const documents = await splitter.splitText(readme);

// 构建消息
const messageWithSplitDocuments = {
  role: "user",
  content: [
    formatToAnthropicDocuments(documents),
    { type: "text", text: "Give me a link to LangChain's tutorials. Cite your sources" },
  ],
};

// 查询 LLM
const citationsModelWithSplits = new ChatAnthropic({
  model: "claude-sonnet-4-5-20250929",
});
const resWithSplits = await citationsModelWithSplits.invoke([messageWithSplitDocuments]);

console.log(JSON.stringify(resWithSplits.content, null, 2));
```

```output
[
  {
    "type": "text",
    "text": "Based on the documentation, I can provide you with a link to LangChain's tutorials:\n\n"
  },
  {
    "type": "text",
    "text": "The tutorials can be found at: https://js.langchain.com/docs/tutorials/",
    "citations": [
      {
        "type": "content_block_location",
        "cited_text": "[Tutorial](https://js.langchain.com/docs/tutorials/) walkthroughs",
        "document_index": 0,
        "document_title": null,
```

## 上下文管理 (Context management)

Anthropic 支持上下文编辑功能，该功能将自动管理模型的上下文窗口（例如，通过清除工具结果）。

有关详细信息和配置选项，请参阅 [Anthropic 文档](https://platform.claude.com/docs/en/build-with-claude/context-editing)。

<Info>
    **上下文管理自 `@langchain/anthropic@0.3.29` 起受支持**
</Info>

```typescript
import { ChatAnthropic } from "@langchain/anthropic";

const llm = new ChatAnthropic({
  model: "claude-sonnet-4-5-20250929",
  clientOptions: {
    defaultHeaders: {
      "anthropic-beta": "context-management-2025-06-27",
    },
  },
  contextManagement: { edits: [{ type: "clear_tool_uses_20250919" }] },
)
const llmWithTools = llm.bindTools([{ type: "web_search_20250305", name: "web_search" }]);
const response = await llmWithTools.invoke("Search for recent developments in AI");
```
