## 提示词缓存 (Prompt caching)

通过在 Anthropic 的服务器上缓存静态或重复的提示词内容（例如系统提示词、工具定义和对话历史记录），可以降低成本并减少延迟。此中间件实现了一种**对话式缓存策略**，它在最新的消息之后设置缓存断点，允许整个对话历史记录（包括最新的用户消息）被缓存并在后续的 API 调用中重用。

提示词缓存对于以下场景非常有用：

- 包含较长、在请求间不发生变化的静态系统提示词的应用
- 包含在多次调用中保持不变的工具定义的 Agent
- 需要跨多个回合重用早期消息历史的对话
- 对成本和延迟降低要求严格的高流量部署

<Info>
    了解更多关于 [Anthropic 提示词缓存](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#cache-limitations) 策略和限制。
</Info>

```typescript
import { createAgent, anthropicPromptCachingMiddleware } from "langchain";

const agent = createAgent({
  model: "claude-sonnet-4-5-20250929",
  prompt: "<Your long system prompt here>",
  middleware: [anthropicPromptCachingMiddleware({ ttl: "5m" })],
});
```

<Accordion title="配置选项">

<ParamField body="ttl" type="string" default="5m">
    缓存内容的存活时间（Time to live）。有效值：`'5m'` 或 `'1h'`
</ParamField>

</Accordion>

<Accordion title="完整示例">

该中间件会缓存每个请求中包含最新消息的全部内容。在 TTL 窗口期内（5 分钟或 1 小时）的后续请求中，之前看到的内容将从缓存中检索而不是重新处理，从而显著降低成本和延迟。

**工作原理：**
1. 首次请求：系统提示词、工具和用户消息 *"Hi, my name is Bob"* 会发送到 API 并被缓存。
2. 第二次请求：缓存的内容（系统提示词、工具和第一条消息）会从缓存中检索。只有新消息 *"What's my name?"* 需要被处理，外加模型对第一条消息的回复。
3. 这种模式会持续到每个回合，每个请求都会重用缓存的对话历史记录。

```typescript
import { createAgent, HumanMessage, anthropicPromptCachingMiddleware } from "langchain";

const LONG_PROMPT = `
请成为一个乐于助人的助手。

<Lots more context ...>
`;

const agent = createAgent({
  model: "claude-sonnet-4-5-20250929",
  prompt: LONG_PROMPT,
  middleware: [anthropicPromptCachingMiddleware({ ttl: "5m" })],
});

// 首次调用：使用系统提示词、工具和 "Hi, my name is Bob" 创建缓存
await agent.invoke({
  messages: [new HumanMessage("Hi, my name is Bob")]
});

// 第二次调用：重用缓存的系统提示词、工具和之前的消息
// 只处理新消息 "What's my name?" 和前一个 AI 的回复
const result = await agent.invoke({
  messages: [new HumanMessage("What's my name?")]
});
```

</Accordion>
